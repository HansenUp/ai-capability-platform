# S12 剩余本机缺口与运营指标口径建议

## 本轮结论与边界

本轮按用户要求检查真实实现、既有验收及未提交工作区，只整理缺口、指标候选契约与执行建议，不实施尚未确认的业务规则。未启用自动跟进；只读核实 s9-s10 为 PAUSED。未连接 Langfuse 或其他外部服务、读取密钥、迁移数据库、提交代码、部署生产或执行真实业务写。

当前 S12 是“获批本机子范围已有闭环，产品整体尚未完成”，不能给出以任务勾选数计算的完成百分比。最近完整回归为上一轮创建报告中的 1400 passed／38 skipped／2 warnings、真实隔离浏览器两轮 62/62；这是历史证据，不是本轮重跑结果。原有 237 项未提交／未跟踪状态保留，本轮仅增补本文和实施计划索引。

## 2. 反馈链路不能直接变成运营指标的原因

1. Runtime 接受的是 [-1,1] 连续数值，并非只有点赞／点踩；0 和历史小数不能未经确认自动归类为负面或采纳。反馈有说明／修正字段，但修正不代表已采用修正结果。
2. 当前每次转发独立 POST score，没有稳定反馈 ID、客户端请求幂等键或改评版本。重复点击／传输结果未知不能按“每条 score 一票”统计，也不能按正文哈希猜测幂等。502 仅证明未取得确定转发确认，下游可能已写入；不得自动重发。
3. 写到 Run 最近一条 Trace，同一 Run 恢复执行会产生多条 Trace。当前请求不要求 Run 终态，不能把任何 score 都当作最终答案评价，也不能把 Trace 数作为 Run／任务数。
4. 转发正文和 score metadata 未显式包含验签 tenant_id、Agent／版本；只有 Run／subject 等。读取时必须通过可信 Trace 属性和服务端 Run 归属核实租户／Agent，缺失、冲突或无关联的数据不能凭客户端自报归入某租户。不能仅按 Trace 名称或 subject 推断归属。
5. observe-adapter 的 /feedback 无应用鉴权，当前仅依赖内网约束；正式作为运营可信输入前需要确认并实现服务间认证及身份传播，不能把“内网可达”视为真实性证明。未配置 Langfuse 时 BUFFER 是内存落点，forwarded=false，不是持久交付、反馈成功或运营事实源。
6. 评论和 correction 可含敏感原文；聚合只需数值、关联、时间和来源，不应默认返回评论／修正或扩展其留存。仍沿用 ADR-0002 的 Langfuse 反馈事实源，不擅自新建另一套反馈事实表。

## 3. 建议统一口径（候选 v1，尚未批准／实现）

### 3.1 身份、粒度与时间

- 查询范围首先是服务端确认的单租户，可再筛 Agent／原执行版本；默认只给同租户有权管理员看聚合，不给浏览器读取 Langfuse 项目密钥。跨租户总览及个人排名不在默认范围。
- Run 唯一键为 `(tenant_id, run_id)`；同 Run 的恢复、租约重投、Trace／generation 多次调用不新增 Run。新的 Run 是新的技术执行，但没有业务 task_id 时不能判断其是否重做同一业务任务。
- 新运营候选窗口用带时区的 `[since, until)`，建议界面默认北京时间，转 UTC 查询，返回实际边界、generated_at／as_of 和指标版本；周报建议北京时间周一零点到次周一零点。现有 Trace 接口实现为双端包含，本文不更改其契约；相邻窗口去重需要新口径和兼容测试，不得静默替换。
- 推荐 Run 创建时间 cohort：C 为窗口内创建的唯一 Run，状态和反馈观察至显式 as_of；迟到终态／反馈可能改变旧 cohort，展示暂定状态及观察时间，不伪称冻结快照。补报期限、成熟窗口及历史重算政策需确认。不能把“窗口内提交的反馈事件量”与“窗口内创建的 Run 满意度”混用。
- 当前 Run 行有 created_at／finished_at 和当前 state，历史 as_of 的状态不能只用今天的当前行重建；需事件历史或一致性读取支持。不存在历史快照时仅报告本次读取观察值，不宣称任意历史切面可复现。

### 3.2 指标字典

| 指标与建议名称 | 候选定义 | 当前能否给真实值／主要缺口 |
|---|---|---|
| 已完成／失败／取消／未决 Run 数 | C 按观察到的 completed、failed、canceled 分开计数；submitted／working／auth-required／input-required 等按真实枚举归未决并可展开 | Runtime 状态／事件是依据；Console 尚无对应运营聚合与一致性接口，不能从 Trace 推断 |
| 技术完成率（不称业务成功率） | `completed / (completed + failed)`，取消和未决另列数量及占 C 比例 | 是否将取消计入分母为业务选择；此为推荐候选，未批准。不得仅展示比例隐藏排除数量 |
| 反馈覆盖率 | E 为 C 中已完成 Run；B 为 E 中有有效最终二元评分的 Run，`|B| / |E|` | 需最终评价粒度、去重和归属。未评价不算差评；未终态反馈／中性／小数／冲突另列，不悄悄丢弃 |
| 点赞占比（满意度代理） | `最终 +1 的 Run 数 / (最终 +1 的 Run 数 + 最终 -1 的 Run 数)`；限定 B | 不等于采纳率，也不默认把任意正小数当 +1；历史连续评分映射需确认 |
| 采纳率 | `已明确采纳的唯一业务任务 / 已产出可供采纳结果的唯一业务任务`，同一 task_id 只计一次 | 当前没有可信采纳／未采纳事件及业务 task_id、可采纳范围；不能用点赞、下载、completed 或 tool.executed 代替 |
| 建议主北极星：周确认采纳任务数 | 周内首次取得可信“已采纳”证据的唯一 `(tenant_id, task_id)` 数；反馈迟到与重复 Run 不重复增加 | 是事件时间指标，与上述 Run 创建 cohort 分开呈现；需要业务定义采纳证据及任务键，当前只能显示待定义 |
| 业务任务完成率 | `有可信业务完成证据的唯一任务 / 纳入目标范围的唯一任务` | 业务完成及任务总体未定义；Run completed 只证明技术停止，不能证明工单已正确解决 |
| 已完成 Run 墙钟耗时 P95 | 对 E 的 `finished_at - created_at`，包含排队、审批和输入等待，异常／缺失时间剔除并展示覆盖数；建议 nearest-rank | 分位算法和取消／失败分组需确认。不能称模型响应时延或 P95 首字节；真实首字节需明确服务端／用户可见边界和新埋点 |
| 每已完成 Run 成本（USD） | 以 E 为分母，并收齐这些 Run 所有关联 Trace 的唯一 generation 成本；先按来源去重，明确覆盖完整性 | 现有仅 Trace 已知小计，恢复 Trace、LiteLLM 与 OTel 重复来源、延迟上报待对账；不能直接除以 Run 数冒充完整成本，更不是财务结算或每业务任务成本 |

所有比率分母为 0 时返回 null／“无样本”；来源不完整、归属冲突或不可用时返回未知／不可用而非 0。已知部分显示小计、覆盖数、排除原因，不能展示为总量；真实完整采集且无事件的“事件计数=0”与“没有数据所以未知”必须区分。

### 3.3 推荐改评与去重规则（需确认）

推荐每个 Run 的原发起人只产生一份“当前最终反馈”，允许显式改评；统计按 `(tenant_id, run_id, verified_subject)` 取 as_of 前最新有效修订，而不是累加所有 score。需由可信服务端 ID／版本和时间确定先后，同时间冲突不能任选一条。历史无稳定 ID／关联的数据标 legacy／冲突，不猜测消重或用同一请求体冒充相同反馈。

这要求确认反馈是否限定最终输出、是否允许撤回／改评、0／小数兼容、改评与撤回如何审计，以及 Langfuse 中如何表达稳定 ID／修订。本文不决定新表、双写、管理员覆盖、自动重试或任意新写 API。Chat 新增反馈还需复用持久写前登记／回执契约，不能直接调用旧非幂等 POST 并宣称已有跨页未知结果保护。

## 4. 可直接执行与必须确认的门禁

### 可直接执行的准备项（不新增业务口径或真实写）

1. 以本文形成指标字典和契约样例，界面继续展示“待定义／未知”，明确满意度不等于采纳、控制面不等于使用量。
2. 复用隔离测试补现有只读接口的畸形字段、重复分页、超界时间、来源失败／旧响应／身份切换与覆盖率展示矩阵；不为测通过增加超时或改变原 Trace 边界。新候选分母只用合成数据演算，不接入真实指标。
3. 检查已有反馈来源和身份传播的数据形状，设计缺失归属、重复上报、改评、连续评分、同 Run 多 Trace、迟到／冲突的测试样例；不发真实 feedback POST，不新增事实源或迁移。
4. 若已有授权测试项目和可用只读权限，下一轮单独验证真实本机运营聚合目标和来源覆盖；先核对项目／租户隔离，凭据缺失则列为门禁，不创建项目、服务或获取新付费资源。

### 必须人工确认，当前不执行

| 决策 | 推荐选项 | 不确认的后果 |
|---|---|---|
| 反馈统计单位、取值与改评 | 原发起人对 Run 最终输出评价；允许显式改评，统计最新修订；新二元评分只用 ±1，历史 0／小数单列 | 不新增 Chat 反馈写或正式满意度聚合；不能靠猜测消重 |
| 主北极星及业务证据 | 周确认采纳任务数；先选一个业务场景，定义 task_id、首次采纳时间、证据提供者和撤销规则 | 无业务证据时保持“待定义”；可另选“周完成 Run 活跃人数”作为技术使用代理，但不得冒充价值北极星 |
| 状态分母和时间策略 | 创建 cohort、取消／未决独立列示、completed/(completed+failed)；北京时间周窗＋UTC 查询，补报／成熟期限另定 | 不发布正式 Run 比率或冻结历史报表 |
| 反馈可信身份与权限／隐私 | Runtime 验签归属，服务间认证，管理员只读聚合、不默认暴露评论／correction | 不扩大无鉴权 adapter 的信任边界，不启用真实采集；服务身份实现和留存删除政策需独立确认 |

以上均为候选，不代表用户已批准。新外部凭据、服务身份、付费或持久服务、管理员代解锁、真实业务写、生产部署继续单独授权。本轮没有任何“未确认但先执行”的业务决策。

## 5. 建议下一步与验收顺序

**建议先收口反馈，不同时铺开全部北极星实现。** 先确认上一表前两项，并确定隔离测试中的服务间身份及租户绑定方案；然后做最小单租户闭环：可信 feedback 关联→确定性去重／改评→只读覆盖率与点赞占比→组件及真实本机验证。采纳及任务完成的业务证据未就绪时，北极星保持待定义，不拿 Run／点赞替代。

回归必须覆盖：同 Run 多 Trace 只计一份最终反馈；重复请求不多计、改评替换而非增加票数；502／丢响应不盲目重发；未评价／中性／连续值／无样本分开；跨租户／Agent 冲突失败关闭；窗口边界、迟到和来源不完整；浏览器身份切换、旧响应和回执恢复。真实来源验收仅证明既有本机测试项目，不代表外部／生产出口。

本轮仅文档和静态核对，未修改业务实现、未运行应用测试或全仓回归；仅检查文档来源路径和 git diff 格式。不把前轮 1400／62 的结果作为本轮新增指标验证。自动跟进保持暂停，不继续下一轮实现，等待用户确认上述业务范围。

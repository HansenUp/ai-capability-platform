## 本轮实现

1. SDK 增加验签身份与活动账本读取、凭据写前登记、已登记动作执行、原操作者确认收口。只发送 UUID／Run、指纹与版本，不把凭据放进正文；令牌仍由内存 headers provider 提供。验证 scope、attempt、credential 动作、Run、请求序号、指纹、版本、状态、证据与 acknowledged，坏回执按未知结果失败关闭。
2. Chat 在应用身份后先查 Runtime 身份和账本，权威读取前禁止新写；旧创建／审批／回答每次提交前也重新查锁。存在活动账本时禁写，但保留 Run 查询、SSE、重新认证和账本只读核对。开发头不冒充验签用户，开发身份只读。
3. 凭据操作拆为“登记当前用户凭据刷新”与“确认执行已登记凭据刷新一次”。PREPARED 重载后只恢复记录，不自动执行。COMMITTED／REJECTED_NO_EFFECT 仍冻结新写，必须预览并本人确认收口；取消预览不写。只有精确 acknowledged 回执后才允许清除本条本地指针并重新查询权威账本。
4. 提交响应丢失不重发。页面保留预期 attempt／Run，查询空列表、同 ID 错 Run、指纹冲突、版本倒退或终态倒退均不能解开已知锁。身份、Run、令牌不存浏览器持久存储；重载后重新认证并从服务端恢复主体锁。
5. 身份切换／卸载取消只读账本请求并增加 generation 校验，即使旧 fetch 忽略 abort、旧 JSON 迟到，也不继续旧主体查询或污染新主体。POST 不作为可安全取消的读取处理，卸载后的结果不更新组件；权威未决记录仍保留。

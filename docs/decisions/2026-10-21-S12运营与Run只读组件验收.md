# S12.4 Operations／Runs 只读组件验收

## 授权与范围

仅本轮本机开发、隔离测试与报告收口，不启用自动跟进、不部署生产、不执行真实业务写操作。保留所有既有未提交变更，不提交／建分支／推送／合并。本轮无新增必须人工确认、却绕过确认实施的事项。

新增 Operations 4 项、Runs 5 项真实 Vue 挂载组件测试，复用现有 Playwright／Chrome、Vite、临时 loopback Console／Runtime 与合成工具 E2E。未安装新依赖、下载浏览器或接入真实 Langfuse／IdP。新测试中的 Runtime、Console 和 Trace 目标页均为接口／页面替身，不冒充实际 Langfuse 数据或生产权限验收。

## 一致性与只读契约

- Operations 身份或条件改变立即清空旧结果并使旧请求失效。即使传输忽略 abort、旧 JSON body 迟到，也不得覆盖新身份／Agent 的结果或写入旧错误。
- Runs 保留既有“读取期间锁定身份”的交互，不擅自开放并发身份切换。读取结束后应用新身份清空旧列表／轨迹；卸载使整个读取纪元失效，迟到 body 不得继续读取事件或 Trace，不得使用已清空的凭据发送后续请求。
- Run 详情元数据的 `run_id` 必须匹配请求目标，事件仍复用 `mergeEvents` 的 Run／序号／冲突校验；错误响应不回显原始正文。401／403／404 清空此前轨迹和链接。
- Trace ID 只取合法 done 尾帧；跳转沿用配置中的本机 host 与 project，不接受事件自带 URL，链接必须 `_blank`＋`noopener noreferrer`。本轮点击后的目标由 Playwright 截获为合成页面，未读取用户现有 Langfuse 服务。
- 全部新增页面接口请求断言为 GET；不审批、不续跑、不取消 Run，不调用节点拉取／ACK，不写指标或业务数据。浏览器 localStorage／sessionStorage 均为空，令牌仅在当前组件内存中，输入应用后清空。

## 新增自动化检查点

| 测试 | 关键断言 |
|---|---|
| Operations 查询与显示 | 当前 Console 用户／租户头、Asia/Shanghai 浏览器时间转 UTC、Agent 参数、控制面计数、Token／USD 缺失显示未知、费用字符串精度；改条件清空旧 Trace |
| Operations 错误 | 超七天不发请求；HTTP 503 不显示服务端私有正文并清空旧 Trace；控制面跨租户响应失败关闭并清空旧数据 |
| Operations 旧控制面响应 | 测试传输忽略 abort，暂存旧 body；切换租户取得新计数后释放旧 body，仍只展示新计数；USER 禁用查询并清空数据 |
| Operations 旧 Trace 响应 | 切换租户／Agent，先展示新结果，再释放旧 body，旧统计与旧错误均不能覆盖新视图 |
| Runs 列表与身份 | 无身份禁止查询；Bearer 用户头而非 Console 服务账号；精确 Agent 筛选和 opaque cursor；筛选变化不能沿用旧游标；新身份清空列表且无凭据持久化 |
| Runs 增量与 Trace 跳转 | 序号缺口允许、乱序排序与重复去重，增量 since_seq 精确；安全链接与实际新窗口 URL 匹配本机替身，事件提供的外部 URL 不参与跳转 |
| Runs 错误 | 401／403／404 均清空旧轨迹和链接、不泄漏正文；跨 Run 事件被拒绝，非法 Trace ID 不生成链接 |
| Runs 卸载与旧响应 | 忙时身份按钮禁用；卸载后重新挂载并应用新身份，再释放旧 body，不能发出后续 events／stream 请求、不能污染新页面 |
| Runs 元数据范围 | 返回另一 run_id 时明确报错，不再读取事件或 Trace，也不渲染另一 Run |

新增 `readonly-fixture.mjs` 以浏览器原生 fetch＋路由替身获取响应，再用显式 Promise barrier 控制 JSON body 到达顺序，并故意不传 abort signal；因此旧响应测试不是仅验证浏览器成功取消。释放后以下一绘制帧作为 Vue／Promise 更新屏障，不使用任意延时等待或放宽断言。另记录组件同步发起的请求路径，防止网络路由尚未处理就提前通过。

`management.html` 增加两页挂载与卸载／重新挂载测试按钮，仅存在于测试 HTML。runner 仅为临时 Vite 显式配置合成 Langfuse host／project，不修改持久环境文件或真实服务配置。每项独立 Context，未配置的组件 API 请求返回 404，不透传真实后端。

## 红绿验证与最小修复

首次完整浏览器回归 25/27 通过，两项失败均位于 Runs：

1. 卸载后旧详情 body 迟到，代码仍继续请求 events，记录数为 2 而期望 1；此时旧组件凭据已清空。修复为读取纪元校验，在发起／收到请求、读取 JSON 后、消费 SSE chunk 后验证当前纪元；卸载和应用身份递增纪元，旧异常与 finally 不再更改当前状态。超时回调绑定本次 AbortController，不引用可变化的全局 controller。
2. 详情返回另一 run_id 时原代码继续读取事件且未报范围错误。补充请求目标与详情 run_id 的相等校验，失败后不执行后续读取。

Operations 已有 readSession＋视图 generation 契约在迟到 body 故障注入下通过，无需修改产品代码。Runs 沿用现有权限、15 秒读取超时与只读 API，无后端／数据库／业务契约变更；组件定位上限仍 5 秒、单项测试仍 30 秒，未删除或放宽失败断言。

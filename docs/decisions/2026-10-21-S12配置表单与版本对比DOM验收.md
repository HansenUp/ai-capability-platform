## 实现与检查点

新增 `agent-config.html` 使用真实 Vue render 函数挂载产品 `AgentConfig.vue`，父组件接收 `update:modelValue` 并回写 prop，显示模型原文及原生 input／emit 计数，不复制产品实现。测试 API 路由失败关闭，独立表单不应产生任何 Console／Runtime 请求。

`agent-config.test.mjs` 另复用实际 Agents 页面及既有管理组件接口替身；保存只接收 mock `/agents`，对比只使用 mock GET 列表，不向真实业务或发布系统写入。

| 新增用例 | DOM／请求断言 |
|---|---|
| 结构化输入同步 | 工具清单去重保序，显式清空产生 `[]`；修改红线仅更新 deny_tools，保留红线扩展和其他字段；原生 input 与父模型 emit 严格一一对应，没有额外递归回写 |
| 高级 JSON 回写 | JSON 改变后工具、红线、Skill 输入同步；恢复先前结构化编辑产生的同一 JSON 时，也必须恢复相应输入，不能保留中间值 |

## 产品根因与红绿证据

真实失败是回写抑制标记未消费：结构化工具编辑生成 A，外部 JSON 改为 B，再恢复 A，原 watcher 因 A 等于历史 `emitted` 直接返回，导致 JSON 为 A、工具框仍为 B。原始失败显示实际 `external-tool`，期望 `first-tool`。

仅将标记改为 `string | null`，每次 prop 回写检查后立即清空，只有紧邻自身 emit 的一次回写跳过结构化字段重置。既保留用户正在输入的结构化草稿，也不再把将来的外部恢复误当成自身 echo。不修改配置 schema、默认工具语义、发布闸门或后端接口。

测试夹具先前的运行时 template 不适用于当前 Vue runtime-only 构建，已改为真实 render 挂载；该临时启动调试不作为产品故障证据。有效 `red.log` 是 render 夹具完整复跑，43 passed／2 failed：除上述同步缺陷，另一项失败来自测试错误假设“一次多行 fill 只产生一次 input”。最终同时计数实际原生 input 与 emit，并严格断言一对一，而不是硬编码 fill 次数；未放宽业务断言或阈值。最终模型原文与高级编辑区始终严格相等。

校验错误继续沿用已有 `configObject`／`updateConfig` 的契约，具体工具／Skill 资格和发布配置由服务端验证；本轮没有擅自增加新的业务字段规则。

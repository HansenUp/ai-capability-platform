# 工单总结只读：非生产真实模型与工单接口接入前置清单

日期：2026-10-27。用户仅授权本轮梳理；未连接真实模型、工单、IdP、原库或生产，也未读取凭据。首批优先场景为工单总结只读，具体业务范围和非生产接入尚需确认。

## 一、结论与建议路径

推荐分为两次独立门禁，避免同时引入模型外发和真实工单数据：

1. **阶段 M：真实模型 + 合成工单**。保持现有 `ticket.get` 替身和临时隔离数据，仅将模型调用经受控模型网关接入已批准的非生产模型。明确模型、出站、预算和日志策略后实施；不能沿用当前禁止外联的演示进程直接绕过其审计。该阶段不接工单业务系统。
2. **阶段 T：真实工单测试接口 + 合成／获批数据**。先核对业务系统非生产环境及测试数据范围，冻结只读 HTTP 适配契约、真实用户委托和行权限；仅经过业务、数据与安全责任人授权后接入。将真实工单内容送往模型属于另一项数据出站许可，不自动包含于只读接口授权。
3. 两者独立通过并完成分级、评测和审计后，才建议在获批范围组合。当前不触碰真实接口或账号。

## 二、现有能力与实际差距

| 项目 | 当前仓库证据 | 对接影响 |
|---|---|---|
| 已有演示 | 临时 SQLite、签名测试身份、mock Harness 与单一 `ticket.get` 合成工具；固定消息产生固定摘要 | 只证明工作台／Run／轨迹功能，不证明真实模型总结、网关或工单接口 |
| 模型 | Runtime 支持模型网关，仓库有 LiteLLM 别名和路由配置 | 配置文件中的供应商／型号只是项目配置，不能假定可用、合规或被当前环境授权；真实模型需证实工具调用、数据出口和凭据 |
| 工单 MCP | `mcp-servers/ticket` 的 `ticket.search`／`ticket.get` 读取包内 mock JSON，并叠加本地 SQLite 覆盖 | 当前并非真实业务 HTTP 后端；真实适配需开发、契约测试及鉴权验证 |
| 文档与源码差异 | 2026-10-16 场景纪要及 `.env.example` 描述 `TICKET_BACKEND=http` 和 `TICKET_API_BASE_URL`；当前 `mcp_ticket` 源码／配置中未发现对应实现 | **不能仅设置该环境变量就宣称接入真实工单**；先以源码和定向测试核对，更新文档后再实施 |
| “只读”范围 | 现有 `ticket.get/search` 是业务语义只读，但 `store.load_overrides` 会调用 `CREATE TABLE IF NOT EXISTS` 并可能创建本地 SQLite | 不应将现有工具调用描述为零本地写；非生产测试只能在明确授权的新临时库内初始化，不能指向原库或真实业务存储 |
| 工具清单 | 现有 MCP Server 还暴露关闭／重开等写工具 | 必须由受控目录、绑定和策略将本场景限制到获批只读工具；仅靠提示词不足以禁止写入。是否需要独立只读连接器或服务端物理禁用写路径待验证 |
| 身份与权限 | 网关可使用已验签用户和 OBO／act；示例 MCP 有 mock 行权限 | 下游真实业务系统必须按真实主体和租户执行行级授权；mock 的规则不能替代业务系统真实权限或数据责任人确认 |

## 三、两阶段最小依赖及可暂缓项

| 组件／能力 | 阶段 M：真实模型 + 合成数据 | 阶段 T：真实工单测试接口 | 不满足时 |
|---|---|---|---|
| Console／Portal、SDK、Runtime | 选一个入口、Console 管理界面（如需创建发布）及单 Runtime；保留 Run、审计、主体写锁 | 同左；接口适配仍经平台网关 | 单 Runtime 与队列／持久性组合需定向验证；不要从演示模式推断真实用户可用 |
| 隔离存储／队列 | 新建专用临时数据库和本机测试身份，按已批准初始化；需明确是否保存结果及清理 | 独立非生产数据库或临时库，由具体授权和恢复目标决定 | 不复用原库；进程内队列不提供多节点接管 |
| LiteLLM／受控模型 | 需要已批准的非生产模型、API 兼容配置和密钥；当前 Compose 配置还引用独立 PostgreSQL，应核对实际配置依赖 | 如 T 单独验证接口，可继续用模拟模型；工单文本是否可送真实模型须另批 | 未明确模型、合法出口、费用上限或凭据时不调用 |
| 模型安全 | 数据分级、用途、脱敏、出站目标／回退、日志和留存批准 | 测试工单内容是否属于可外发数据必须确定 | 未签署的开发矩阵不能冒充正式许可；不把原文或密钥写日志 |
| 工单 MCP + 网关 + 策略 | 阶段 M 可沿用工单纯替身；真实网关路径若纳入测试需单独确定 | 真实业务接口需适配、受控目录和两层身份／授权，具体依赖按设计核对 | 不能通过绕过网关／策略、使用开发头或共享全量账号代替行权限 |
| IdP／OBO | M 仅合成输入可维持测试身份，不能声称验证正式身份 | 需批准的非生产 IdP、测试用户、服务身份、正确 audience／issuer／tenant、JWKS／网关 act 验签与下游主体映射 | 缺任一可信属性或权限映射失败关闭 |
| 业务接口测试数据 | 合成，不依赖业务接口 | 由工单负责人指定非生产端点、授权的隔离账号和测试工单／脱敏数据 | 不用生产工单、不猜地址、不自行创建账号；“只读”仍可能产生业务系统访问审计 |
| 观测／评测 | Runtime 临时事件与本机合成评测可作为调试；不冒充真实 Langfuse 或正式发布闸门 | 需要明确非生产审计／观测范围及保密策略；评测集与阈值待业务确认 | 当前 Console 生产模式要求 Langfuse 评测门禁；不能将开发 flag 带入生产 |
| ES／FastEmbed、APISIX、多节点、Data Hub／etcd／见证 | 固定工单只读首轮可先不作为设计前置，但现有各配置是否确实无需它们须用隔离测试证实 | 若需要发现、路由或经营分析再按范围引入 | 不因此削弱权限、审计、写锁或生产基线；不把暂缓功能当可用 |

## 四、需人工提供或确认的事项（不要发送密钥内容）

### M1 真实模型接入

- **模型**：供应商／内网部署、具体版本或别名、OpenAI 兼容与工具调用支持、服务地址的安全引用、所属区域及是否会使用数据训练或留存；在获批前不从现有配置推断实际模型可用。
- **授权与成本**：该非生产环境是否允许连接目标、运行者／责任人、独立测试凭据的安全引用、调用次数／金额上限和停止条件。不得复制生产主密钥，不要求在聊天中粘贴秘密。
- **数据与出口**：第一阶段确认仅提交合成工单和合成提示；确认数据分级、回退模型和观测渠道允许清单、脱敏、保留期限及外发责任。LiteLLM 的回退与其他回调可能扩大数据流向，必须逐项核对并按批准配置失败关闭。
- **验收**：指定少量合成案例、结果结构、基本质量阈值、超时／错误预期及是否允许模型真实费用；需要明确不以固定 mock 文本验证模型能力。

### T1 工单只读接口

- **负责人和环境**：业务接口负责人、非生产 API 文档与地址的安全引用、接口可用窗口、是否拥有隔离测试租户和合成工单。历史纪要中的负责人及分级字段仍为空，不能假设已确认。
- **范围与字段**：优先 `ticket.get` 单工单；若需 `ticket.search`、处理记录、客户反馈、附件或分页，逐项确认字段最小化、最大结果／截断、分类、脱敏和业务语义。关闭／重开／通知／知识库写入均不在范围。
- **身份与权限**：接口是否接受 OBO 用户令牌、issuer／audience／JWKS、租户／用户映射、下游行级权限；无权和不存在是否可统一响应。不能使用有全量权限的共享账号代替真实用户授权。现有工单连接器的 act `jti` 防重放要求与 Data Hub 所选“有效期内允许重放”是不同契约；多副本时其配置描述要求共享防重放存储，不能把两个场景的规则混为一谈。
- **边界与运维**：访问速率／时间窗、非生产审计及日志保存、只读保证、是否有副作用（含服务端审计、查询计费）、测试账号和责任人；请求真实接口本身需明确授权。
- **适配开发**：确认提供者文档后，先实现不连真实服务的 HTTP 适配与契约替身测试；实际版本、认证、分页及错误格式不能凭模拟推断。

## 五、实施前必须保持的安全门禁

1. 显式区分临时环境与生产，配置白名单、环境变量来源与网络目的地；禁止读取已有真实密钥或使用原库。测试键、外部凭据与用户令牌仅限授权存储／内存，不打印或提交。
2. 场景只绑定获批只读工具；数据访问与模型出口需两项独立权限。保留用户验签、租户与业务行权限、数据分级、拒绝默认规则、访问审计及现有 Run 未决写保护。
3. 模型调用失败、策略/身份不可用、数据权限不确定均失败关闭；不得将非生产开发模式、测试权限、mock 评测标志或演示身份当作生产保障。
4. 不进行真实评分／Trace 写、生产部署或用户账号变更；使用真实非生产观测或采集前另行确认目的、字段、凭据与授权。
5. 外部成本、网络、测试账号创建、真实数据处理、持久资源、上线均须先确认。一个步骤的授权不自动覆盖后续步骤。

## 六、下一步建议

先由用户确定阶段 M 的**模型供应方／版本、合成数据限定、非生产凭据安全引用和费用上限**；在确认前可完成模型适配配置草案和纯替身验证，但不发出模型请求。并行由业务方确认工单 API 负责人、文档及身份映射；得到接口文档后先用合成 HTTP 替身实现契约，而不是直接接真实工单。

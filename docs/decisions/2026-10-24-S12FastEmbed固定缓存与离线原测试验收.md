## 离线契约与验证过程

1. 原加载器未改；仅本轮验证进程设置 FASTEMBED_CACHE_PATH、固定原模型名、HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1、关闭Hub遥测／隐式令牌及两个OTLP出口。缓存refs/main只指向该固定revision；已安装FastEmbed会将Hub离线模式转换为local_files_only，不需要增加依赖或更换实现。
2. `/usr/bin/sandbox-exec` 使用 `(version 1)(allow default)(deny network*)`。独立探针确认对测试保留地址的socket连接被PermissionError拒绝，不是仅设置离线环境变量。
3. Python socket审计持续拒绝connect、connect_ex、DNS、sendto和bind；有外连／未知网络尝试时整个验证失败，即使pytest本身通过也不算验收。固定snapshot在此约束下以local_files_only及5文件allow_patterns解析成功，才运行原测试。
4. 两次推理验证均0外连／DNS／下载尝试；每进程另有1次urllib3导入时 `_has_ipv6` 对 `::1:0` 的本机能力探测，被原审计拒绝并单列记录，未允许该绑定或放宽OS断网。只对此确切调用栈、AF_INET6与回环零端口做诊断分类，其他绑定仍导致验收失败。
5. 每次验证前后逐文件复核大小及SHA256，固定refs及4个依赖版本亦检查，文件哈希不变。fastembed0.9.0、onnxruntime1.31.0、huggingface-hub1.33.0、tokenizers0.23.3保持原版本。

### 失败证据与修正

- 首次离线预检误以完整仓库范围调用snapshot_download，Hub严格拒绝缺少未授权的4个非必需文件。保留 `preflight-incomplete-scope.log`；仅将预检范围修正为已授权5文件，未追加下载或伪造缓存元数据。

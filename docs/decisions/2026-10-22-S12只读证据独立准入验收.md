# S12.1 Runtime 只读证据独立准入

## 授权与实现范围

用户批准仅本轮本机代码修改及临时库／替身隔离回归，不启用真实实例，不写真实评分或 Trace、不变更账号、不部署或恢复自动跟进。

本轮将 `GET /v1/metrics/feedback-evidence` 的准入从反馈写协议中拆开：

- 新增 **`FEEDBACK_LOCAL_EVIDENCE_READ=1`**，仅精确字符串 1 启用，缺省／0／true／yes／空值均关闭；同时严格要求 Runtime dev 环境。生产及 staging 均拒绝。
- 继续要求真实验签用户 JWT、既有 platform-admin、令牌所属单租户、指定 Agent 和带时区最长七天 cohort；2000 Run／修订及证据完整性限制不变。开发头、开发身份、服务身份、非管理员不能读取。
- 不再调用反馈写协议 `enabled()`。只有写开关打开不会隐式授予证据读取；只读开关打开也不会改变 `FEEDBACK_LOCAL_PROTOCOL` 或 Observe 的鉴权守卫。
- prepare／execute／reconcile／ACK、协议内 owner receipt／head 和 Observe 独立交付通道仍按原写协议开关准入；本轮不扩大这些接口权限。原 v1 cohort 的已有读取规则不变。
- 已有 Runtime 其他业务 API／旧反馈 API 的规则保持原样；**这不是把整个 Runtime 变成全局只读实例**，也不解除真实实例启动、Worker、凭据与运行配置授权门禁。
- 浏览器专用临时夹具显式设置两个开关，以维持原有 synthetic 写协议与 v2 聚合验收；未修改项目 `.env`、真实 Runtime 或真实 Observe 配置。无迁移、无新身份或密钥。

## 独立开关契约

| 只读开关 | 写协议开关 | 验签管理员证据 GET | 原反馈写协议 |
|---|---|---|---|
| 关闭 | 关闭 | 503 | 保持关闭 |
| 关闭 | 开启 | 503 | 保持原准入规则，不隐式开启只读 |
| 开启 | 关闭／未设置 | 200（其他权限和范围须全部满足） | 保持关闭 |
| 开启 | 开启 | 200（其他权限和范围须全部满足） | 保持原准入规则 |

认证与管理员检查先于只读特性门禁。独立开关不改变查询返回版本、权威修订、OBSERVED 摘要、历史评分隔离、未知锁与本人 ACK 的业务契约；GET 不提交、对账终结或解锁。

## 隔离验收矩阵

- 四种开关组合均测试；写开关开启而只读关闭时不能读证据，只读开启且写开关缺省时可以读。
- 默认关闭、非 1 字符串、prod／staging、缺令牌、伪造开发头、非管理员、服务身份和关闭验签后的开发身份均拒绝。
- 跨租户读取仅返回自身租户 cohort；Agent、左闭右开时间窗、无时区／反向／超过七天、扫描上限沿用并回归。
- 在临时库先建立一个 PREPARED 样例，再关闭写开关、仅启用只读：两次 GET 的证据摘要一致；prepare、execute、reconcile、ACK、协议 receipt／head 均 503，Observe GET／POST 交付通道也 503。活动账本与锁完全不变，替身下游调用为零；没有凭读取或空列表解除锁。
- 有样例的未观测／OBSERVED 管理员读取和既有反馈全专项继续回归；临时样例不代表真实数据中存在可信回执。

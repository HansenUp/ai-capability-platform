## 实现与一致性边界

- SDK 新增 `run-client.ts` 并从既有入口导出，提供 TypeScript 声明；沿用原 `<ai-assistant>` 注册与接口，不破坏 Portal 嵌入。无新依赖或 Runtime API／数据库修改。
- 新客户端只调用同源 `/v1/runs`、Run 详情／events、approve／reject／input。不使用 Console 服务账号，不传客户端声称的 approver／角色，不调用额外 resume 重复执行。
- 创建只接受约定 202 与可读 Run ID；审批／输入只接受约定 200。错误不回显服务端正文；POST 网络／5xx／异常成功响应结果未知时锁定后续写操作，不自动重试。只读刷新不自动解锁，Run ID 丢失可复用既有调试列表查找；查无记录不是重发证明。
- 权限、租户、待办状态、审批指纹和回答 schema 由 Runtime 最终判定；前端 JSON 解析只处理输入格式，不声称替代完整 schema 校验。
- 审批卡只从 auth-required 的待批调用与对应决策构造，已批准／拒绝／已有结果的调用不重复展示；支持逐条处理剩余批次。非输入挂起态不显示输入卡，已提供输入后清除。
- Run ID 改变、应用身份、401／403／404 和离开页面清空旧卡片；读取是手动全量，受限审批视图不冒充完整日志。输入令牌字段在应用后清空，不使用 localStorage/sessionStorage 保存用户令牌、消息或事件。
- 保留原发布页与 Runtime 已发布快照校验，本轮测试 Agent 仅在隔离 Runtime 的开发态 flag 路径发布，不降低真实评测或生产发布门槛。

## 真实隔离验证

- `scripts/verify_s12_workbench.py` 使用临时 SQLite、独立回环 Runtime、Mock Harness、既有基线策略 transport，以及现场生成 RSA 签名的本地测试 IdP，`AUTH_REQUIRED=true`。JWKS 和策略不出网，工具 `_dev_execute` 被替换为仅返回 simulation／external_effect=false 的函数。
- alice 为发起人、bob 为另一测试用户；私有测试令牌仅写临时目录的 0600 文件供浏览器夹具读取，未输出令牌或私钥，关停时删除文件，REPL 引用和页面已释放。不是 Keycloak／真实用户权限矩阵或生产身份验收。
- 脚本实际 HTTP：answer 只允许发起人，提交后同 Run completed；alice 自批 403，bob 批准后同 Run 自动续跑，仅一次合成写、无外部效果。
- 新增 Runtime 3 项（强制 JWT）：answer 的非发起人 403／跨租户 404／无效 schema 400／错误调用 409／重复提交 409；approve 与 reject 的自批 403、错误指纹 409、另一用户批准／拒绝、分别一次或零次合成写、重复决定 409。
- 浏览器仅连接 Vite 5191 → 临时 Runtime 65077：
  - `run_aad7e0a44d194f78bc75`：input-required 卡片展示 JSON schema，提交合成 ID 后同 Run completed，助手显示工具回答。
  - `run_2b96e71f45a84a3a9c72`：展示 ticket.close_batch 参数卡与指纹，alice 确认自批实际返回 403 并清空旧卡；应用 bob 测试令牌后按原 Run ID 定位，二次确认批准，自动续跑后手动刷新 completed。
  - 只读核对恰好一次 input.provided、一次由 human:bob 产生的 tool.approved、一次 tool.executed，结果明确 simulation=true／external_effect=false，没有重复 resume 或真实工具效果。

## 验证中发现并修复的问题

浏览器首次请求因 SDK 以客户端对象为 `this` 调用原生 fetch 而失败，正确进入未知写结果锁定。先只读确认隔离 Runtime 仍只有脚本预置的两个 Run、没有浏览器新增记录，再建立一个要求 fetch 接收者不是客户端对象的确定性测试，修复前失败。修复为局部函数引用调用，测试及浏览器均通过。未放宽断言／阈值，未把未知请求直接盲目重发；失败与核对证据保留。

初次类型检查也暴露 SDK 原来无声明入口，已补 SDK 公共类型声明；最终使用真实类型检查，不以 any 声明掩盖 API 类型。

## 1. 决策

| 编号 | 决策 | 落点 | 后续 |
|---|---|---|---|
| D15 | 新增 `litellm` Harness：平台持有循环（`loop_owner=platform`），经模型网关直连任意模型，能力等级 L2。它是 Runtime 自有的默认真实模型路径；claude-sdk 作为第三方 Harness 的接入样板 | `services/runtime/src/runtime/harness/litellm.py` | — |
| D16 | claude-sdk Harness 的工具只经平台注入的进程内 MCP（`mcp__platform__*`）提供，SDK 内置工具全部禁用，工具 handler 只挂起等待平台裁决结果、不执行任何逻辑。据此声明 `tool_interception=enforcing`，能力等级 L1；证据为拦截探针测试 | `harness-adapters/claude-sdk/` | `can_resume_from_events` 在 S5 评估原生 resume 后再定 |
| D17 | claude-sdk 子进程隔离：`setting_sources=[]`、`strict_mcp_config`、`permission_mode=dontAsk`、`CLAUDE_CONFIG_DIR` 指向 Run 工作区；继承来的 `ANTHROPIC_*`、`CLAUDE_CODE_*`、`CLAUDE_AGENT_SDK_*` 环境变量一律置空后再设置网关地址与令牌，避免宿主机配置泄漏进会话 | 同上 | — |
| D18 | 模型访问一律经 LiteLLM：litellm Harness 用 OpenAI 兼容端点，claude-sdk 用 Anthropic Messages 兼容端点（`/v1/messages`），两者共用别名与网关 Key | `runtime/config.py`、`.env.example` | S2.4 网关 Key 改为按 Agent 签发的虚拟 Key |
| D19 | Runner 按 Harness 的 `DoneEvent.stop_reason` 决定 Run 终态：error → failed，cancelled → canceled，max_tokens → completed 且如实记录停止原因；Harness 的 ErrorEvent 记 `run.error` 并转发客户端 | `services/runtime/src/runtime/loop/runner.py` | — |
| D20 | Trace 粒度为每次 drive 一条：续跑新建 Trace，根 span 记 `ai.resumed_from_trace_id`，同一 Run 的多条 Trace 以 `langfuse.session.id=run_id` 归并；`t_run.trace_id` 指向最近一条 | `services/runtime/src/runtime/observe/` | — |
| D21 | Trace 内容脱敏：Run 带 confidential 污点后，模型轮次 span 只记元数据，不记提示词与补全原文（对应 ADR-0010） | 同上 | S4.9 数据分级矩阵复核 |
| D22 | 数据库 schema 只由 Alembic 管理：Runtime 启动时在同一连接上程序化执行 `upgrade head`，删除 `create_all`；时间列统一 `UTCDateTime`（读出补 UTC），MySQL 下 `DATETIME(6)`、utf8mb4 | `services/runtime/migrations/`、`state/db.py` | 多节点部署改为独立迁移 Job（见遗留 2） |
| D23 | 请求体字符串长度按数据库列宽约束，超长返回 422，避免 MySQL 严格模式下 500 | `services/runtime/src/runtime/api/admin.py` | 其他写库接口在 S2 一并核对 |
| D24 | 本机 Langfuse 用无头初始化（固定开发项目与 `pk-lf-dev` / `sk-lf-dev` 密钥），仅限本机 compose；生产由运维创建项目并经 Vault 注入 | `deploy/compose-dev/` | P0-4 预发布环境 |
| D25 | 思维链进入可重建历史：产生工具调用那一轮的思维链写入 `TOOL_REQUESTED.reasoning` 与历史中工具调用消息的 `reasoning` 字段，不变量同时覆盖；litellm Harness 不再在进程内缓存推理文本 | `loop/toolbroker.py`、`run/invariant.py`、`llm/client.py` | — |
| D26 | 每次 drive 结束（含挂起、出错、客户端断开）都调用 `harness.interrupt` 关闭会话；进程内活动 Run 注册表使取消接口能中断正在运行的 Harness；runner 在关键检查点发现 Run 已被取消即以 `done(cancelled)` 收尾 | `loop/runner.py`、`loop/active.py`、`api/messages.py` | 多节点取消经 Run 队列转发（S7） |
| D27 | 续跑时从事件日志重建污点（`TOOL_RESULT.data_class`），保证审批续跑后的 Trace 脱敏与外发收紧仍然生效 | `loop/runner.py`、`loop/toolbroker.py` | — |

## 3. 遗留与待办

| # | 问题 | 影响 | 计划 |
|---|---|---|---|
| 1 | `EventLog.append` 用"读 last_seq 再加 1"分配 seq，无行锁 | MySQL 多连接并发写同一 Run 时主键冲突 | S7（Run 队列与多 Worker）前改为 `SELECT … FOR UPDATE` 或原子自增 |
| 2 | 多个 Runtime 节点同时启动会并发执行迁移 | 迁移竞争 | 部署时改为独立迁移 Job，或 MySQL 下以 `GET_LOCK` 包裹；P0-4 预发布环境落实 |
| 3 | toolbroker 内部迁移到 auth-required / input-required 时不检查并发取消 | 闸口判定或工具执行期间被取消，可能覆盖 canceled 状态 | S7：t_run 行锁或乐观锁 |
| 4 | 每轮只支持一个工具调用（请求带 `parallel_tool_calls=false`） | 多工具并行场景效率低 | S5 / S7 |
| 5 | claude-sdk 等待平台结果以 `CLAUDE_SDK_TURN_TIMEOUT_S`（默认 300 s）为上限，超时放弃 SDK 查询 | 审批等待较长时，续跑按历史文本重建，丢失 SDK 内部上下文 | S5 评估原生 resume |

| 7 | `UsageEvent` 无 `reasoning_tokens` 字段（推理 token 已含在 output_tokens） | 无法单独统计推理开销 | Contract 小版本（V1.1）评估 |

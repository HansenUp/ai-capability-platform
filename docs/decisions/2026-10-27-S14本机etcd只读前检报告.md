## 隔离测试候选方案（尚未执行）

1. **先决定版本**：可选择复用现有 3.5.21 镜像开展版本限定的兼容性预检；若目标必须 3.6，则当前未观察到该标签镜像，获取固定 digest 的 3.6 镜像需单独授权下载，不能用 3.5 冒充 3.6。即使批准 3.5，也需根据镜像元数据核对来源、固定 digest 和二进制版本／具体 API；不把本地标签当作供应链证明。
2. **隔离边界**：只使用按 ID 创建并可回收的临时容器、`--network none` 和容器内部 loopback；不绑定宿主端口、不使用 host 网络或既有容器。新建带唯一标识的临时数据目录，若挂载需先验证 user 1001 的访问权限；禁止原库、共享挂载和现有数据卷。网络隔离和容器内运行测试工具的可行性须实际验证；不能假定镜像包含 etcdctl 或兼容 API 网关。
3. **操作与清理**：先建立资源归属登记、固定运行 ID 和容器 ID，保存仅合成配置、版本、命令、输出、退出码和错误；确认容器无网络与挂载范围。无论成功失败，仅停止并精确删除本次容器与本次自有临时目录，核对残留；严禁基于名称前缀批量删除其他容器、卷或镜像。不把镜像配置 `Volumes=null` 视作所有运行参数不会创建其他资源。
4. **回归与解释**：优先用受控工具验证真实单节点 CAS、线性一致读、失联、重启／单节点快照，以及独立见证替身不匹配时的失败关闭；不改变测试阈值、不增加重试掩盖问题。单节点测试不能证明多节点共识、生产高可用、独立见证、防回滚或灾难恢复。若需跨容器／多节点、gRPC 依赖、专门网络或付费／持久资源，先提交具体方案及新增授权。

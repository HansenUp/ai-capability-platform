# S12.1 不依赖真实备份与原库升级的本机收口建议

## 本轮边界与结论

本轮仅核对源码、测试和已有验收报告，梳理下一步；没有执行回归、连接数据库、启停服务、读取凭据或修改业务代码。真实备份与原库迁移继续暂停；自动跟进不启用，不部署、不写真实评分或 Trace。

已实现的反馈审计、可信写协议、SDK／Chat 交互、可信聚合 v2 和独立证据只读准入，不应再列为待开发。当前未发现必须先升级现有 ai_platform 才能开展的本机代码收口；真实来源验收受阻，不代表隔离开发受阻，也不能以替身结果替代真实验收。

## 已有能力与证据

- Runtime 权威修订、outbox、主体锁、显式发送／只读恢复／本人 ACK 已实现；SDK 与 Console 已接入，重载、断连、身份隔离及多标签竞争有隔离浏览器证据。
- v2 按最新已接受修订聚合；未决／中性不回溯，历史未验证与冲突使正式比率未知。计算器、接口、页面和隔离浏览器已有覆盖。
- 独立 `FEEDBACK_LOCAL_EVIDENCE_READ=1` 不开启反馈写协议；四种开关组合、验签身份、单租户和范围守卫已有测试。它不是整个 Runtime 的只读运行模式。
- 真实 Langfuse 3.225.11 的 Scores v2 列表／单条和 Trace GET 已核对结构兼容；并未验证真实可信样本或写入协议。
- 最近完整 Python 证据为可信聚合 v2 轮 1491 passed／38 skipped／2 warnings。后续独立只读准入轮为反馈专项 83、读取器 7、OpenAPI 属性 35、浏览器 75/75，未重跑全仓；迁移演练后也未全仓收口。上述均为历史结果，不是本轮验证。

## 可直接执行：不依赖真实数据和凭据

| 顺序 | 工作 | 最小验收及边界 |
|---|---|---|
| 1 | 建立当前代码的覆盖矩阵，核对已有测试而非重复开发 | 映射写协议、聚合、只读开关、身份／旧响应、多标签、上限和失败关闭到现有用例；仅对确实缺失的格子补测试，不把建议场景直接宣称为已发现缺陷 |
| 2 | 对当前版本做反馈专项与页面定向收口 | 临时库、签名测试身份和 Langfuse 替身；重点复核只读开启／写关闭、有未决锁时读取不改账本、不发下游写、正式比率未知和旧结果清空。保留原断言、超时和失败日志 |
| 3 | 完成当前工作区的整体验证与可复现报告 | Python 全仓、SDK／Console／Portal 类型构建、lint、OpenAPI、既有隔离浏览器；先检查夹具不会连接现有库或真实观测出口。测试可用临时 Mock Worker，不启动现有真实 Worker；不把全仓通过等同真实来源通过 |

这批工作的主要剩余项是当前版本验证和证据一致性，不是重写已完成的反馈产品流程。不需要真实备份、原库升级、新服务身份或真实评分写入。

## 推荐下一步

先做“当前版本的隔离验收收口”：覆盖矩阵 → 确认夹具安全边界 → 反馈专项／浏览器 → 全仓及类型静态检查 → 更新验收报告。发现真实缺陷再最小修复，不新增指标、不改变反馈契约，也不为测试通过增加重试或放宽断言。

若全仓出现超出已确认契约的架构／业务取舍，或必须访问真实库、配置新身份或写真实观测数据，保留证据并暂停相应工作；不要转入备份／迁移路线。完成后可声明“获批本机范围已验证”，仍不得声明真实可信满意度已可用或 S12.1 完整出口通过。

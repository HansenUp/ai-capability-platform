# S12 单卡审批／拒绝持久回执验收

## 范围与授权

沿用 2026-10-21 12:06:08Z 至 22:06:08Z 的自动推进窗口、Runtime 权威账本、按验签租户与真实写操作者冻结新写、精确终结回执后的本人显式收口。仅本机实现与隔离回归；不操作真实业务、账号、生产，不提交、建分支、推送、合并或部署。本轮开头读取适用实现与报告、检查时间／磁盘和账户工具：可用磁盘约 999 GiB、ordinaryUsageAllowed=true、周窗口已用 48%，未触发已知额度或消费上限。不使用额外额度或重置券，不保证不可观测资源余量。

已复用前轮 credential 闭环，新增 **单卡 approve／reject**，不扩展批量、可编辑 TTL／意见、代理／服务身份或管理员解锁，不标 S12.3 整体完成。创建和回答仍待后续接入。

## 安全与一致性契约

- 审批 attempt 属于实际审批人 Bob，不属于 Run 发起人 Alice。主体键继续用可信验签维度，不用 Run.subject 替代写操作者。Alice 可读自己的 Run，但读／确认 Bob 的 attempt 均 404；Bob 的活动指针冻结 Bob 的全部新写，不冻结 Alice。
- 写前登记校验验签用户、租户、非自批、Run 挂起状态、当前仍待审批的单一 call_id、参数指纹和该调用最新决策事件序号。新协议不使用开发态自批旁路；未强制鉴权时 current_principal 不验签 Bearer，因此不能仅凭 Bearer 字符串进入新协议。
- 动作指纹绑定主体、approve／reject、Run、请求事件序号、call_id、params_hash，以及原 Chat 默认的 TTL=900 秒、空意见。TTL 在显式执行时按既有规则起算，登记、查询、回执重放和收口不延长有效期。prepare 不批准、不拒绝、不入队。
- 从旧 approve／reject 抽取 `apply_approval`，由调用方持有事务，不自行 commit。旧 API 保留原签名、正文、状态、批次语义和入队规则；新协议仅支持单卡，额外 TTL、意见、calls 等字段拒绝，不默默扩权。
- execute 重新校验权限和决策序号，将带唯一 workbench_attempt_id 的 tool.approved／tool.rejected、Run 状态、拒绝时的终态凭据删除及 COMMITTED 回执原子提交。审批提交后按原规则入队；同 attempt 的已决重放只返回回执，不延长 TTL、不重复入队或追加审批事件。预期拒绝保存点回滚后可生成 REJECTED_NO_EFFECT；未分类故障整体回滚，仍 PREPARED。
- COMMITTED 是本次工作台写的提交回执，不是工具成功或 Run 完成证明。ACK 校验同主体、attempt、动作、Run、版本／指纹及精确事件中的 call_id、params_hash、approver；缺失或冲突均保留锁。收口只清除本人本条指针并审计，不再批准、拒绝、续跑或执行工具。

## 本机实现

新增迁移 0008：为账本增加 action／call_id／params_hash；已有 0007 credential 记录回填 credential，原主体指针、状态和指纹保留。迁移测试验证升级、降级、重升级和 ORM 一致性，只使用临时库；未升级现有业务库或生产库。S7 head 断言精确更新至 0008，不改为宽松断言。

SDK 增加 prepareApproval，校验动作和调用绑定，credential 登记仍强制返回 credential，防止同 attempt 被换动作。settle／ACK 验证所有不可变字段。Chat 先预览并登记，再显式执行已登记批准／拒绝，显示单卡调用指纹、900 秒有效期和写回执边界；支持服务端只读恢复与本人确认。当前页已知记录的动作或调用绑定改变也失败关闭。

旧 API 的主体锁仍是**新请求准入门禁**，不追溯已经准入的旧请求，不把无 attempt 的旧事件冒充请求级回执。未接入的 create／answer 保留原能力边界，页面已提示。

## 失败、默认选择与未确认项

首轮 Ruff 报测试 SQL 字面量过长，已拆分字面量，不改变 SQL 或行长规则。补充开发态负向用例时，先误把冻结 dataclass Settings 当作 Pydantic 对象复制，后又误认为开发态会验签 Bearer；核对真实 current_principal 后，用 dataclasses.replace 在受控上下文切换设置，严格断言开发态所有新协议请求均 403，恢复强制验签后才断言 Bob 登记成功。没有修改权限实现来迎合错误假设，没有增加超时、重试、跳过或放宽拒绝断言；失败日志脱敏归档，测试 JWT 不进入证据。

首轮全仓还出现原 Worker 测试 `len(q)==0` 实得 2。小集合诊断没有稳定复现，不能拿其偶然通过当修复；只读检查本轮隔离临时库，确认新增用例因故意拦截入队而遗留两个 durable／working 合成 Run，部分已被后续 Worker 的启动 reaper 领取。新增仅限本测试文件的生命周期夹具，逐一使用原取消 API 收尾自己创建、尚未终态的 Run，检查取消回执状态并断言自身 Run 不再是 reaper 候选；终态 Run 不改，不清空共享表、其他用例数据或队列。原 Worker 测试和 Runtime 的扫描、租约释放、ACK 时序及所有阈值完全不改。新增／旧账本、迁移和 Worker 整组定向 54 passed／3 skipped，随后最终全仓 1378 passed／38 skipped。

范围内自主选择：沿用既有单卡 Chat 的 900 秒／空意见，不新建业务表保存原始参数；只持久化现有调用标识和参数指纹；复用共享事务，不另做审批引擎。无需新增业务选择确认。

仍需另行确认且未执行：真实业务写、账号／外部 IdP、生产迁移部署、管理员代解锁、代理／服务身份、记录清理与额外付费或持久服务。D47、Helm／Argo CD、S10.7、S9 外部验收和远端门禁保持原状态。

下一可执行闭环：answer 的持久写前登记及精确输入回执，再处理尚无 Run ID 的 create 结果定位。敏感回答／消息不得因增加账本而另存明文；必须明确内容绑定和旧 API 准入边界，不以 TTL／Run 终态／空列表／404 直接解锁。10 小时自动跟进保持开启，截止不变。

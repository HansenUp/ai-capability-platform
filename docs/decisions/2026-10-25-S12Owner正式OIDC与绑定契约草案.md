# S12.1 Owner正式OIDC、身份绑定与合成测试契约草案

日期：2026-10-25。状态：**离线待确认草案，不是已采纳ADR，不是运行配置**。承接《2026-10-25-S12Owner正式IdP与身份映射接入前检》；本轮授权仅起草，无实现接入、IdP变更或新权限。

## 1. 不变边界

Owner仅单Agent摘要与最小Trace聚合，不含反馈、原始Trace、全租户查询或北极星。沿用已确认D1～D6：验签真实用户、精确旧user映射、当前UserAgent分配，管理员不豁免；可读接手前获准聚合。T1准入与T2输出前复核，T2后已准入响应可完成；重授按当前授权，JWT角色不保证即时撤销。目录元数据、创建者及Run发起人均不能代替Owner分配。

现有测试profile及旧管理员接口保持原样，正式接入默认关闭。本草案不把现有本机开关升级成正式开关，不改变原Runtime／发布／节点认证，不因OIDC通过而提升Trace来源可信度。

## 2. 推荐OIDC配置契约

### 2.1 静态profile与客户端

推荐后续由服务端受控配置提供下列字段；此处是字段设计，未新增环境变量或加载器。

| 字段 | 推荐约束 |
| --- | --- |
| profile_id／revision | 不含密钥的稳定标识与单调版本；整体校验、整体切换，T1／T2绑定同一配置代次 |
| issuer | 精确匹配，固定允许列表；不从token／query／浏览器推导信任根 |
| audience | 单一Owner API专用字符串，不接受多aud列表，不复用ai-runtime或节点受众 |
| client_id | 精确匹配azp的公开人类客户端；优先评估已有console-web，是否复用需确认 |
| jwks_uri | 管理员受控的确定地址，HTTPS；本机回环HTTP仅限另行批准的隔离profile；禁止重定向和任意发现地址 |
| algorithms | 固定RS256以延续本机契约；不依据header自行放宽；拒绝none、对称密钥和私钥配置 |
| role_map | 精确realm角色到既有Role枚举的受控白名单；至少ADMIN且仍需分配，不接受令牌自报权限映射 |
| binding_revision | 引用精确清单版本／内容标识，不允许客户端指定，不能跨profile复用 |
| callback／origin | 授权码＋S256、精确回调和origin，不沿用通配回调；具体地址待确认 |

已有console-web默认ai-runtime／act scope可能产生受众／代理声明冲突。推荐先评估独立Owner scope且不破坏旧消费者；如无法保证单受众与直接用户，再提交独立客户端方案，不直接删改共享scope。客户端／受众／角色正式名称均待确认，console-owner-test等测试值不作为正式默认。

### 2.2 令牌判定

- 仅Authorization Bearer access token；不接ID token、URL token、开发身份头、服务或代理身份。浏览器解码只作展示，授权事实由后端验签产生。
- 必需iss、aud、sub、tenant、exp、iat、nbf、azp、identity_type；标量类型／非空／时间有效性严格校验，身份字段不trim、不大小写折叠。要求identity_type=user且azp匹配client_id。
- 拒绝act、may_act、client_id代理／服务声明及既有服务账号识别条件；role缺失／不允许则拒绝。真实IdP若不满足，先改草案／申请mapper契约，不在实现中静默兼容。
- exp／iat／nbf必须可靠；允许时钟偏差、最长令牌寿命及具体刷新策略须确认，不自选宽限期掩盖过期。不得以刷新成功推断用户或分配仍有效。
- issuer＋tenant＋sub核对受控绑定，再以tenant＋legacy_user＋agent查当前分配。范围不存在／不分配统一不披露；身份无效401、无映射／角色403、不可用配置或授权存储503。T2失败丢弃完整结果。

### 2.3 JWKS与会话故障边界（候选）

JWKS仅读取受控公钥，固定响应大小／超时／缓存寿命；具体数值与请求限额确认后冻结测试。缺kid、重复kid、算法不符、过期缓存且源不可用均失败关闭。未知kid最多触发一次受限刷新，不形成无限重试；并发刷新合并且限频，不访问token中的jku／x5u。缓存尚在有效期可使用已验证键，是有界旧键信任，不宣称立即密钥撤销；是否接受该边界需确认。不得把临时网络故障变成旧授权无限续期。

建议Owner access／refresh token仅内存，登录态重载后重新认证，不从Portal sessionStorage复制令牌。PKCE state／verifier在重定向期间的保存例外、一次消费／过期和回调路由清理需确认；不将业务Bearer放URL或持久存储。身份／tenant／profile切换立即清空数据与在途代次，忽略迟到响应；登出仅清理本地并不撤回已交付数据。IdP全局登出、refresh rotation、多标签协调与即时角色撤销属于后续明确范围，不默认提供。

## 3. 受控身份绑定清单schema

机器可读草案：`docs/contracts/owner-identity-bindings.schema.json`，JSON Schema 2020-12，无加载器、真实身份样例或部署引用。不是签名证明；revision／change_ref本身也不能证明发布获批。

推荐先采用仓库外受控版本化清单而非新增业务表；清单是身份链接，不赋予角色或Agent分配。独立审核者审批后通过受控发布整体替换，只读运行身份不可改；维护者、存放位置、安全权限与审计证据载体待确认。未引入签名、密钥或管理API。

| 规则 | Schema／语义职责 |
| --- | --- |
| schema_version=1、revision正整数、profile_id、change_ref、bindings | Schema限制字段与类型，拒绝额外字段、空值和控制字符；uri的format断言必须显式启用 |
| issuer／tenant／subject／legacy_user精确值 | 不允许模糊匹配、通配租户或token自报旧user；issuer须与profile精确相同，属于语义校验 |
| 双向唯一 | (issuer,tenant,subject)及(tenant,legacy_user)均唯一，包括完全重复行也拒绝；uniqueItems不能替代复合键校验 |
| 大小限制 | 建议最多2000绑定、标识最长256字符；issuer最长2048。仅提案，真实兼容性未经原库核对；不截断或自动清洗 |
| 撤销 | 删除对应绑定并发布新revision；空bindings合法、所有Owner拒绝。撤销不是删除业务分配，历史清单不得自动重新启用 |
| 版本与失败 | 新版本整体通过schema＋语义＋发布审批校验才切换，拒绝回退／同版本不同内容；不可用新配置令Owner失败关闭，不静默回退旧绑定。无自动回滚 |
| 并发 | T1固定不可变profile／清单代次，T2发现任一变化拒绝本次输出；多进程需确认一致发布与失败关闭机制，不宣称单进程原子引用解决集群撤权 |
| 审计与隐私 | change_ref关联外部审批／旧新版本摘要／受控操作者和时间；不记录token／评分／Trace正文。清单含身份信息，应限制读取，不提交真实清单入仓 |

不从DirectoryUser自动同步，不提供管理员代绑定、别名合并、多issuer共享旧user或自助认领。业务确需这些能力需另议；原库只读数据质量核对、迁移与备份恢复仍各自独立授权。

## 4. 合成测试矩阵（待实现，不是通过结果）

所有正向身份由测试构造，临时库、固定合成声明、内存JWKS／Langfuse替身；不得加载真实.env／密钥或出网。未来密码学测试仅在另行获批实现轮使用临时测试身份材料。时间与并发用可控时钟／屏障，不增加超时／重试或放宽断言。

| ID | 场景 | 必须断言 |
| --- | --- | --- |
| O01 | 正确direct-user＋专属aud＋显式分配 | 仅指定Agent最小摘要／Trace；无反馈与额外个人字段 |
| O02 | 缺Bearer、ID token、伪造签名、错误iss／azp／aud、多aud | 拒绝；下游源GET为0；ID token即使同密钥也不能通过access-token准入 |
| O03 | 缺identity_type／nbf／tenant、错误类型、act／may_act／client_id、服务身份 | 拒绝；不能靠metadata补身份 |
| O04 | 过期、未来iat／nbf、T1后到期、角色不允许 | 失败关闭；T2到期无部分结果，不自动刷新或重发查询 |
| O05 | 未绑定／重复身份／重复旧user／跨tenant同名 | 未绑定拒绝；无效清单整体拒收；不同租户不串授权 |
| O06 | 无分配、创建者相同、管理员、跨Agent猜测 | 不豁免分配、不泄露其他范围数量 |
| O07 | 绑定撤销／分配撤销／profile变更发生于源响应期间 | T2拒绝且丢弃结果；T2后撤销当次可完成，下一次拒绝；ABA按既定当前分配 |
| O08 | schema额外字段、空值、控制字符、重复行、issuer错配、超量 | 无静默修复；schema与复合键语义均覆盖，无部分激活 |
| O09 | 清单旧版本、同版本异内容、并发切换、损坏／读失败 | 拒绝回退与未知代次；失败关闭，不复用陈旧授权 |
| O10 | JWKS已知kid、轮换、未知／重复kid、错误算法、jku注入 | 仅访问固定替身；限频／刷新合并；缓存边界与失效严格按确认规则 |
| O11 | JWKS断连、重定向、超大响应、缓存过期 | 不出网／跟随跳转／无限重试；不可验签失败关闭 |
| O12 | 身份／tenant切换、刷新后不同sub、页面卸载与旧响应 | 立即清空，旧响应不能覆盖新查询；刷新不继承旧绑定 |
| O13 | 重载、登出、多标签切换与回调state重放 | 不存业务token；重新认证；回调重放拒绝，不跨标签继承身份 |
| O14 | 当前scope产生Runtime aud或代理声明 | 明确兼容拒收；不降低Owner校验、不改旧Runtime路径 |
| O15 | 原管理员开发头、节点／发布账号、查询身份覆盖 | Owner拒绝混用；原接口回归不拓权；日志无token与原始Trace |
| O16 | 接手前历史、半开窗口、来源错配／未知用量 | 保留原聚合契约；身份通过不升级来源，未知不补零 |

O02的access／ID token区分仍需确认IdP的可靠签名声明（例如固定token类型／用途声明），仅aud／azp不充分；不得先宣称该安全属性已实现。O10～O13依赖待确认参数／生命周期，当前只能冻结测试目标，不能报验收通过。未来真实浏览器隔离回归与纯函数／ASGI测试分别报告，不互相替代。

## 5. 推荐决策与需确认项

1. **C1客户端与声明**：优先评估console-web＋隔离Owner scope／单aud；确认正式名称、直接用户／access用途证明、角色映射和必需claims。不修改现有realm。
2. **C2映射权威**：推荐受控版本化清单、双向唯一、整体拒收／失败关闭；确认维护／复核人、安全位置、容量限制、多进程发布及审计机制。无需预设原库迁移。
3. **C3会话**：推荐内存令牌＋重载重新认证；确认PKCE短期事务状态、刷新／登出／多标签范围及令牌寿命／时钟偏差，不默认复制Portal存储。
4. **C4密钥与撤权**：确认固定JWKS信任根、缓存／轮换／故障策略及有界旧键信任；沿用D1～D6在途边界，不升级即时撤权承诺。
5. **C5实施授权**：以上确认后，可另行授权只做临时库／签名合成身份／替身的配置加载及矩阵验证；真实IdP／JWKS核验、原库最小读取、实际身份绑定与发布均另设门禁。

本轮完成草案与schema，仅校验JSON可解析及文档差异；没有实现schema加载／语义验证器、运行合成业务测试或重跑全仓。没有读取密钥、连接真实服务／原库、写评分／Trace、操作IdP、部署或启动自动跟进；未先执行任何待确认方案。北极星仍待定义，S12.1不标整体完成。

# S10.4 本机路由与身份安全契约

本记录限定本机开发，不启用 Helm／Argo CD、不部署生产。首个增量保留为历史背景，当前实现与约束以本文“本机实现契约”及 S10 开发记录的实际验证为准，不代表生产验收。

## 控制面快照

`GET /routing` 新增兼容字段 `tenant_id`，取自已授权 Operator，而非查询参数。`groups` 仍为组名到健康、ready 节点 ID 数组；`bindings` 仅包含该租户的 Agent 权重。节点 ID 不是 URL，不允许从节点注册或请求头构造任意上游地址。

后续插件须用可信配置中的租户身份拉取，缓存按租户和配置隔离；快照 tenant_id 必须匹配预期租户，错误租户或结构非法不得覆盖已有缓存。当前 Console 开发身份头不是生产服务鉴权，生产拉取凭据仍需独立设计和授权，不转用节点令牌冒充管理员。

## 插件实现前必须保持的边界

- 先验证调用者 JWT，再取租户、subject 和 actor；剥离客户端自带的 X-AI 身份头与 Console 角色头。保留原始 Bearer 给 AUTH_REQUIRED=true 的 Runtime 独立验签，不能为接入网关关闭 Runtime 鉴权。
- 节点 ID 只能映射到平台静态配置的上游白名单；未知 ID 不作为主机名解析。纯 Worker 不得进入接收 HTTP 的节点组，须由配置／角色校验保护。
- 按 Agent 的正权重选组，再在该组健康节点中选择；全零权重或显式绑定组无可用节点返回不可用，不能静默转到未绑定组。仅未绑定 Agent 使用默认组。
- Console 故障沿用最后有效租户缓存；冷启动只能使用该租户显式配置的静态默认组。没有可信租户或可用静态上游则失败关闭，不能跨租户共享默认缓存。
- 新 Run 可按 Agent 绑定选节点；已有 Run 查询、SSE、恢复和审批不能假设请求总带 Agent ID，也不能解析不可信请求头后随机跨组。现有 Run 路由与节点归属／共享状态契约必须先闭合，不把模型切换语义扩展成任意跨节点重路由。
- APISIX 健康检查、重试及 JWT/JWKS 集成需在真实本机 APISIX 中验证；有副作用的 POST 不自动重试。当前没有 APISIX 镜像或 Lua 工具实跑证据，不标记插件完成。

## 首个增量进度（历史）

本轮仅完成租户标识字段及防查询参数冒充回归。后续依次补齐服务拉取鉴权、节点白名单与 Run 路由约束，再实现插件与隔离本机 APISIX 验证。S9 外部验收、D47 及 S10.7 保持待办。

## 本机实现契约：只读服务身份

- 管理页面原 `/routing` 开发身份链保持兼容；插件只拉新增 `/internal/routing`。此接口不接受开发角色头、查询参数或节点令牌替代授权，仅使用签名服务身份。它不赋予服务调用者 Console 管理权限，也不宣称整个 Console 已完成生产身份改造。
- Console 须配置 CONSOLE_ROUTING_JWKS_URL／CONSOLE_ROUTING_ISSUER／CONSOLE_ROUTING_AUDIENCE，缺配置或 JWKS 不可用返回 503。只接受 RS256、有 kid、具备 exp／iat／sub／iss／aud／tenant／client_id／scope 的有效 JWT；client_id 固定 ai-routing-svc，scope 含 routing:read。无效令牌 401，错误 client／scope／租户 403。每个令牌只读签名 tenant 的快照，头与查询不能换租户。
- Console JWKS 按 URL 缓存 60 秒，未知 kid 拒绝，不无限刷新；插件用户 JWKS 缓存同为 60 秒。生产轮换和吊销传播仍需验收。
- routing_token 来自受信任 APISIX 配置，schema 标记 encrypt_fields；独立 YAML 文件不会因此自动磁盘加密。临时含令牌配置不归档。生产服务客户端、密钥注入及服务令牌刷新不以本机临时 JWT 代替。

## 本机实现契约：白名单与已有 Run

- nodes 最多 64 个静态 HTTP 节点，限定 IPv4、合法端口、api／all 角色；Worker 拒绝。fallback_nodes 必须在白名单内。Console 节点 ID 仅查此映射，不作主机名或 URL 解析，未知 ID 不转发。节点注册不能修改白名单。本机上游仅支持 scheme=http，不冒充已验证的 TLS／mTLS。
- 每份租户配置仅一个 state_pool，全部白名单节点必须声明同池。这个名字是配置管理者的可信承诺，不是数据库或物理隔离的自动证明：同池必须共用持久 Runtime DB、Redis／租约、凭据加密与事件指纹密钥、可访问的工件／工作区和兼容的 Harness／Skill 配置。不得把不同状态后端填成同名以规避约束。
- 新 Run 只在 POST /v1/messages、POST /v1/runs 从最多 1 MiB JSON 体读取 agent_id，不相信自称路由头，不修改原体。未绑定使用 default_group；已绑定仅在正权重、存在健康白名单节点的组间按权重选择，再由 APISIX 组内轮询。全零／空绑定或全部绑定组不可用返回 503，不转到未绑定默认组。
- 已有 Run 查询、events、stream、approve／reject／resume／cancel／input／feedback，以及列表，在同一租户状态池的健康白名单节点转发，不要求重传 agent_id，也不套用 Agent 的最新绑定。其他公开前缀内路径／方法 403，不暴露 admin。Run 快照、原主体、审批参数指纹及 Worker fencing 仍由 Runtime 校验。
- 不提供跨池迁移、进程内 Harness 会话无损搬迁或自动重放未知写。流断开由客户端按 Run ID／事件序号重连，不能因为 502／超时就重做写操作；保持已有幂等和对账流程。在途 Run 的模型版本不因路由重绑改变。

## 本机实现契约：用户身份与降级

- 插件使用 lua-resty-openidc／JWKS 真实验签，限定 RS256、kid、issuer、audience、tenant、exp／iat／nbf；拒绝 none／HS*、声明类型异常及未来／过期令牌。签名前不使用 payload 路由。
- 剥离客户端全部 X-AI-*、X-Console-*（含下划线等价写法）和 X-Userinfo／X-ID-Token／X-Access-Token，再注入已验证的 subject／tenant／actor。用户 human:sub、应用 app:client_id，act 优先于 azp，与 Runtime 语义对齐。Authorization 原 Bearer 保留，Runtime 必须 AUTH_REQUIRED=true 独立验签及执行禁自批；注入头不替代授权。
- 缓存按完整配置指纹（含租户、凭据、信任源、白名单、状态池）隔离，每 worker 最多 128 份。活跃流量按 refresh_seconds（默认 10 秒）触发异步拉取；首次请求作一次有界冷拉取，空闲不轮询。结构／租户错误或生成时间倒退不能覆盖旧表。失败沿用最后有效表，陈旧告警，不按年龄删除；进程重启／LRU 淘汰视作冷启动，只用显式静态 fallback_nodes，无回退返回 503。
- 实跑确认 APISIX 3.11 的 upstream.set 不自动初始化原生健康检查，不能只填写 checks 便宣称生效。本插件显式探测静态节点 /healthz（500ms／节点、缓存 1 秒），无健康节点 503；log 阶段将上游 429／5xx 记为被动失败，后续探测成功恢复。存在一秒传播窗口。当前按需串行探测，最坏延迟随节点数增加，生产容量／并发探测优化未验收。
- retries=0，读写都不自动重试。故障可先返回 502，健康排除后返回其他健康节点或 503；不以请求重试替代副作用对账。

## 真实本机回归入口与外部边界

`make verify-s10-routing` 使用固定官方 apache/apisix:3.11.0-debian、独立 Redis、真实 Console、双 Runtime（JWT 开启）、共享临时 SQLite 与临时 RSA JWKS；只暴露随机回环端口。Docker Desktop 通过 host.docker.internal 访问回环服务，白名单使用其解析后的 IPv4，不泛化为生产网络授权。

验证 schema 拒绝纯 Worker／混合池／坏地址／未知回退，服务鉴权与用户 JWT、权重／零权重／默认组、白名单、身份头剥离、坏缓存、健康失败关闭、POST 不重试；Agent 重绑和原 HTTP 节点退出后查询／SSE；模拟写挂起后跨节点审批恢复（禁自批／应用审批、执行一次）；Redis 持久 Run、Console 故障缓存及冷启动回退。模型、策略和工具明确使用本机桩，不替代真实厂商、Cedar 或业务写验收。具体结果以开发记录为准。

生产管理面 ACL、正式服务客户端及自动令牌轮换、TLS／mTLS、网络强隔离、多 worker／容量压测、外部渗透与签字仍未验收；S9 外部待办、D47、S10.7 不变。

实现参考 Apache APISIX 的 [插件扩展接口](https://apisix.apache.org/docs/apisix/plugin-develop/)、[3.11 upstream 源码](https://github.com/apache/apisix/blob/3.11.0/apisix/upstream.lua)和 [3.11 openid-connect 源码](https://github.com/apache/apisix/blob/3.11.0/apisix/plugins/openid-connect.lua)，同时核对镜像内实际 API。

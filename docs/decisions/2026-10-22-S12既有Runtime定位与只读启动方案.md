## 只读启动方案（待前置条件满足，未执行）

1. **既有库**：由用户指定实际非生产账本 DSN／文件及既有配置来源。先在批准范围内只读核实文件存在、数据库类型和 schema 版本，确认反馈账本／outbox 所需表已存在；需要迁移即暂停，禁止 create_all／空库初始化或拿测试库补样。
2. **身份**：仅使用已有验签用户管理员凭据；核实 issuer、audience、JWKS 与目标租户，不新增账号或角色，不生成替代用户 JWT。令牌通过安全本机环境提供，不粘贴聊天或报告。
3. **启动参数约束**：明确设置 `RUNTIME_ENV=dev`、`AUTH_REQUIRED=true`、`RUNTIME_MIGRATE_ON_START=false`、`RUNTIME_ROLE=api`、`FEEDBACK_LOCAL_EVIDENCE_READ=1`、`FEEDBACK_LOCAL_PROTOCOL=0`；禁用节点代理并清空两个 OTLP 导出地址。此处仅列约束，**不是可直接执行的启动命令**。
4. **后台门禁**：使用已有且获准的 Redis 配置才能满足现有 api 角色校验，并须明确接受 CancelListener；若要求连订阅任务也不得运行，需要另行批准无后台只读入口的代码闭环，不能绕过 WorkerSettings 校验或改为 all。
5. **审计门禁**：需要明确允许标准安全审计落库还是要求数据库严格零写。前者不应改动 Run／attempt／outbox；后者须另行设计批准的只读快照／审计出口，不关闭审计或直读库绕过用户权限。
6. **仅 GET 的边界**：独立证据开关不启用反馈协议写接口，但不会关闭整个 Runtime 的其他既有写 API；后续运行应绑定 loopback、只使用规定 GET，并明确其他调用者的访问隔离。若需新增全局写拒绝入口／网关，先授权，不在本轮悄悄扩大实现。

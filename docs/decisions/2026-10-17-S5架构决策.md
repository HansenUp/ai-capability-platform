## 2. 联调与评审发现

- **spike（D79）**：合成转录可被 CLI 载入；以流式输入补发 tool_result 不可行（CLI 先给悬空 tool_use 补"interrupted"错误结果并丢弃后到结果），改为整段历史写入转录 + 自动续跑。
- **独立评审必须修 4 项均已修复**：① 续跑消息未与事件日志绑定、审批人可改写对话并自批高风险写（D88 指纹 + 只允许发起人续跑）；② 审批人续跑后续工具以审批人令牌执行、结果回流发起人（同上）；③ litellm 中断在读流任务首次调度前发生时消费端永久挂起（done 回调兜底）；④ 安装顺序使 `ai-harness-probe` 从 PyPI 解析（一次性安装）。建议修 6 项一并处理：工件分级洗白、无盐指纹、审批视图过宽、Hooks 探针近恒真、实时与转录路径 is_error 不一致（TurnInput.tool_statuses）、post_model 拒绝前输出已下发。
- **verify-s5 发现**：claude-sdk 调不了名称带点的平台工具（D83）；原探针因脚本化 CLI 未规范化工具名而漏检，已补。
- litellm 中断只在下一个增量到达时检查，上游停顿时无法中断（探针发现），改为独立读流任务、interrupt 直接取消。
- stdio interrupt 改为结束会话并回收子进程（原实现泄漏子进程），会话 id 改由适配器生成。

# S12 回答持久回执验收

## 范围与安全契约

沿用用户已批准的 Runtime 权威账本、验签租户和实际操作者范围、冻结同主体全部新写、精确终结证据后本人显式收口。自动窗口仍为 2026-10-21 12:06:08Z 至 22:06:08Z（北京时间 20:06:08 至次日 06:06:08），未延长。本轮只接入 answer，不修改账号、真实节点或业务，不提交、推送、发布、迁移现有业务库或部署生产。已核对前轮 credential／单卡 approve／reject，不重复实现。S12.3 仍未整体完成，create 尚待接入。

本轮开头及长回归前检查当前 UTC 时间和可观测资源；13:20Z 账户工具报告 ordinaryUsageAllowed=true、周窗口已用 49%、spendControlReached=false，可用磁盘约 999 GiB。未动用重置券或购买资源，不承诺不可观测的 CPU／费用／配额余量。

- prepare 必须由验签 Run 发起人提交当前 answer 卡片的 call_id 和有效回答值；复用原 schema、深度与待答校验。只提交 PREPARED，不写输入事件、不续跑。原始回答仅用于当前请求校验，账本、审计和返回视图不另存原文。
- 内容绑定复用既有服务端 HOOK_DIGEST_KEY 的 HMAC-SHA256，域隔离包含协议、主体、attempt、Run、call 和规范化 JSON 值；指纹另绑定请求事件序号。不是可穷举低熵回答的裸 SHA。JSON null 与缺少字段严格区分；有限、深度受限、可编码 JSON 才可绑定。
- execute 需原操作者显式提供登记时同一 JSON 值，重新计算绑定、校验待答请求与权限；换值 409、漏值 422，均保留 PREPARED 与主体锁。不存在从账本恢复原文、自动重发或自动换值。
- 复用原 answer 输入处理及 post_tool hooks，在同一数据库事务写入带 attempt／内容绑定的 input.provided、原 tool.result、Run 状态和 COMMITTED；已决重放不重复输入或入队。预期拒绝保存点回滚后可形成 REJECTED_NO_EFFECT；未分类异常整体回滚并保留 PREPARED。既有大结果 workspace offload 不属于数据库事务，本轮不宣称文件系统原子性或新增自动清理能力。
- ACK 不接受回答正文，只核对原主体、attempt、动作、范围、指纹、版本及精确 input.provided 中的 kind、call_id、内容绑定。Run 完成、SSE done、404、空列表或浏览器存储均不是解锁证据。仅原操作者明确确认后收口，不重新提供输入。
- PREPARED 跨重启执行依赖服务端绑定密钥保持一致；密钥变更或丢失必须失败关闭，不能重新绑定或自动解锁。真实密钥轮换、密钥丢失处置与人工裁决不在本机授权中，留待确认；本轮未实施这些变更。

## 实现与兼容

新增迁移 0009，仅为现有账本增加可空 value_hmac。旧 credential／approval 数据结构与指纹保持兼容；迁移只在临时隔离库验证，S7 head 断言精确更新为 0009，不放宽断言。抽取原 answer 待答校验给 prepare／execute 复用，旧 input API 行为不改；活动主体锁仍是旧 POST 的新请求准入门禁，不追溯登记前已准入的在途请求，不能把旧协议事件当作 attempt 回执。

SDK 新增 prepareAnswer，严格区分 credential／审批参数指纹／回答内容绑定；execute 明确提供原值，ACK 不带原值，坏回执或绑定变化失败关闭。Chat 显示“登记回答一次”→“确认执行已登记回答一次”→本人确认收口；初次登记后原值仅内存保留，重载后执行框为空，必须重新填写原始 JSON（包括带引号的字符串／null）。应用身份及卸载清空原值；未知执行结果后只允许查询和精确收口，不自动重发。已知未决记录的内容绑定变化同样保留锁。

无效 JSON 在本机拒绝，不发请求。服务端拒绝登记后保持禁止新写，用户可重新应用身份并权威读取账本；不把网络失败或错误响应自动归为无效果。创建仍为旧协议，页面明确提示其未知结果内存锁尚无完整跨页保护。

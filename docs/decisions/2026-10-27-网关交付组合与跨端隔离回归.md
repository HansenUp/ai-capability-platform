## 结论与交付组合

当前工作区的网关删除与替代代码有明确设计关系，但仍需作为一个交付单元审核，不能只提交暂存删除。此次没有修改暂存区、提交、推送或部署。

| 交付单元 | 当前状态 | 关系与风险 |
|---|---|---|
| `services/capability-gateway/src/capability_gateway/mcp_proxy.py` 及 `tests/test_mcp_proxy.py` | 两项已暂存删除 | 删除的是旧自研 `/mcp/{server}` 代理及其测试；删除后旧代理接口返回 404 |
| `src/capability_gateway/dataplane_authz.py`、`tests/test_dataplane_authz.py` | 两项未跟踪 | 提供／验证 `/authz/mcp-check`、目标 server 与 system、策略不可用失败关闭和回调 token；必须与删除同步审阅纳入交付 |
| `src/capability_gateway/main.py`、`auth.py`、`config.py` 及相关测试 | 已跟踪文件未暂存修改 | `main.py` 全环境挂载回调并保留 `/invoke`；生产启动约束要求相关配置；不能只提交新模块而漏掉路由和配置 |

旧代理的流式转发不是由授权回调取代：agentgateway 才承担 MCP 转发；`/authz/mcp-check` 对工具调用做授权，`/invoke` 是另一条平台路径。回调中的 `require_approval` 返回 200，审批依靠 Runtime 上游，不能解释为回调自身完成审批。POC 配置将授权回调只绑定到 `tools/call`，方法限制、真实用户 OBO／act 验签、服务身份、流式行为、网络与生产密钥仍需在正式拓扑验收；现有 POC 示例不能作为正式部署配置。真实 agentgateway、本机之外的服务和生产均未启动。

### 首轮失败与修正

- Gateway 首轮 **41 passed、1 skipped、5 failed、11 errors**：执行器禁止全部子进程，阻止生产配置路由检查及 Skill 合成代码的 Bandit 扫描。保留 `gateway-broad.log`；之后只允许固定参数、指定测试内的两个本机 Python 子进程，其他子进程和父进程网络仍拒绝，原测试及断言未改，最终通过。子进程范围与审计限制见上。
- Console 首轮 **28 passed、1 failed**：测试用 SQLite `:memory:` 被执行器误判为非临时文件；修正守卫仅明确允许 SQLite 内存后，第二轮仍因执行器对内存标识调用 `relative_to` 出错，保留两份失败日志。第三轮修正记录逻辑后 29 passed；未连接外部库、放宽断言或修改迁移测试。

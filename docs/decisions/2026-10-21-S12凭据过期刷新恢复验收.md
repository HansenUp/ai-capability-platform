不提供浏览器自动获取／续签用户令牌，不连接真实 IdP、不存 refresh token；不扩展多轮会话、Token 流、附件或未知写对账操作。本轮未新增需人工确认却未经确认实施的事项；S12 整体及外部验收仍未完成。

## 核对的既有安全契约

- Worker 在同 Run 恢复前读取加密保存的发起人凭据；缺失或有效期不足时写 `input.requested{kind:credential}`，迁移到 input-required，不凭过期身份继续执行。
- 真正过期的访问 JWT 在 API 验签时返回 401。credential 输入的有效新令牌必须由用户在身份区重新应用；应用清空旧 Run／卡片／SSE 游标，重新定位原 Run 后才能操作，不沿用未应用的身份草稿。
- `POST /v1/runs/{id}/input` 的 `kind=credential` 使用已验签的 `principal.token`，而不是请求体 value；非发起人 403，其他租户 404，状态／待办变化 409。仅复用既有接口，不创建第二个 Run 或调用 resume。
- 成功刷新与 `input.provided`／状态迁移在同一事务提交，再由既有队列续跑；Run 终态删除存储凭据。浏览器不从 SSE 或卡片自行推断授权。
- 写响应丢失属于结果未知，锁定所有写入口；只读状态完成、SSE done、换令牌或换身份均不能解锁或触发重发。

未知写锁沿用当前页面内存契约，本轮验证限同一组件生命周期，不声称跨浏览器重载／新标签页持久化。没有新增 localStorage 锁、服务端对账或跨页解锁能力；新页面不构成结果已核对或允许重发的证据。若要求跨页强制持久锁，需要另行确定主体／Run 绑定、持久化与解锁证据规则，不能擅自增加。

## 过期模拟方式与边界

复用现有临时 loopback Runtime／Console、独立 SQLite 库、测试 RSA IdP、Mock Harness／策略和无外部效果工具。HTTP 鉴权仍强制验签，未关闭 exp 校验、伪造开发身份或等待真实墙钟自然到期。

先用有效 Alice 测试身份创建合成 Run，在 request_user_input 前置回答挂起时，将**同发起人已存储的凭据**替换为签名正确、exp 已在过去的测试 JWT；其密文与 expires_at 由真实 `store_credential` 写入。回答前置输入后，真实 Worker 读取过期存储凭据，产生 credential 待办。有效 Alice 访问令牌与存储的过期 JWT 是不同凭据；不是声称最初创建请求的令牌随墙钟自然到期。

浏览器夹具在其进程内 Mock Harness 注入上述状态，没有新增 Runtime HTTP 管理端点或生产故障开关；准备两个独立 Run 分别验证正常恢复、已提交后响应丢失。测试没有调用真实账号续签、停用、角色变更或真实工具写入。

## 夹具发现与修正

初次增强浏览器 52 passed／2 failed（当时共 54 项，新 DOM 用例尚未纳入该次执行）：两个凭据 Run 实际变 failed 而不是 completed。只读检查临时测试库的 run.error，定位到新增 Mock Harness 的 `KeyError`：只在 open_session 登记 Run ID，忘记 MockHarness.resume 会创建新的 session handle。

仅在测试 Harness 的 resume 路径同步登记 spec.run_id；不修改 Runtime、SDK 或工作台，不放宽 completed 断言或等待时限。失败日志保留，不能把它宣称为 Runtime 产品缺陷。新夹具此后通过真实恢复路径验证，不以直接改 Run 终态或模拟成功 JSON 绕过。

接着一次 54 passed／1 failed（55 项）发现完成但无持久化回答：新增替身分支漏发既有 Harness 契约中的 UsageEvent，TextEvent 没有形成 model.response 日志。补齐零用量 UsageEvent，保留原精确 DOM 文本断言，并对正常／丢失响应两条路径都新增实际 model.response 文本断言；不是用 Run completed 掩盖回答未落库。

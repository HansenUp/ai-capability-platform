# S12.1 可信反馈聚合 v2：契约与验收

## 契约

- 本轮仅临时库、签名测试身份及 Langfuse 替身；无生产、真实评分写入、自动跟进或账号变更。北极星待定义。
- 新增独立 v2，不升级旧审计路径或历史评分信任。Runtime 验签平台管理员按令牌租户及创建时间 cohort 提供有限证据摘要；Console 不向 Langfuse 转发用户令牌。
- 满意度分母为可信最新二元评分 Run，覆盖率分母为 cohort 中读取时已完成 Run。零分母返回 null；历史未验证、未决最新或冲突影响完整性时正式比率未知，不挑可信子集冒充整体。
- 对每 Run 按 Runtime 已接受的单调修订号取最新，而非 Langfuse 更新时间、到达顺序或 ID。最新 PREPARED／PENDING、缺失或摘要不匹配均不得回溯旧评分；最新中性不回溯。ACK 只管写锁，不决定可信性。
- 当前来源须同时满足 Runtime 协议证据与 OBSERVED 摘要、Langfuse 当前评分完整载荷摘要、Trace 归属。metadata 自报 verified 不构成来源证明。旧修订须有对应权威摘要才可归为已证明历史；其他评分隔离为未验证诊断。
- 同 ID 完全重复去重，冲突拒收；Run 最多一票。最多 2000 Run／2000 修订／20 页每页 100，超限拒绝部分比率；读取前后核对权威证据变化，仍不提供历史快照或跨系统原子快照。
- 只读 GET 不发送、重投、对账终结或 ACK，不返回评论、correction、个人排名或完整证明正文。

## 实际验收

### 已实现

- Runtime `GET /v1/metrics/feedback-evidence`：复用验签、平台管理员和单租户 cohort，新增有界协议证据摘要查询；核对 outbox、主体绑定、完成事件、修订、载荷摘要和 OBSERVED 证据。不暴露完整载荷；缺失 outbox／账本对应关系时拒收，不将遗漏视为无评分。仅开发环境且原协议开关开启时可读。
- Console `GET /metrics/feedback-v2`：保留 v1 不变；仅 GET 读取 Runtime 证据、Langfuse Scores v2／Trace，复用 loopback、无代理／重定向、大小、超时及分页约束。读取前后权威范围／事实／证据变化时受控不可用，不返回部分比率。
- 独立计算器按权威修订选择最新；旧修订已证明与历史未验证分开，来源冲突、未决、中性、已知点赞／点踩分别诊断。未验证历史使整体正式比率保持未知；不迁移历史，不按 metadata 提升信任。
- Operations 独立 v2 查询区与严格响应校验；实际验签身份、分子分母和排除原因分列。查询、令牌或 Console 身份变化立即清空，忽略取消的旧响应也不能恢复旧结果；令牌只驻内存。
- 无迁移、无新密钥／账号、无后台任务或重投；现有 prepare／execute／reconcile／ACK 业务语义未改动。

### 失败与修复

1. Runtime 新证据测试最初共用 `demo` Agent，读入之前故障注入用例留下的损坏证据，正确得到 503；拆为独立临时 Agent，并同步替身 Trace 的 Agent 归属。没有关闭证据校验或放宽断言，反馈专项最终 77 passed。
2. 新真实 v2 浏览器用例最初改评了既有可信反馈用例共用的 Run，导致原“当前修订 0”断言超时；该轮 74 passed／1 failed。保留原断言及 5000ms 超时，将新聚合场景拆成独立临时 Agent／Run，不重置或删除修订来伪造通过。失败日志归档于本轮 evidence。
3. 拆分 Run 后，既有可信反馈用例严格对账仍保持 PENDING_OBSERVATION（该轮 74 passed／1 failed）。根因是本机夹具 `OTEL_SDK_DISABLED=true` 使不同 Run 的 Trace 都为零 ID，替身按 Trace ID 查询时错误关联到先前 Run；服务端拒收是正确行为。仅夹具启用本机 Trace 生成，同时明确清空两个 OTLP 导出地址，不启动外部观测；增加非零 Trace 及跨 Run 不重用 Trace 的断言。保留原 OBSERVED 断言，不改业务核验、不重试或增加超时。
4. 原生 Ruff 直接读透明加密文件报 E902；改用仓库既有包装器，未修改检查规则。Portal 首次验证路径误写为 `apps/portal`，修正为已有 `apps/portal-web` 后类型与构建通过；不是业务实现失败。

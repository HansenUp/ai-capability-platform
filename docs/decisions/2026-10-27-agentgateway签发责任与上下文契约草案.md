# agentgateway 签发责任与上下文契约草案

本轮仅本机测试和契约整理；以下推荐尚未获正式接入授权，不新增签发服务，不修改生产身份配置。

## 现状与信任边界
现有 `/invoke` 验签服务令牌，限制可信 azp，独立验签用户令牌并按用户租户查询能力、执行策略，换取连接器 OBO 后签发 act。主体来自用户令牌；客户端传入的 act、断言与 Run 头不会直接转发。Agent/version、Run/call、approved 等请求体上下文由受信调用者提供；当前链路不因此证明其权威登记关系。act 签名绑定具体 OBO 哈希、subject、audience、Agent/客户端链及 Run/call，但不含独立租户字段、工具或参数摘要、策略版本、审批凭据。

因此，认证客户端身份、允许其代表用户、确认其有权声明特定 Run/Agent，以及授权具体操作是四个不同的判定。不得把授权回调共享 secret 或验签成功当作以上全部成立。

## 推荐契约及需人工确认项
| 编号 | 推荐方案 | 确认后才实施的变化 |
|---|---|---|
| C1 签发责任 | Capability Gateway 保持唯一 act 签发责任；Runtime 负责权威执行上下文，agentgateway 负责数据面转发，不持有私钥 | 是否批准这一职责划分，以及签发发生在何种受控接口；本轮不增加通用签名接口 |
| C2 可信调用者 | 首批仅既有 Runtime 服务身份；用户令牌或数据面共享 secret 不具备独立签发资格。若 agentgateway 需独立获取断言，使用独立、最小权限身份并另行冻结委托协议 | 正式 issuer/audience/客户端 allowlist、凭据来源、服务身份与用户代理权限 |
| C3 上下文权威 | Runtime 从持久 Run、已发布 Agent/version 和当前工具调用构造不可由浏览器覆盖的上下文；Gateway 校验用户租户、连接器和策略，再签名 | Run/call 与调用主体关联的证明方式：推荐受认证 Runtime 声明并受范围校验，是否需独立查账；审批人不能被 Run 发起人替代 |
| C4 内容绑定 | 保留具体 OBO 哈希；正式数据面若允许断言与工具请求分离传输，推荐版本化绑定 tenant、connector/tool、规范化参数摘要、Run/call 及授权证据引用 | 摘要规范、敏感数据规则、策略/审批证据语义和协议版本；不得把现有 v1 宣称为参数防替换 |
| C5 生命周期 | 策略允许后再签发，短 TTL，MCP 先验 OBO 再验 act，最后原子消费 jti；多副本使用共享防重放存储，故障关闭 | 撤权最大窗口、缓存策略、密钥轮换和共享存储责任；已消费或未知结果不自动重新签发并重发写操作 |
| C6 迁移兼容 | 保留现有 `/invoke` v1，新增数据面协议显式协商版本；缺签名/绑定失败拒绝，不降级裸头，不恢复已删除旧 MCP 代理 | 调用方清单、灰度路由、版本并存期限和安全回滚方案。写请求迁移不在本轮范围 |

推荐先确认 C1–C3，明确上下文权威；C4 的签名扩展不能仅由技术实现自行决定。可以继续纯替身测试，但不可把候选约束写成已经存在的生产保证。

## 本轮新增隔离验证
在已有真实 signer/verifier 测试上新增 4 项：
1. 使用签名测试服务和用户身份调用真实 `/invoke`，纯 HTTP 替身换取 OBO；捕获实际转发断言并交给真实 MCP 验签器。验证原始伪造用户字段、act/断言/Run 头未替代签名主体和上下文，实际转发 OBO 与断言绑定。
2. 不受信 azp：拒绝，签发器不被调用，无 OBO 换取、无连接器调用。
3. 策略拒绝：同样在签发前停止。
4. 策略不可用：同样失败关闭。

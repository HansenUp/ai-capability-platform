后续增量：用户已确认D1～D6并授权本机隔离实现，新增Owner独立摘要／Trace入口和页面已完成本机验收，详见《2026-10-25-S12Owner单Agent只读最小闭环验收》。本文件保留只读梳理当时的实现快照；旧管理员指标接口仍限管理员，正式IdP／绑定与真实来源未接入，不把测试profile视为正式权限开放。

## 结论与本轮边界

**已有 Agent 分配及管理权限基础，但尚无已开放给 Owner 的运营指标闭环。** 当前控制面／Trace／反馈运营接口和页面仍要求 Console 租户管理员及以上；反馈还独立要求 Runtime 验签用户的 `platform-admin`。不能把放开页面按钮或将接口角色改成 ADMIN 当作完成 Owner 视图。

本轮仅读取源码、测试及既有验收文档，运行不导入应用模块的 AST／文本审计并更新报告和计划。不修改业务接口、页面、角色、数据库或真实配置；不运行业务测试、访问真实服务／数据库、读取凭据、写评分／Trace、部署或启用自动跟进。北极星仍待定义，S12整体及真实身份／来源／生产验收保持未完成。

## 1. Owner已有实现与身份含义

| 事项 | 源码事实 | 当前可以认定／不能认定 |
| --- | --- | --- |
| 角色 | `console_api/auth.py`：USER＜ADMIN＜TENANT_ADMIN＜PLATFORM_ADMIN，没有独立 OWNER 枚举 | ADMIN 是“只管理分配给自己的 Agent”的现有管理角色；不能推断所有 ADMIN 自动有指标读取权 |
| 分配 | `t_console_user_agent` 唯一键为 `(tenant_id,user,agent_id)`；`assert_assigned` 核对这三项，租户管理员及以上跳过归属校验 | 可复用为候选 Agent 授权关系；不是唯一 Owner 字段，也不是组织／角色继承模型 |
| Agent列表 | `GET /agents` 的 ADMIN 分支按当前租户／user 的分配表筛选版本；管理员按本租户读取 | 说明已存在按分配限制 Agent 的管理入口，不表示运营聚合接口复用了该逻辑 |
| 分配修改 | `GET/PUT /agents/{agent_id}/admins` 要求 TENANT_ADMIN；替换用户列表、同租户查 Agent、记录 assignment 审计 | Owner不能借运营视图修改自己的分配；本轮不调用这些接口 |
| 创建者 | Agent表另有 `created_by` | 创建者不等于当前分配者；不能用创建者、Run发起人或最近评分人代替 Owner |
| 目录映射 | DirectoryUser按 `(tenant_id,issuer,subject)` 保存展示元数据；UserAgent只有user字符串 | 尚不能由显示名、目录条目或相同字符串猜出 Console user 与 Runtime `human:<sub>` 的可信绑定 |
| 当前Console身份 | `operator()`从 X-Console-* 解析，默认开发身份；前端 readSession 仅允许 development | 源码注释规划生产 APISIX 注入，不等于代码已完成真实登录／可信边界验收；开发头可编辑不能作为正式身份来源 |
| Runtime身份 | JWT签名、issuer／audience、有效期和tenant声明校验；用户主体为human前缀；反馈调用user_scope与管理员门禁 | Console `PLATFORM_ADMIN` 字符串与Runtime令牌 `platform-admin` 不是同一份权限证明；服务账号、代理身份不可替代用户证明 |

Console和Runtime分别有自己的身份／权限边界。当前反馈返回实际验签租户与主体，并核对租户与Console查询相符，但不因此建立通用的 Owner 身份映射或证明两端用户名等同。

## 2. 现有接口与页面权限矩阵

以下为**当前实现**，不是新的授权方案。

| 接口／页面 | Console准入 | 数据范围及附加门禁 | Owner现状 |
| --- | --- | --- | --- |
| `GET /agents` | ADMIN及以上 | ADMIN按UserAgent筛选；查询始终带op.tenant | 已有管理列表，不是指标API |
| `GET /metrics/operations` | TENANT_ADMIN及以上 | 当前租户控制面聚合，无单Agent参数；不调用assert_assigned | ADMIN被403拒绝；不能直接对Owner复用全租户结果 |
| `GET /metrics/traces` | TENANT_ADMIN及以上 | 同租户Agent存在检查；本机Langfuse配置、项目凭据；带时区最长7天 | ADMIN被403拒绝；无Owner分配核对，无Runtime验签令牌要求 |
| `GET /metrics/feedback` | TENANT_ADMIN及以上 | 用户Bearer转发Runtime cohort核实；验签用户platform-admin；同租户／Agent／最长7天 | 不能降低Console角色后借管理员令牌读Owner数据 |
| `GET /metrics/feedback-v2` | TENANT_ADMIN及以上 | 同上，并需Runtime dev独立只读证据开关及完整权威来源／修订核对 | Owner正向读取未实现；不启用写协议或复用发布服务身份 |
| `/manage/operations` | 路由本身不是认证边界；组件allowed仅含TENANT_ADMIN／PLATFORM_ADMIN | 控制面与Trace分开查询，切身份／时间窗清空和旧响应隔离；反馈子组件单独内存Token | 可打开路由不等于准入；改allowed不能代替后端权限检查 |

平台管理员在现有这些指标读取里仍受op.tenant筛选，不据角色名推导跨租户聚合许可。反馈Token仅发Runtime，不转发Langfuse，Langfuse使用服务端已有项目凭据；本轮未查看任何实际凭据。

## 3. 数据来源与指标契约

| 数据 | 事实源和现有处理 | 对Owner扩展的约束／缺口 |
| --- | --- | --- |
| Agent／版本数量 | Console Agent／AgentVersion，控制面状态计数 | 可讨论仅单Agent计数；不得把全租户节点、指令、审计或其他Owner数量打包返回 |
| 分配关系／人数 | Console UserAgent关系数、distinct user数 | 不是活跃员工、周活或实际使用人数；Owner能否看到其他被分配者的数量／身份需隐私确认 |
| Trace调用／Generation | Langfuse Trace列表和详情，按name拉取后核对tenant／agent元数据，分页完整性和重复ID检查 | Trace不等于Run；元数据一致只是关联校验，不是Owner授权或评分来源证明。项目级密钥不能发浏览器 |
| Token／费用 | GENERATION的单位、用量字段和成本字段；全部已知才给总量，否则未知并单列已知小计／完整覆盖数 | 来源报告USD不是财务结算，未知不补零；不能据此直接给单次业务任务成本 |
| Trace时间窗 | 源码接受带时区最长7天，当前列表逐条检查`since <= timestamp <= until` | 当前Trace读取是含尾边界；反馈是下述半开cohort，两者不能静默合并或当作同一分母 |
| 反馈分母 | Runtime权威Run创建时间`[since,until)` cohort；读取时completed的唯一Run，失败／取消／未决另列 | 原发起人用于评价资格，不是Owner身份。Owner能否看接手前历史或仅任职区间须明确 |
| 反馈v1／v2 | v1无证明历史评分只审计；v2使用Runtime权威终结／来源证明及最新修订，对照Langfuse GET；最新中性／未决不回溯 | 不完整时正式比率未知，不升级历史评分信任。Owner权限不能取代platform-admin证据GET，须单独设计受限读取契约 |
| 错误率／时延／北极星 | 现有Trace响应明确`run_metrics_available=false`；控制面声明不采集Runtime执行指标 | 当前Owner视图没有这些可信结果；不新增成功率、业务任务、活跃度或收益口径 |

Trace读取本机限制、禁止重定向、响应体上限、单页100／最多20页、并发详情与整体时限等现有边界应原样保留。只读扫描不保证并发写入快照；证据不足保持不可用，不返回可误解为完整结果的部分比率。

## 4. 后续推荐契约草案 尚未批准实施

建议采用“单Agent、当前明确分配、最小只读字段”的独立Owner入口，而非直接降低现有租户管理聚合API的最低角色。此处只记录方案，**本轮不新建路由或给任何主体增加读取权限**。

1. 先定义可信操作者：服务端验证身份来源，稳定tenant／issuer／subject绑定到Console授权关系；不可让客户端填写user、Owner名单、tenant或metadata完成授权。
2. Owner候选按现有UserAgent归属核对；单Agent请求必须既存在于同租户又明确分配给操作者。created_by、Run发起人、Directory显示名、管理员Token均不作替代。
3. 授权完成后才查询外部指标；字段白名单不含Run原发起人列表、评分正文、correction、原始Trace输入输出、项目总量、节点／全租户指令和审计统计。
4. 保留缺失／来源不完整诊断、读起止时间和非快照声明；浏览器身份／Agent／时间窗变化立即清空，旧响应和缓存不能跨主体。
5. 建议第一阶段只讨论单Agent控制面摘要与Trace用量；反馈v1／v2暂保留管理员路径。若要给Owner反馈聚合，必须另行定义Runtime只读授权，不给Owner补管理员角色、不启写协议，也不借管理员或服务身份代读。
6. 撤销时效建议采用不缓存授权、查询前及输出前复核当前分配作为候选方案；但两次读取不是跨数据库原子快照，不能保证检查后撤销的在途响应绝不送达。是否接受该边界必须确认，不在本轮自行确定。

既有分配表没有有效起止时间和分配修订字段。不能依赖当前行或审计列表无损重建历史归属；若要求“只看任职期间”或强一致撤权，需要独立设计数据模型，不能先加迁移再补批。

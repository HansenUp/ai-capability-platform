# 首批场景与最小运行依赖清单（2026-10-27）

## 1. 结论与使用方式

建议先收敛到 **工单总结／只读问答** 一条垂直链路：先用已有隔离演示确认配置、发布、对话和轨迹体验，再单独确定真实工单接口、模型和身份如何在非生产环境接入。这个排序是建议，不代表用户已选择上线业务或授权真实接入。其他场景仍保留计划，不删除代码。

本文区分三个范围：**A 隔离体验**（临时库、模拟模型／工具／测试身份）；**B 真实能力的非生产单场景候选**（真实工单／模型／IdP 接入需要分别获批，尚未实施）；**C 当前生产安全门禁**（按现有代码与计划列条件，不代表已部署或验收）。同一组件在不同范围可有不同类别；“可暂缓”不等于可以从现行生产基线移除。本文是源码和已有证据分析，没有启动或关闭组件、操作数据库或验证真实服务。

## 2. 首批场景核对

| 场景 | 计划定位与现状 | 主要依赖／门禁 | 建议 |
|---|---|---|---|

## 3. 最小运行形态

### A. 已有证据的隔离体验

运行轮廓：`Console Web + Console API + 单 Runtime（API／进程内队列）+ 临时 SQLite + 测试身份／模型／工具替身`。身份、策略和 Langfuse 等采用隔离替身或空配置；前端的 SDK 是代码包，不是独立服务器。用于展示显式配置／发布、创建同 Run、审批、输入与轨迹；不是自然语言模型效果或生产权限验证。

依据《2026-10-26-独立本机演示执行报告》：临时 Runtime／Console、签名测试身份、mock Harness 与工具、进程内队列；该轮实际浏览器主链路 2/2。后续 S12 第一批报告的整合演示 3/3 与最终同版本回归另行记载，不能混加计数。原演示地址已按当时期限停止，本文不承诺现有地址在线。演示使用开发身份及测试旗标，**只允许合成数据／替身**，不能迁移为真实用户、业务数据或生产部署。

### B. 非生产真实能力单场景候选

建议最小链路：`入口页面 → Runtime → 能力网关 → 工单只读 MCP／业务接口`；`Runtime → 模型网关／受控模型`，网关接策略与 IdP。可按需求保留 Console 配置和发布；数据持久化使用专用隔离数据库，审计及访问边界必须存在。具体保留哪些进程、运行拓扑和单节点失效语义须以真实运行配置和新增验证确定，不把示意图当启动承诺。

该候选未验证：真实模型／业务／身份需要凭据、接口负责人和授权；若希望“可恢复的真实 Run”，队列、凭据、租约与备份必须按实际设计验收；不可因运行节点为单个就默认移除 Redis 或绕过主体写锁。

### C. 当前生产模式

仓库当前的生产自检要求：Runtime 强制验签、生产凭据和非 SQLite 数据库、经能力网关分发，并要求 Redis；Gateway 要求受控身份、生产目录 MySQL、服务间密钥及 `SKILL_STORE=s3`；生产 Policy 拒绝 baseline，需 Cedar 与服务间鉴权；生产 Console 要求 Langfuse 评测闸门及节点鉴权。除自检外，S9 外部安全、网络边界、签署、真实业务与 D47／S10.7 等仍待验收。

因此当前代码中 **S3 存储、Redis、Langfuse 不能简单当作生产可删项**；它们也许是可重新评估的架构取舍，但修改现行生产约束、评测来源或分布式语义必须另行设计、审批和验证。生产模式不接受隔离演示的 mock、开发身份或临时 SQLite 作为替代。

## 4. 逐项依赖与影响矩阵

“启动必需”均指**明确列出的 A 体验闭环**，不是笼统表示各服务不能在别的模式启动；“生产门禁”包含现有强制约束与独立验收要求。

| 组件 | A 隔离体验启动必需 | B 工单真实只读的业务依赖／待核验 | C 生产门禁 | 简化影响或暂缓条件 |
|---|---|---|---|---|
| Console Web、Console API | 需要，用于配置／发布演示 | 管理发布需要；固定已发布 Agent 的纯使用路径是否可不启动 Console，需验证 | 现有生产发布／权限与评测链待验收 | 可以把“使用”与“管理”运行模式分开，不删 Console |
| Portal Web／Web SDK | A 已有 Console Chat，Portal 非必需；SDK 被页面依赖 | 需要面向用户的入口；Portal 或嵌入宿主择一 | 登录、可见性、租户与浏览器安全需要验收 | 暂不要求同时建设所有入口；不改变授权 |
| Runtime API／单进程队列 | 需要 | 需要执行 Run；真实恢复语义待确认 | 生产模式要求 Redis 且持久状态、安全配置 | 体验可以使用进程内队列；失进程后不具 Redis 消费组／接管语义 |
| SQLite | 需要临时库；隔离演示按 ORM 建表 | 真实试点能否使用须另评审，不能访问原库 | Runtime 生产自检禁止 SQLite，要求受控数据库配置 | 只适合隔离演示，不作为正式持久性、迁移或容灾证据 |
| MySQL | A 不需要 | 非生产持久场景推荐独立授权库，绝不复用原库；实际选型待确认 | Runtime 禁 SQLite；Gateway 生产目录要求 MySQL | 合理共享实例可减少运维但增加故障耦合、备份范围与权限隔离要求 |
| Redis | A 不需要，采用进程内队列 | 是否要求可靠排队、持久执行及节点接管决定；按实际角色验证 | Runtime 当前生产模式强制 Redis | 仅隔离单进程演示可暂缓；不是可靠队列等价替代 |
| Keycloak／可信 IdP | A 用签名测试身份替身 | 真人用户及 OBO 必须有受控身份来源；具体 IdP 可待选 | 生产验签、服务身份、委托和正式 IdP 配置需要验收 | 可以不在演示启动真实 IdP；不能用开发头代替真实验签 |
| Capability Gateway、Policy／Cedar | A 以测试替身隔离，非真实网关必需 | 真实工具路径按当前设计必须网关与策略，身份与目录需要核对 | Runtime 生产必须 gateway；生产 Policy 禁止 baseline | 不建议为减进程直接绕过；可研究合并部署但须保留故障关闭、认证和审计 |
| 工单 MCP／业务接口 | A 纯替身 | 真实工单总结所需只读接口；数据范围和责任人待确认 | OBO／最小权限、审计、业务验收；写操作另需审批／幂等 | 固定只读工具范围，不提前开启工单写动作 |
| 模型网关／模型 | A 用 mock Harness | 真实模型效果必须受控模型与授权，当前设计用 LiteLLM 路由 | 模型出口、数据分级、密钥、成本与服务可靠性须验收 | 本机体验可不连真实模型；无法评价自然语言质量、成本或延迟 |
| LiteLLM 自用 PostgreSQL | A 不需要 | 当前 Compose 的 LiteLLM 配置可能依赖；实际选型及配置需验证 | 取决于实际部署配置，不可假定能删除或合并 | 若研究替代配置，先评估预算、密钥、日志功能及迁移 |
| Langfuse / Observe / OTel | A 不需要真实服务；事件轨迹来自临时 Runtime | 若进行真实评测／Trace，需可信观测链；纯功能体验可暂缓 | 当前生产 Console 强制 Langfuse 评测闸门；审计与观测出口待验收 | 暂缓仅限 mock 体验；无真实评测、Trace、成本或反馈可信结论 |
| Langfuse 的 PostgreSQL／ClickHouse／MinIO、初始化 | A 不需要 | 随真实 Langfuse 选用及配置而定 | 采用当前 Langfuse 部署时按其依赖验收 | 这些是观测栈组成部分，不是每个场景单独业务需求；不可直接删除仍声称 Langfuse 全功能 |
| Elasticsearch／FastEmbed | A 不需要 | 固定已知工单工具可先评估不依赖语义搜索；网关在未设置 ES_URL 时有进程内检索代码路径 | 若业务或安全设计依赖检索，需验证正确性、权限与性能；不得当作生产豁免 | 暂缓混合检索／向量模型可能降低发现效果和规模；单机场景是否能替代须定向测试 |
| MinIO／S3 | A 不需要 | 无 Skill 包／对象下载的只读场景可先梳理需求；具体服务启动约束需验证 | 当前 Gateway 生产要求 `SKILL_STORE=s3`，不因“不用 Skill”自动移除 | 演示可暂缓；生产若想减少需独立评审配置与签名存储要求 |
| Vault／KMS | A 使用测试凭据，不接真实密钥服务 | 真实凭据必须来自受控来源；是否 Vault 待确认 | 密钥注入、轮换和权限必须验收；现有 Runtime 支持 Vault 或文件注入条件 | 可以评估受控文件／企业 KMS，但不把开发明文／默认值当替代 |
| APISIX／多节点管理 | A 不需要 | 单节点场景可先评估直连；不提供节点组路由与多节点故障转移 | 若需节点组或灰度／既有 Run 路由，必须保留经验证的路由契约 | 暂缓多节点拓扑不删除插件；影响扩容、不中断迁移及高可用 |
| Data Hub／etcd／见证 | A 不需要 | 普通工单摘要如不查询经营分析数据，可暂缓；业务范围须确认 | 真实经营数据接入前需可信身份、行列权限与防回滚设计／验收 | 暂缓仅是不开通相关数据能力；不把实验模型或 3.5 单节点当正式权威 |
| gVisor／Helm／Argo CD | A 不需要 | 只读固定工具可先限定不执行任意脚本；如执行脚本需相应隔离方案 | 按实际部署架构及安全方案验收；D47／S10.7 延期 | 暂缓集群与高级沙箱不等于在生产用不安全方式执行脚本 |

## 5. 建议实施顺序与影响

1. **冻结首批演示范围**：以工单总结只读为候选，列出用户、输入、输出、允许工具和成功标准；业务负责人确认真实售后只读与摘要是否构成同一场景。既有审批／输入演示仍可保留为功能展示，但不暗示首批业务必须启用写操作。
2. **先固化 A 配置矩阵**：列明入口、临时库、测试身份、模型／工具替身和停机清理；复用现有演示和证据，必要时在单次授权中做同版本隔离验证。输出“运行前置、实际启动项、不可体验项、停止与清理”，避免因按计划启动整个 Compose core 而引入不必要依赖。现有 Compose core 默认并非最小依赖。
3. **为 B 做依赖验证而非直接上线**：逐一核实单 Runtime／固定 Agent 是否可在现有代码配置中只用已批准的非生产组件；单测与替身之外另评估真实 IdP、真实模型和工单接口接入授权。真实非生产接入的凭据、网络和数据范围必须单独批准。
4. **安全门禁不削减**：真实数据接入时保留身份验签、租户／行列授权、业务系统最小权限、审计、数据分级与安全出口；如有写入，保留审批、幂等、未知结果对账与本人收口。不是所有门禁都必须对应新的独立进程，可在架构评审中研究合并部署，但必须证明隔离、失效和可审计性。
5. **暂缓而非删除**：在业务范围不需要时暂停深化经营分析 Data Hub 权威／见证、生产多节点扩展、自动化运维及额外接口；恢复工作时重新核对依赖与验收。S14 既有恢复失败证据保留，不标通过。

## 6. 尚需用户／业务方确认

- 是否将**工单总结只读**作为首批优先场景；具体用户、工单范围和输出用途。
- 下一阶段是仅做本机模拟体验，还是准备非生产真实 IdP／模型／工单接口的独立接入方案；后者需业务与凭据授权。
- 工单范围是否包含真实写操作、需要的恢复／可用性目标及评测阈值。
- 生产时需要的部署职责、数据分级、保留期限、成本与审计要求；不以当前简化建议替代安全签署。

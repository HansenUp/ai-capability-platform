## 实现约定

- Skill 源包由网关扫描，Console 编排评测；提交人与审批人分离，审批经 Cedar。网关签发 ES256 清单，Runtime 钉信任公钥及发布快照中的 `skills_lock`，加载前核验文件哈希。
- 已签名固定脚本在 L1 沙箱执行，模型不能生成或修改脚本，权限只取签名清单。首轮评审曾临时关闭写沙箱；本轮已接入高风险审批、写前登记及对账闭环，详见后续“写脚本闭环补齐”。生产三级隔离仍须部署验收。
- Runtime 出站统一经 `runtime.net.client`，按 scheme、host、port 匹配，逐次检查重定向目标。集群网络策略与部署验收仍按 D47 延后。
- 节点通过服务令牌注册、心跳、拉取指令并回执；关闭 Runtime 管理路由不等同于关闭对话 API 的入站服务。
- 同批只读调用并发，写调用按序审批执行；写结果未知时转人工对账，旧租约持有者隔离。上下文压缩落事件，恢复后重建模型请求哈希。
- 数据矩阵控制模型、嵌入、重排、观测、回退与记忆六通道。尚无重排及跨会话记忆执行链，现阶段以契约和架构测试守卫；开发矩阵不视为合规签署。

## 写脚本闭环补齐

本轮明确请求范围为签名写脚本的持久化审批、写前登记与故障恢复对账。实现复用现有 Run 事件、`t_tool_operation`、审批及 reconcile API，不新增一套状态机或数据库迁移。

- `skills/execution.py` 每次重新核验信任公钥、签名及文件哈希，冻结 `effective_input.__skill_execution`：包／脚本哈希、Run／工作区、数据等级、镜像、沙箱配置 HMAC、执行用户和 Docker 引擎。stdin 与冻结范围一起参与审批指纹；配置、内容或信任变化时失败关闭。
- 两种写级别统一强制 `write_high`，网关发布风险也提升到高风险，禁止自报 read 降低 L2 发布要求。pre_tool 对脚本按高风险保守评估，之后按签名实际权限判定。影响预览是声明式范围，绝不提前运行任意固定脚本，也不声称预测文件差异。
- 复用工具闸口的策略、审批有效期与审计；执行前在同一事务提交操作登记及 `TOOL_EXECUTING`。写脚本使用规范化参数指纹生成稳定操作标识，不依赖嵌套 JSON 的字典顺序。
- 容器附带操作标记，脚本启动前再次核对持久审批、操作状态和租约纪元。过期、失租或被结算的调用不得迟启动，注入后校验失败仍清理容器。
- 异常、非零退出、超时和崩溃都可能留下部分副作用，结果未知必须人工对账，不自动重做；脚本没有下游幂等承诺，显式禁止 retry。done／skip 先检查原引擎与配置并清理该操作的容器，清理失败则保持 input-required。skip 不代表补偿或撤销写入。
- 对账结果保留原数据等级与签名执行绑定，成功执行仍走 post_tool、结果外置及日志重建；已完成的操作不重复执行。
- 写脚本的晚到结果仅允许更新 executing／unknown 登记行，原子条件更新保护已执行／已跳过终态；旧 Worker 不能在人工结算后将登记降回 unknown，也不能用晚到结果替换对账指纹。

部署约束：接管节点必须访问同一持久工作区路径和同一 Docker 引擎，且使用相同签名信任、沙箱配置与执行用户；不支持向另一独立 Docker 引擎透明重做未知写操作。写容器使用 Runtime 的非 root UID/GID；Runtime 为 root 时使用 65534，需预先配置可写工作区。read-only 仍使用 65534，不挂工作区。本轮没有放宽宿主目录权限。

验证入口：`SKILL_STORE=fs .venv/bin/python scripts/verify_s9_e2e.py --subset script-writes`，已纳入完整／nightly 的第 ⑭ 项。真实容器先写入计数文件，再在尚未返回结果时 `kill -9` 持租约 Worker；另一 Worker 约 15 秒接管，进入 input-required，拒绝 retry，对账后完成且计数仍为 1，原操作容器无残留，登记状态为 executed，故障 Worker 可恢复。

`test_s9_script_writes.py` 覆盖写前事务可见、两种写级别、审批参数与过期、配置漂移、信任钥轮换、部分写入／非零／超时、取消后接管、done／skip、清理失败不结算、原引擎与操作标记隔离，以及容器启动前失租清理。独立只读复核未发现具体可复现问题。

真实故障演练只覆盖本机共享引擎的 workspace-write；full-access 的持久审批与失败关闭经定向回归验证，真实出站代理和生产网络隔离仍待部署验收。

## 加密路径建议：先明确已有来源，不自行补建

1. **优先**：用户指定已使用的备份加密工具、已有恢复身份及安全引用（例如明确的密码管理器条目、备份专用身份文件或受控设备）。只提供路径／条目引用及允许的访问方式，不在聊天发送内容。先获准核对解密可用性，再做真实备份。
2. 如果组织已有 age 备份身份，可考虑其接收者公钥加密、对应已有身份恢复的流程；本机尚未在 PATH 找到 age，安装／提供工具位置须另行确认，不运行 keygen、不复用未知用途 SSH／签名身份。官方用法支持分别指定 recipients 和 identity，不能把公钥存在当作私钥可恢复。[age 官方用法](https://github.com/FiloSottile/age#usage)
3. 不以“已有 openssl”直接选择未经验证的 enc 管道。OpenSSL 官方文档指出 enc 不提供 CCM／GCM 认证加密模式，并说明流式处理认证失败的风险；这不是对本机 LibreSSL 全部能力的替代验证。本轮不拼装 CBC＋摘要或自行设计 nonce／文件格式来绕过门禁。[OpenSSL enc 官方说明](https://docs.openssl.org/3.0/man1/openssl-enc/#supported-ciphers)
4. hdiutil 创建加密映像、安装新工具、创建新长期密钥或复用登录身份均不是本轮已执行的替代方案；如需要，单独确认相应安全与资源边界。FileVault 即使可用，也不能替代备份自身的密钥分离、恢复验证和授权。

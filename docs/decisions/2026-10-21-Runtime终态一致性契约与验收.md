# Runtime 终态一致性契约与验收

## 契约（实现前明确）

- 终态为 completed / failed / canceled；终态状态、对应状态事件、租约 owner/expires 清空和凭据删除必须在同一个数据库事务提交。任一步失败则整体回滚，读者不能看到终态仍持有租约或凭据的窗口。
- lease_epoch 不因终态递增：保留既有取消边界收尾（例如 RUN_DONE）语义；终态不等于 harness 物理退出或队列已 ACK。不可恢复为可执行状态，不允许重新抢租约；旧纪元仍由原 CAS fence 拒绝。
- 终态提交后的 finally 释放属于幂等确认，仅接受相同 epoch 且 owner/expires 都为空的终态；非终态仍严格匹配 owner/epoch，绝不释放接管者租约。
- 心跳续期不能重新填入已清空的终态租约。续期拒绝后，仅相同 epoch、已清空租约的终态属于正常收尾；canceled 仍触发本纪元 harness 中断，其他拒绝仍自我隔离、不 ACK。
- auth-required / input-required 是非终态：保留凭据，退出持租上下文后释放，防丢唤醒与重投机制保持不变。
- 不改变既有测试断言、超时阈值、发布阈值；以事务回滚、终态已提交但驱动尚未退出的事件屏障，以及原接管/取消回归验证，不用重试通过替代修复。

## 根因与实现

原 `EventLog.transition` 只提交状态与事件，凭据由 runner 尾部尽力删除，租约由外层 `hold` 退出时另开事务释放。API／SSE 尾随者可以在这两个清理步骤之前读到 completed；上一轮原断言失败即落在该窗口。隔离重跑通过不消除这个调度窗口。

本轮在状态 CAS 中同时清空 owner/expires，并在同事务删除 RunCredential；同步 ORM identity map，避免缓存对象再写回旧租约。finally 释放加入相同纪元的终态幂等确认，防止成功完成被当成失租而不 ACK。续期拒绝后只认可相同纪元、已清空租约的终态；canceled 仍按 epoch 中断本地会话，其他情况仍隔离。终态确认查询失败同样保守隔离，不静默失去心跳保护。

保持 lease_epoch 不变是沿用已有终态后的取消边界事件语义，不是取消 fencing；接管仍递增 epoch，旧持有者不能写入或释放新持有者租约。节点优雅重启仍等待 HTTP 和 Worker idle，不以数据库租约为空冒充物理排空。

# S12.1 可信反馈后端最小闭环验收

日期：2026-10-22。用户已明确批准 Runtime 回执＋最小 outbox、本机临时库迁移、completed 原发起人 -1/0/+1、中性不撤回、不收评论／修正、未知结果冻结主体新写、严格读回后本人 ACK；独立认证仅使用临时测试身份／凭据和替身。未启用自动跟进、真实服务身份或密钥、真实 Langfuse 写、自动发送／重投、TTL 解锁、留存清理或生产部署。

## 实现与安全契约

- 迁移 0011 新增 `t_feedback_outbox`，ORM 与迁移一致；存最小不可变交付载荷、数值、身份／完成事件／Agent 版本／修订、摘要及观测摘要，不存自由文本或用户令牌。补充 ADR-0002 的协议证据边界，不另建独立满意度事实源。
- 新增 `/v1/workbench/feedback-attempts` 及按 ID 的 GET、execute、reconcile、acknowledge。仅验签用户 JWT，原发起人、当前租户、completed 且有固定 Trace／唯一完成事件可 prepare；不同主体／租户不能恢复或执行。dev 显式 opt-in，默认关闭、prod 禁止。
- prepare 与既有主体活动锁、attempt 和 outbox 同事务；同 UUID 同绑定返回原记录，同键异体／旧 expected_revision 拒绝。逻辑 Run 修订单调增加、数据库唯一约束；每修订固定新 score ID 和时间，不覆盖旧修订。
- execute 在任何 HTTP 前提交 PENDING_OBSERVATION。一次显式执行最多调用 Observe POST 一次；再次 execute 不会发送。进程在标记后、发送前崩溃也保持未知，不猜测未发送，不自动恢复投递。
- 独立 `/internal/local-feedback` 通道使用专用 opaque Bearer 测试凭据、常量时间校验；不复用用户 JWT／发布账号。Observe→Langfuse 仅 Basic 项目凭据；两跳均限定 loopback、禁代理／重定向、超时与有界读回。旧 `/feedback` 不变，未默认启用任何真实认证配置。
- reconcile 仅发 GET score／Trace，随后记录本地观测证据；不发评分 POST。严格匹配规范化完整内容摘要、类型、主体／租户／Agent／Run／版本／完成序号／revision／attempt／scope／固定 ID／时间，同时核对 Trace 属性和 Run Session。缺失、冲突、404、失败／丢响应均保持锁，不以成功 POST 响应、Run 终态或空列表解锁。
- OBSERVED 仍不解除活动锁。原操作者以精确 fingerprint／revision 显式 ACK，核对 outbox 完整性和观测摘要后才原子清指针并审计；不重做评分写。未发送 PREPARED 也不能靠客户端取消／TTL 自动清锁。

覆盖登记无发送、同键异体、并发 execute 仅一次、旧版本、同主体全部写冻结、跨主体／租户隔离、原操作者收口、POST 写后丢响应、GET 缺失保持锁、Trace 冲突、伪造布尔数值／身份／版本／作用域／事件证据、拒收自由文本、原子插入前故障回滚及腐败观测回执拒绝 ACK；迁移校验重复升级、降级和 ORM 对齐。

保留初始失败：夹具误用 subject 前缀造成 403，禁用协议测试未带身份先得 401，测试尝试改 frozen Settings；分别改为现有签发主体格式、携带合法身份测试禁用门禁和替换不可变配置对象。类型检查修正 Any 返回值为明确 bool；格式问题按现有 Ruff 修正。未增加重试／超时、放宽断言或新增跳过。失败日志与最终结果分别归档。

首轮全仓为 3 failed／1466 passed／38 skipped／2 warnings／1 error。两处旧迁移 head 断言严格更新 0010→0011；新 Runtime 请求改走既有 `runtime.net.client`，没有豁免出站架构扫描，测试仅临时增加指定 loopback origin 白名单。创建清理再现 CAS 的进一步原因是嵌套 TestClient lifespan 会覆盖共享 `app.state.node_lifecycle`，清理可能暂停的是已关闭的另一个 Worker，而不是会话客户端仍在写的 Worker。会话 client 现在保存启动时自有 Worker 引用，创建清理只暂停／等待该实例；新增嵌套 lifespan 用例验证实例区分并恢复共享状态，不改业务 CAS 或重试。前轮 1449 passed 是历史实测，不代表该生命周期风险当时已完全排除。

## 明确未完成与下一步

本轮是后端最小协议闭环，不是 S12.1 全部完成：SDK／Console 的 feedback 动作识别、显式 prepare／execute／只读恢复／ACK 页面与新协议实际浏览器故障矩阵尚未实现；既有五动作界面不自动代执行未知 feedback。Console 现有审计仍为 strict_readonly_unverified，不将真实路径 trusted 改为 True，不把新测试回执冒充真实满意度。

下一步先接 SDK 与 Console 的反馈回执识别及跨页未知锁，再推进显式交互和真实本机浏览器；仍用替身，不接真实写。真实 Langfuse v3 profile 的 ID／时间与响应格式兼容、服务认证实际身份／密钥、故障重投与留存裁决仍待后续授权。北极星及生产／外部验收仍待办。

参考官方兼容说明：本轮保持仓库 v3 profile 的 Scores v2／Trace 读取接口，不升级 SDK；v4 已移除这些旧 GET，不将当前官方文档等同本机兼容验收。[版本兼容说明](https://langfuse.com/docs/compatibility)

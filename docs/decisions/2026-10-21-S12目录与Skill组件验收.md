# S12.4 Directory／Skills 组件验收

## 范围与边界

仅执行本轮本机开发、隔离自动测试与报告更新，不启用自动跟进、不部署生产、不执行真实业务写操作或真实账号变更。不提交／建分支／推送／合并，保留现有未提交变更。本轮没有新增必须人工确认却绕过确认实施的事项。

新增 Directory 5 项、Skills 6 项真实 Vue 挂载组件测试。复用既有 management HTML、Playwright、已安装 Chrome、临时 Vite／Console／Runtime 和合成工具 E2E；不安装依赖、不下载浏览器、不新增付费或持久服务。新测试全部 Console 请求由接口替身截获，未配置请求返回 404；测试原生 confirm／prompt 也只提交至替身，不接触真实 IdP、账号、角色、网关签名／吊销服务、节点或业务工具。

## 沿用的权限与一致性契约

- Directory 仅管理当前 Console 租户展示元数据与 IdP issuer／subject 映射；创建映射不是创建账号，编辑不得修改身份，删除不是撤权或终止 Run。写入只构造原 API 的元数据字段，不携带角色／账号生命周期字段。
- Directory 管理沿用 TENANT_ADMIN／PLATFORM_ADMIN；读写错误由服务端最终判定，不把前端开发身份当生产鉴权。读取响应须为当前租户、`display_metadata_only` 范围；卸载使读取纪元失效，迟到正文不得继续触发查询。
- Skills 审批接口的 Console 入口允许 USER，实际 skill-reviewer 权限和禁自批由用户令牌与网关 Cedar 判定；不能据开发态角色自行推断审批资格。本轮明确测试 USER 携带合成令牌后被网关替身 403 拒绝，而不是错误地把审批按钮限制为租户管理员。
- Skills 吊销另需 TENANT_ADMIN／PLATFORM_ADMIN，与既有 Console API 要求一致；审批／吊销均需用户令牌，吊销原因非空且至多 500 字符。前端守卫不代替网关最终校验，不改变服务端角色、签名或撤销语义。
- 操作者改变清空旧列表、详情、名称／版本定位草稿和 reviewer 令牌，再按新身份读取；状态筛选可保留，但旧筛选请求不得覆盖新结果。令牌本身改变使旧查询失效，要求显式刷新，不逐字自动向服务器发送令牌。
- 审批／吊销确认之后，身份、令牌、筛选、查询和重复提交在本次写请求及刷新期间禁用；取消确认／prompt 不发写请求。写结果错误或未知不自动重试，不宣称网络中断能撤销服务端已接收的操作。
- 仅开发操作者展示元数据允许复用既有 `console.operator` 存储；reviewer 令牌只在内存，不写浏览器存储。切身份及卸载后清空 reviewer 令牌。

权限规则来自现有 `console_api.directory`、Skills 代理接口与网关边界，未新增业务权限或账号联动规则。

## 新增自动化覆盖

| 范围 | 检查点 |
|---|---|
| Directory 元数据表单 | 租户 PUT、用户映射 POST、展示信息 PUT 的精确路径／body；issuer／subject 编辑时禁用；更新只含展示字段，清空编辑不写入 |
| Directory 删除 | 展示映射删除二次确认；取消无请求；确认仅 DELETE 当前映射，204 后刷新，不调用账号、分配或 Runtime 接口 |
| Directory 权限与错误 | 403 不显示原始正文并清空旧数据；切换身份清空编辑及待删除确认；USER 写控件禁用，新请求使用新租户头 |
| Directory 范围与分页 | after_id 精确取服务端游标、正常追加；跨租户用户页失败关闭，清空旧目录并显示范围错误 |
| Directory 迟到正文 | 忙时锁身份；卸载并重新挂载后释放旧正文，不再由旧实例请求用户列表；既有和新实例仅各读一次用户页 |
| Skills 查询详情 | 状态过滤、名称／版本 URL 编码、扫描发现项兼容字段、评测引用与缺失通过率展示；无写请求 |
| Skills 审批取消／拒绝 | 无令牌禁用、原生确认取消不写；USER＋合成令牌的最终 403 拒绝，清空旧审核视图且不展示私有正文；POST 仅原版本路径与空对象 |
| Skills 审批成功与忙态 | 原生确认后只发送一次 POST；等待响应时锁身份、令牌及提交按钮；成功再 GET 同版本刷新，不凭本地猜测上架 |
| Skills 吊销 | prompt 取消不写，空白原因本地拒绝，合法原因仅进入 `{reason}`；刷新展示 revoked；USER 即便有令牌也不能吊销 |
| Skills 身份隔离 | 切操作者清空 reviewer 令牌／详情／定位草稿；新租户 GET 不携带上一身份的 reviewer 令牌 |
| Skills 旧响应与错误 | 故意忽略 abort、延迟旧正文，新筛选先完成后释放旧正文，旧行不回流；HTTP 503 不回显正文，网络错误受控展示，无未处理 pageerror |

`directory-skills-fixture.mjs` 为每项创建独立 Context，以 Promise barrier 控制 text／JSON body 到达顺序；复用已有的显式释放与下一绘制帧屏障，不靠任意延时猜测完成。同步记录组件发起的请求路径，避免路由回调尚未触发就提前通过。实际请求体只存于测试内存；日志中的 reviewer 值仅为明确的合成字符串，非真实凭据。

## 红绿证据与产品最小修复

修复前完整浏览器套件 30/38 通过、8 项失败，均属于新增用例；`red.log` 保存原始结果，没有降低断言或超时以绕过：

- Directory 直接回显错误正文；未拒绝跨租户用户页；卸载后旧租户正文继续请求用户页，计数为 3 而期望 2。补充安全状态码提示、401／403／404 清空目录、租户／scope 校验和卸载纪元失效，复用已有 perform 的代际检查。
- Skills 无令牌和写入忙态的按钮未禁用、空白吊销原因仍发送请求；身份变化保留旧 reviewer 令牌；旧筛选响应能覆盖新筛选。补充与后端一致的令牌／吊销角色守卫、原生确认后的串行写与控件禁用、明确原因校验、读取代际检查和身份／令牌变更清理。
- Skills HTTP／网络失败改为受控消息，不展示服务端原始正文或产生未处理 Promise rejection；权限拒绝清空审核列表。刷新失败保留实际错误，不用旧成功提示覆盖；请求禁跟随重定向、禁缓存，不自动重试。
- 同时将已触达的 Skills 表格补齐 thead／tbody，避免本机 Vue 编译时出现 table 直接包含 tr 的结构警告。未改扫描、评测、上架或吊销状态机。

仅修改两个前端页面与测试编排，没有后端接口、数据库结构、真实权限或账号配置变更；既有 E2E 仅写临时 SQLite 测试数据。定位上限仍 5 秒、单项测试仍 30 秒；原有 Runtime／stdio 测试阈值不变。

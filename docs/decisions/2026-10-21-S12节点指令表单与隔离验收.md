## 复用的安全契约

依据 `2026-10-18-S10节点控制安全契约.md`，没有修改 Runtime 执行器、Console 指令权限或发布策略：

- `reload_config` 仅生成 NodeAgent 轮询 1～3600 秒／超时 0.1～120 秒字段，至少一项；不生成 URL、密钥、鉴权或 Runtime 安全配置。
- `reload_skills` 为结构化名称／版本／64 位十六进制清单哈希，拒绝空列表、重复 Skill 和路径输入；不接受远程 URL／脚本。不代替节点的签名、哈希与原子物化验证。
- `switch_model` 必填 agent_id、base_version、expected_version、target_version、model_alias。页面明确同租户已发布全量目标、非模型配置一致、CAS、仅新未固定版本 Run；实际规则仍由 S10 节点执行器复核，不宣称客户端已验证发布快照。
- `graceful_restart` 仅生成 timeout_s 0.1～300 秒；表单、Console 权限和原 Runtime 契约均保留 PLATFORM_ADMIN 门禁，不接受 PID／shell／强杀参数。ok 不等于新 PID／boot_id／ready 已确认。
- 操作者租户与角色只作为既有 Console 开发身份头；请求 args 不含伪造租户／授权角色。Console 继续产生不可变指令 ID 并持久化真实授权上下文。

## 页面与下发语义

- 在既有 `/manage/nodes` 补表单，只选择已读取的注册节点，固定四类指令，无任意 JSON／shell 入口。离线／排空提示不隐瞒异步执行和延迟风险。
- 先校验预览，显示操作者／角色、租户、节点、完整类型与参数，再显式「确认下发一次」。参数或身份变化撤销预览；发送前重新比对当前上下文，防止旧确认继续生效；发送期间锁定指令编辑和身份切换，防双击。
- 一次 POST，拒绝跟随重定向，无自动重试。仅 202＋合法 ID 记作已入队，复制同一 ID 至已有只读回执查询并读取一次；后续由用户手动刷新，不重复下发。
- HTTP 400／401／403／404／409／422 作为明确拒绝，不伪装已入队。网络失败、5xx、非约定状态及 202 内容损坏均标记结果未知并锁定本页再次下发；提示先核对原租户／节点的 `node.command` 审计，再按 ID 查回执，不通过刷新盲目重发。当前服务没有 POST 幂等键或按客户端请求 ID 查找能力，因此不虚构自动恢复保证。
- 新请求在生产构建失败关闭；仅开发身份头、不保存或使用节点服务凭据。错误不回显服务器敏感正文。原有分组、路由与回执接口继续复用，不扩改既有通用 CommandIn 或未知指令兼容语义。

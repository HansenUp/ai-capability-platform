## 核对的 Runtime 原有契约

- `GET /v1/runs/{run_id}/stream?since_seq=N`：补发严格大于 N 的事件日志，并跟随后续提交；每条 `event=type`、`id=seq`、`data=RunEvent`。本轮使用查询游标，不同时发送 Last-Event-ID。
- 读取权限复用 `run_reader`：发起人／已记录审批人／管理员完整视图；尚未审批的有资格审批者是受限审批视图，序号可能合法缺号。客户端不要求连续编号，也不扩大受限视图。
- `done` 是无日志 seq 的统一结束信封，不是 RunEvent；Run 终态或者受限审批视图失效均可能结束，`awaiting` 不能解释为 Run 已完成。完整视图挂起等待审批／输入时可保持连接，不自动执行任何动作。
- 服务端在同一事务读取状态与对应事件；客户端不重新计算 Runtime 状态或从事件推断审批权限。UI 流结束后提示手动读取当前状态／卡片。
- 未修改 Runtime、租约、事件日志、审批／输入／resume 契约，也未扩展现有连接期间服务端鉴权重验语义。身份更新由客户端立即终止原连接，再显式请求服务端重新验权；无后台刷新令牌。

## 实现与安全契约

### SDK

`RuntimeRunClient.follow(runId, sinceSeq = 0, signal?)` 是只读异步事件迭代器，仅发一个带当前身份头的 GET。使用 fetch 而不是无法自定义 Authorization 头的原生 EventSource；令牌不放 URL，禁止重定向、禁用缓存，不使用 Console 服务账号。不自动重连，不读取 SSE retry 指令来安排重试。

解析兼容 UTF-8 跨字节分块、LF／CRLF／CR 分行、注释心跳及多行 data。每个日志帧校验 Run ID、正安全整数 seq、严格递增、SSE id 与 seq 一致、event 与 JSON type 一致、非 null 非数组对象 payload。允许合法序号缺口，重复／乱序／跨 Run／坏 JSON 失败关闭，不跳过坏数据伪造完整历史。done 单独校验 Run ID、type 与已有停止原因枚举，不作为持久化事件或新的游标。

单帧缓冲上限为 1,048,576 字符，超限停止并报错，不截断展示或静默丢弃；不是修改测试超时或业务阈值。未收到合法 done 的 EOF、读取故障、无效帧及非 SSE 响应均停止，并明确要求手动续读。HTTP 401／403／404／5xx 不回显正文、不视作未知写结果、不重试。

身份头等待前后、收到响应后、每次 read 前后及 yield 后检查 AbortSignal。即使传输忽略 abort、响应头迟到，旧响应 body 也被释放，不继续交付事件；已取得 reader 时，abort 主动取消挂起 read，退出／消费者提前结束均释放 reader。取消仅影响 GET，不调用 Run cancel／resume。

### 使用工作台

新增“跟随／续读已持久化事件”，用户显式启动，游标只来自已完整验证且交付给当前页面的日志 seq。断连保留当前身份、同 Run 已确认的内存列表与游标，用户可手动续读；不持久化游标／令牌／消息，不自动重连。

列表展示 seq、事件类型和完整已持久化 model.response 文本，不渲染 Token 增量或内部思维内容，也不由流生成可写审批卡片。启动跟随清除旧状态／确认／卡片；如需操作卡片，先停止或等本次流结束，再手动读取权威状态。

跟随期间可应用新身份：先 abort 原 GET、推进 generation，再清空旧 Run、列表、游标与凭据。新身份必须重新定位 Run，从 0 请求其获授权视图；旧响应迟到不能追加事件、覆盖提示、推进新游标或继续请求。只编辑身份草稿并不更改已应用身份。

停止读取保留已确认的同身份／同 Run 跟随记录，明确“不取消 Run”；切换 Run 清空记录，卸载推进代次并 abort／清理。未知写结果锁始终保留，任何跟随、停止、断连、done 或切换身份都不解除它。既有写请求不因本功能被重发。

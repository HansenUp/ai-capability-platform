# S14.1 清单与策略版本账本：本机契约

本轮仅使用新建、可销毁SQLite与合成清单／策略，不创建真实身份、签名密钥或生产资源。账本是本机受控调用方的实验接口，不提供HTTP、管理员操作或真实审批。

- 同一租户／视图的清单和策略各有独立、持久递增的正整数版本；写入由SQLite `BEGIN IMMEDIATE` 串行化，调用方提供预期当前版本，事务内CAS失败关闭，不重试。服务端分配下一版本，不能指定旧版本。
- 每个变更有规范UUID命令ID，作用域内不可复用；事件按版本追加、绑定前一事件哈希、状态和内容哈希。重复命令、旧预期版本、缺失历史、哈希不符或状态异常均拒绝。哈希链用于发现未协调改动，不等于签名、可信操作者身份或防止有权限者重算整个链。
- 撤权是保留历史的`revoked`事件，不删除或重置版本；重新授权必须追加新版本和新命令ID，不把旧版本重设为有效。相同内容可以经过新的授权操作重新发布，但旧命令不能重放。
- 一个活动策略必须绑定提交时精确的活动清单版本与事件哈希；只要当前清单或策略已撤权，或策略引用的清单不再是当前版本，查询拒绝。更新清单不会自动继承旧策略授权。
- T1/T2提供者只读当前权威记录，版本和事件哈希纳入返回前复核。撤权后再授权即使内容不变，较新代次也使在途旧请求失败；T2后新发生的变更不追溯阻止已准入的响应。
- 重启可从同一账本恢复并核验链；普通并发、重复提交、陈旧发布与缺记录不会降低版本。**数据库文件整体恢复旧快照、同权限者重写完整链、可信签名／审批身份及多节点防回放不在单SQLite可证明范围**。这些需要独立的不可回退可信锚、签名/身份及运维治理，真实方案须另行确认；不得用本机CAS通过声称已解决。
- 错误不暴露数据库细节；只允许调用方显式处理冲突，不使用重试、TTL解锁或自动重放。查询本身仍只读，实际策略服务`read_data`默认拒绝不变。

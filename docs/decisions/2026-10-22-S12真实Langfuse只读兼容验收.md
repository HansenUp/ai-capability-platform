## 实际只读请求

所有 HTTP 请求均为 loopback GET、禁用环境代理和重定向、5 秒超时及 1 MiB 响应上限；不向 Langfuse 转发用户 JWT。

1. 08:54:35 UTC 初次健康 GET 为 5 秒 ReadTimeout，未发认证数据请求。读取容器就绪标记后，于 08:55:20 UTC 使用同一上限再次检查，200／3.225.11；保留初次启动期超时，不增加超时或把它隐藏为首次成功。
2. `GET /api/public/v2/scores?name=user_feedback&page=1&limit=100` → 200，顶层 data／meta；meta 为 page=1、limit=100、totalItems=6、totalPages=1，实收 6 条。该单页返回符合现有读取器的分页形状，**未覆盖多页并发变化或 2000 条边界**。
3. 对其中一条既有评分执行 `GET /api/public/v2/scores/{existing_score_id}` → 200，返回独立评分对象。样例字段 id／traceId／dataType／timestamp／updatedAt 为字符串，value 为整数，metadata 为对象；不归档实际值、ID、评论或 correction。
4. 对同一评分关联的既有 Trace 执行 `GET /api/public/traces/{existing_trace_id}` → 200，id／sessionId 为字符串、metadata 为对象。metadata／attributes 中均可找到读取器要求的 ai.run_id、ai.tenant_id、ai.agent_id、ai.subject 字段；这里只验证字段存在，**未与 Runtime 权威 cohort／原发起人账本核对，不能声明归属或来源可信**。

没有调用现有 `verify_langfuse_trace.py`，因为其会真实导出 Trace；没有运行 prepare／execute／reconcile／ACK、评分 POST、项目初始化或任何账号变更。

# S12 创建持久回执契约

## 状态与范围

这是回答闭环后创建步骤的本机技术约束；后续实现和真实验证以《2026-10-21-S12创建持久回执验收》为准，不能仅凭本文设计条目判定通过。沿用已批准的主体账本及显式收口规则，截止仍为 2026-10-21 22:06:08Z；不扩展生产、外部服务、账号、代理身份、管理员解锁、记录清理或 S13。

仅接入现有 Console Chat 的一个 Agent ID＋单条纯文本用户消息；附件、多轮、session、任意消息数组和新业务字段不在本闭环中。旧 POST /v1/runs 不改签名和行为，不把旧未知结果追溯绑定到新 attempt。

## 写前登记与尚无 Run ID

1. 客户端生成 attempt UUID；服务端验签身份并串行锁定同主体指针。客户端不提供或推断 Run ID。
2. 服务端复用当前 Agent 选版和输入校验，仅选择本租户可见已发布版本；将选中版本、模型及快照内容绑定显示给操作者。未提交有效登记前不创建 Run，不写 RunInput／凭据，不入队，不调用模型或工具。
3. 可预留服务端随机 Run 标识作为 attempt 的不可变定位范围，但明确标为“预留，尚未创建”；PREPARED 时 Run 404 是正常情况，绝不作为解锁或重新创建依据。创建请求序号使用专门的未创建语义，不假造既有事件序号。
4. 账本仅保存创建定位和必要快照元数据／指纹，原始消息不另存新表。内容绑定采用域隔离的服务端 keyed HMAC，包含主体、attempt、预留 Run、Agent 快照及规范化请求，不用低熵文本裸哈希。登记响应丢失后可仅凭验签主体活动账本恢复，不要求客户端先持有 Run ID。
5. 为避免登记与执行间悄悄改变行为，显式执行时重新核对当前可见选版和快照；版本撤回、选版或快照变化失败关闭，不自动改版执行。不新增“登记后仍可调用已撤回版本”的业务旁路。

## 显式执行、回执与收口

执行要求原操作者再次提供登记时同一纯文本消息；重载后不恢复原文，需重新输入。错误消息、错指纹／版本／主体在业务写前拒绝，不允许客户端换 Agent 或改消息复用 attempt。HMAC 密钥变化按回答同一规则失败关闭，不自动重绑。

抽取既有 Run 创建的调用方持有事务 helper；旧入口仍由原包装负责 commit 和入队，不能在持久账本 execute 内调用会自行 commit 的旧创建方法。新执行将 t_run、既有 t_run_input、加密用户凭据、带 attempt／消息绑定／快照标记的唯一 run.created，以及 COMMITTED 和精确证据序号原子提交。原始消息只进入既有执行输入存储，不能复制进账本、审计或新回执字段。

提交后沿用既有队列／reaper 规则；入队不等于执行成功，COMMITTED 仅证明 Run 已受理创建，不证明模型、工具或 Run 终态成功。相同 attempt 的已决重放只返回原回执，不重复创建 Run、写输入或入队。未分类故障整体回滚；可明确确认无创建效果的校验拒绝才能记录 REJECTED_NO_EFFECT，不能把外部未知效果改判无效果。

ACK 只接受证据，不接受消息。必须核对原主体、attempt、创建动作、预留 Run、当前版本／指纹及精确 run.created 的操作者、快照和内容绑定；严格终结后本人明确确认才清除活动指针。PREPARED、Run 404、空列表、SSE done、Run 终态、重载或 TTL 均不提供解锁途径。原值遗失、密钥丢失或管理员人工裁决不增加旁路。

## 准入边界与验收清单

旧入口活动锁仍仅阻止新请求准入，不追溯已准入在途写。新接口不信任 Console 标记，不接受开发头或服务账号，锁以验签租户与实际创建者为准。不能把预留标识直接显示为已创建任务或将 prepare 当作真实创建成功。

实施后需验证：无 Run ID 的登记丢响应恢复；PREPARED 无 Run／输入／凭据／队列；原消息不进入账本；换值、换版本、撤回快照及权限变化失败关闭；部分创建后故障事务回滚；同 attempt 并发只有一个 Run／run.created；精确收口与他人／跨租户隔离；旧入口 409 与已准入请求边界。真实隔离浏览器必须覆盖准备后重载、执行提交后丢响应、同主体新令牌、只读恢复与显式 ACK；不得用 TestClient 替代浏览器证据。完成相关、全仓、类型构建及浏览器回归后才能更新为已实现／验收。

## 实现定位

新入口为 POST /v1/workbench/create-attempts，传 attempt_id、agent_id、text，不传 Run ID；通用 execute 中 value 为原始纯文本字符串，ACK 不接收 value。PREPARED 的 request_seq=0 表示尚无创建事件；COMMITTED 必须对应精确 run.created seq=1。迁移 0010 增加可空 create_agent／create_version／create_model／create_snapshot／create_reason，保留既有账本数据；原文仍不存入账本。

创建时在主体事务内重新取得选中 Agent 行锁并校验快照，使用原选版规则的准入时点；不承诺对分布式节点配置或未来发布状态建立跨系统事务。既有已发布快照后续如何变更仍服从原发布契约，不增加绕过发布闸门的入口。旧入口已准入请求的确定性屏障验证保留为兼容边界证据，而非声称其被追溯冻结。

## B 阶段准入：必须全部明确

### 数据及权限

- [ ] 明确允许读取 ai_platform 的真实数据用于备份和恢复验证，包括 Runtime、Console、两套迁移版本及有关对象；不扩大到 ai_gateway、Langfuse 或其他库。
- [ ] 确定使用已有凭据的安全来源；不新建账号／密钥、不输出口令。数据库备份权限不是 Runtime JWT 管理员权限。
- [ ] 批准的验证仅输出 schema、计数、摘要与拒收诊断，不打印业务正文、个人明细、密文凭据内容或完整 SQL dump。
- [ ] 明确备份可能含提示词、事件、用户映射、密文凭据及审计数据；不得写入仓库、evidence、聊天或普通日志。

### 存储与恢复目标

- [ ] 用户指定已有的加密备份目录、加密方式及安全密钥来源；不在聊天粘贴密钥，不新建密钥或替换既有密钥。
- [ ] 验证目标目录权限、磁盘容量、加密工具可用性、失败后的临时明文处理；没有可靠加密流程则暂停，不降级为仅 chmod 0600 的长期明文备份。
- [ ] 用户明确保留期限、到期删除授权和责任人；不擅自设置自动清理或执行删除。真实备份与恢复副本采用相同敏感数据保护等级。
- [ ] 指定批准的隔离恢复目标与资源上限。不得覆盖 ai_platform、复用其他业务库或默认新增持久服务；临时库也含真实数据，其创建、访问和清理需包含在授权中。
- [ ] 不向 Langfuse、对象存储云端或其他外部服务发送数据；不恢复可触发真实业务的调度器／事件任务。

### 共享库停写及一致性

- [ ] 用户明确允许协调已确认的 Runtime、Console、节点代理及其他数据库写入者停写；启动、停止或变更服务不从本次清单授权中推定。
- [ ] 在授权范围内核实实际写入者、在途 Run／租约、事务、迁移锁及未决外部效果；不能因端口无监听或只停 Worker 就认定无写入。
- [ ] 确认备份／恢复验证期间无并发 DDL；记录共同恢复点和两套 Alembic 版本。备份期间无法冻结 DDL或确认一致性则暂停。
- [ ] 先选定一致性方案：当前已知全 InnoDB，可评估单事务逻辑备份，但不能将实时 volume 文件复制当作已验证一致性快照。
- [ ] 明确不可接受的数据丢失与停机时间要求。RTO／RPO 尚未测定，不以合成演练耗时承诺真实恢复时长。

- [ ] B 阶段真实恢复通过；停写窗口、责任人、现有库升级与失败恢复授权单独确认。
- [ ] 重新只读核实原库仍为预期 0005、无手工漂移／同名冲突、所有写入者已冻结；迁移目标固定 0011 而非可变 head。

# 任务失败原因与只读恢复验收

## 已实现

共享 RunOutcome 同时服务 Console 工作台、Run调试及 Portal 任务详情。新增“失败原因与只读恢复”：
- 按可见事件序号呈现 run.error 与 error/denied 工具结果，保留历史失败，不被后续成功覆盖。
- 已核对错误码 UNKNOWN_TOOL_RESULT、BUDGET_EXCEEDED、DATA_CLASS_MODEL_BLOCKED、POOL_EXHAUSTED、HARNESS_VERSION_MISMATCH、RUN_SNAPSHOT_MISSING 提供固定解释；其他代码统一提示核对原始事件，不猜根因。仅接受映射自身属性，__proto__ 等不当成已知错误。
- 不自动展开任意错误 message/output/code；原始正文仍在既有授权轨迹查看。工具错误不推断无副作用，Run failed 而缺少原因时明确证据不足。
- 工作台传递当前主体活动回执的 status/run_id，标明可能属于其他任务。PREPARED 不等于执行，COMMITTED/REJECTED/OBSERVED 不自动解锁；无回执也不证明无锁。Runs只读页没有读取账本，不伪装持有回执。
- 给出重新认证、原Run只读读取/核对账本及手动续读指引；Run终态、SSE结束、404和空列表不能替代收口证据。新增区域没有重试、执行或ACK按钮。

未改变后端协议、权限、审批、回执确认、SSE和写锁逻辑，未新增自动重试；B2十文件指纹保持一致。

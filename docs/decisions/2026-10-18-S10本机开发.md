## S10.2 首个闭环：节点持久化与分组接口

- 新增 Console 迁移 `0003`：`t_console_node` 保存节点注册、分组、版本、最近心跳与负载；`t_console_node_binding` 保存按租户隔离的 Agent 分组权重。SQLite 本机与 MySQL 使用同一 ORM／迁移，节点与绑定不再依赖进程内字典。
- 注册／绑定采用数据库原子 upsert，并发首次登记不产生重复行；节点重注册更新元数据与心跳，但保留平台管理员调整的分组。心跳超时只从路由剔除，不删除注册记录，恢复心跳后重新进入路由。
- 新增 `GET /nodes`、`GET /node-groups`（租户管理员及以上只读），`PUT /nodes/{node_id}/groups`（平台管理员修改共享基础设施分组），分组修改写审计。分组以节点标签表示，尚无独立的空组元数据与分组前端页面。
- `PUT /agents/{id}/bindings` 持久化租户作用域的权重并写审计；拒绝重复组与非法权重。`GET /routing` 按当前操作者租户输出绑定、按心跳输出健康节点；不接受任意查询参数切换租户。开发身份头仍沿用当前 Console 信任模型，生产身份注入与 APISIX 插件另行验收。
- Skill 标签推送改为查询持久节点表，保持现有指令下发和回执协议。节点是共享基础设施而非租户专属资源；租户隔离的是 Agent 绑定，平台分组修改不得下放普通租户管理员。
- 既有内存数据没有可靠持久来源，不虚构迁移：升级后已有节点在下一次心跳 404 时自动重新注册，旧内存绑定须由管理员重新配置。持久化后的注册、心跳、绑定可在 Console 重启后保留。

## S10.3 节点指令首个增量

- 新增受限 `reload_config`：参数仅允许 `poll_interval_s`（1～3600 秒）、`timeout_s`（0.1～120 秒），只作用当前 NodeAgent。未知键、字符串、布尔值、非有限值和显式 null 拒绝；校验完成后一次性替换不可变配置，不部分应用。
- 不允许通过指令修改 Console URL、令牌、签名信任、网络白名单、模型或 Runtime 全局设置；回执只记录作用域与生效数值，不包含秘密。这不是完整 Runtime 热重载，也不改变生产鉴权。
- 回执失败时保留本进程缓存并停止本批后续指令；下一轮仅重发已执行指令的回执，成功后再处理后续指令，避免控制面确认失败后越序执行。缓存不是跨进程执行账本，不声称重启后恰好一次。
- 当前配置增量不跨进程重启持久化，重启后仍以部署环境变量为基线；Console 指令与回执本身持久化。`switch_model`／`graceful_restart` 继续返回 unsupported，须先明确模型版本绑定及排空／重启契约再实现；S10.3 仍为进行中。

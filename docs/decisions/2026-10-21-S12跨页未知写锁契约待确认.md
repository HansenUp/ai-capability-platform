## 推荐契约草案（待批准）

### 1. 权威来源与写前登记

推荐 Runtime 持久操作账本作为权威，复用本机测试 SQLite 验证，不引入外部服务；浏览器存储至多缓存不敏感定位信息，不能作为业务授权或唯一防线。localStorage／IndexedDB 可被清理或篡改，不能承诺恶意清除后仍强制锁定、跨设备一致或同源脚本隔离。

写操作需要明确的写前准备阶段：生成稳定 attempt_id，服务端在实际业务 mutation 之前登记操作意图并返回准备凭证；未确认准备成功时不发送业务 POST。重载后先验当前身份、查询其未决账本，完成恢复检查前不得发送受保护的写请求。只有错误返回后才保存 uncertain，无法覆盖“POST 已发出、页面在收到异常前崩溃”的窗口。

建议状态为 PREPARED／IN_FLIGHT／UNKNOWN（阻止相应新写）与 COMMITTED／REJECTED_NO_EFFECT（有证据终结）；记录单调版本，禁止被旧标签页覆盖。相同 attempt_id 与相同操作绑定，不能改变 payload 或产生第二次业务效果。是否返回既有回执、允许幂等准备重查及兼容旧客户端，需协议评审；不预设所有既有 POST 已支持幂等。

最终回执必须与目标业务状态／事件同一事务提交，或明确另一套可证明的原子性设计；准备成功不等于执行成功。网络丢失、登记／存储不可读、协议版本未知、数据损坏均失败关闭，不通过重发试探结果。准备阶段响应未知时不发送业务 POST，避免悬空登记演变为重复业务操作。

### 2. 身份绑定与范围

身份只能来自 Runtime 对当前有效凭据的验签结果。建议绑定 Runtime 环境／实例域、受信 issuer、安全域／audience、tenant、真实写操作者 subject，以及必要的 actor／client_id／auth_method；字段与环境实例来源需确认。客户端 JWT claims、用户输入 subject、Run.owner、token hash、JWT 的 exp／jti／kid 都不能独立充当权威主体键。换有效令牌但主体不变，不能获得新锁空间。

特别区分：Alice 发起 Run、Bob 审批，锁应绑定 Bob 的审批动作，而不是把 Alice 的 Run.subject 当成 Bob。credential／answer 仍只能由原发起人提供。换用户／租户不继承旧人的可写权限，不暴露其账本、Run ID 或负载；换回原主体仍恢复其未决锁。服务账号、代理身份或开发头不得默默当作真实用户身份。

推荐初期维持保守语义：同 Runtime 安全域、同已验证租户与操作者存在未决写时，冻结该操作者的工作台新写，仍允许只读与重新认证；不冻结全租户或无关用户。按 Run／操作细分是另一种业务选择；创建结果未知没有 Run ID，必须另有主体级创建保护，不能漏掉这一类请求。

不得持久化访问／刷新令牌、消息、回答、工具参数、凭据值或完整响应正文。最小记录只保留不敏感定位、动作描述、状态／版本及必要关联指纹；指纹是否含敏感信息、规范化与保护方式也需评审，不能默认“hash 就无泄漏”。未决记录不因 TTL、退出登录或存储满自动删除；已决留存／归档策略另行确认。

### 3. 解锁证据与权限

| 观察 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 当前身份验签成功 | 在本主体范围查询账本 | 把新 token 当作对旧请求已决的证明 |
| Run completed／failed、SSE done、查询 404／空列表、TTL 已过 | 仅展示辅助线索 | 自动解锁、删除账本、推断未执行或重发 |
| 相同 Run／call 的 input.provided 或 approval 事件 | 辅助人工定位；若无唯一 attempt 关联仍是候选 | 将他人动作、较早输入或另一次凭据刷新当作本次 POST 回执 |
| 同身份＋同 attempt＋相同动作／范围／指纹＋不可歧义的服务端终结回执 | 候选终结证据，按获批规则收口锁记录 | 自动重发原操作、把拒绝结果改为成功 |
| 日志冲突、回执不可读、跨主体、受限审批视图缺证据 | 保持锁，显示不确定与待处理 | 用客户端勾选“已核对”替代服务端证据 |

推荐：只有不可歧义终结回执后，允许原写操作者显式确认收口；确认行为独立审计，不重新执行业务写。另一可选规则是同等强度回执验证后自动收口（仍不自动重发）。需要人工裁决或管理员代解锁时，必须另定角色、理由、证据及审计规则，当前不新增。

确认收口只能清除该账本条目的未决阻塞，不授予新的业务权限，也不能改写／删除回执。404、过期、篡改、跨租户或重放的解锁请求应拒绝；不得实现无证据清空全部锁的按钮。

### 4. 多标签页、失效与保证范围

同源通知／storage event／BroadcastChannel 只用于 UI 同步，不能代替服务端 CAS。旧页面、同时开页、页面在写前／提交后关闭，都应由账本版本与单次动作约束兜底。禁用、清空或伪造浏览器存储不能清除服务端未决条目；网络断开时不得用缓存成功代替本次权威验权。

要对所有入口强制执行协议，必须评审旧 SDK、API 调用方、测试夹具与发布兼容；不能只凭客户端可伪造的“来自 Console”头启用防线，不能偷偷把旧 POST 的可选字段改成全局必填。确认前本文只描述目标，不宣称已有跨页或跨设备强保证。

## 获批后最小实现／验收顺序

1. 本机迁移＋权威身份只读接口＋带权限的未决账本查询，确认不能把 Run 发起人与审批操作者混淆；不连接外部 IdP 或生产。
2. 先选定一种动作（推荐已有 credential fixture）实现写前准备、同事务终结回执及重载恢复；其他写入口在协议未覆盖时明确保留原能力边界或按获批策略禁写，不能冒充全面防护。
3. 隔离测试覆盖：发出后立即重载、服务端已提交但响应丢失、准备响应丢失、同主体换 token、不同用户／租户、Bob 审批 Alice Run、多标签页竞争、存储禁用／清除／篡改、旧响应迟到、已决回执匹配／冲突、无证据拒绝解锁、确认收口不触发第二次写。
4. 单独覆盖创建未知且没有 Run ID，确认按主体检索与原 attempt 关联；不能用“列表没有找到”判未执行。再按依赖扩展 create／approve／reject／answer，不复用工具层 operation_id 假装已经覆盖。
5. 相关后端、DOM、真实 loopback 故障 E2E、全仓回归与证据归档后，才可标记获批范围完成。仍不能标记 S12 整体、外部或生产出口通过。

## 当前待确认

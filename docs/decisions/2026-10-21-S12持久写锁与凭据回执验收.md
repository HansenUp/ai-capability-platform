# S12 持久写锁与凭据回执验收

## 授权与交付边界

2026-10-21 用户确认：Runtime 为权威账本；同验签租户与真实操作者存在未决写时，冻结其工作台全部新写；严格匹配服务端终结回执后，由原操作者显式确认收口。授权本机迁移和身份／账本／回执接口，仅执行本轮隔离开发验证。未启用自动跟进，未提交、推送、部署、操作生产、真实业务或账号。

本轮交付 **credential 后端最小闭环**，不是全部工作台动作或 Console 跨页体验完成。新增迁移 0007；只在临时测试库执行迁移，不对现有业务库执行升级。S12.3 继续保留未完成标记，S9 外部验收、D47、Helm／Argo CD 与生产出口状态不变。

## 已落实契约

- 身份：新增接口仅接受验签用户 JWT；不接受开发头、服务身份或未支持的代理身份。主体键采用配置的可信 issuer／audience、验签 tenant／subject／auth_method，actor 与 client_id 为身份元数据。换 token 的 exp／jti／kid、客户端或角色不创建新锁空间；Run.subject 仅用于 credential 发起人权限校验，不能代替其他动作的真实操作者。
- 持久化：`t_workbench_scope` 保存主体活动指针，`t_workbench_attempt` 保存 UUID、Run、请求事件序号、动作指纹、状态、版本、终结证据及确认标记。不保存访问令牌、回答、消息或完整请求正文。未决记录没有 TTL、退出清理、管理员代解锁或浏览器清空入口。
- 写前登记：`POST /v1/workbench/attempts` 先串行锁定主体行，校验 credential 待办并提交 PREPARED；同 UUID／同绑定返回原记录，不同 UUID 在活动锁存在时拒绝。指纹绑定主体、credential、Run 和待办事件序号。
- 原子执行：`POST /v1/workbench/attempts/{id}/execute` 校验主体、指纹、版本与待办。复用原输入规则，将凭据刷新、带唯一 attempt 标记的 input.provided、Run 状态与 COMMITTED 回执放在同一数据库事务；凭据来自当前验签令牌，不接受请求正文传值。预期校验拒绝在保存点回滚后记录 REJECTED_NO_EFFECT；未分类故障整体回滚，保留 PREPARED，不伪造已决结果。
- 读恢复：`GET /v1/workbench/identity`、`GET /v1/workbench/attempts`、`GET /v1/workbench/attempts/{id}` 仅查询当前验签主体。重新连接数据库、丢弃客户端响应或换同主体有效令牌后仍查到活动记录；其他人／租户不能读取或确认。GET、Run 终态和 SSE 均不解除锁。
- 显式收口：`POST /v1/workbench/attempts/{id}/acknowledge` 校验原主体、指纹、当前版本及精确终结证据；COMMITTED 必须存在同 Run、事件序号和 attempt 的 credential 输入事件，拒绝回执必须为服务端已确认的无效果拒绝。收口原子清除该指针并写审计，不删除回执、不重做业务写。同 attempt 执行重放只返回已决回执，不再刷新凭据或入队。

## 旧 API 兼容及未覆盖边界

Runtime messages 路由所有 POST 在准入时查询该验签主体的活动锁，存在则返回 409，覆盖创建、审批、拒绝、输入、resume 等原入口；GET 不受阻。没有活动锁时保留既有 API 行为，不增加旧 SDK 必填字段，也不信任客户端“来自 Console”标记。

这是**新请求准入门禁**，不是将所有旧写请求纳入相同事务：准备前已准入的旧请求不追溯冻结；旧协议创建／审批／回答的未知结果尚无本次 attempt 回执。其他主体不被冻结，代理身份不能使用新协议。不能宣称全部旧入口已有端到端跨页未知写保护。

Console／SDK 尚未接入新的 prepare／execute／acknowledge 流程，原组件内存锁行为保持不变；本轮未验证真实浏览器对新增账本协议的重载、断网、旧响应和多页竞争。已有浏览器回归只证明原功能未退化，不作为新增页面验收证据。

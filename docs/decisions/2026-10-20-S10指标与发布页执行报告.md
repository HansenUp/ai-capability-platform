## 已实现：只读 Trace 指标

- 新增 `GET /metrics/traces`，需要 `agent_id`、带时区的 `since`／`until`。窗口须递增且不超过 7 天；仅 TENANT_ADMIN 及以上、当前租户已登记 Agent 可查询，跨租户不存在为 404，USER／ADMIN 为 403。
- 范围是 Langfuse v3 中名为 `run <agent_id>`、且根 metadata 的 Agent／租户精确一致的 Trace；不是所有 Span、不是 Run 数、不是模型请求次数。列表分页后先按租户／Agent 筛选，再读取匹配 Trace 的详情并复验 ID、时间和归属。冲突元数据拒绝。
- 按 GENERATION 汇总 Token 与费用，不把其他 Span 的默认用量或 Trace 的默认总费用当作已采集值。只有 `usage.unit=TOKENS`、明确 `usageDetails.total` 与 `usage.total` 一致的非负整数才计用量；布尔值不计。费用仅接受明确提供的 totalCost，或有可用 costDetails 支撑的 calculatedTotalCost；无定价信息的计算默认 0 仍视为未知。
- 结果包含 Trace 数、GENERATION 数、Token／USD 费用、完整覆盖的 Trace 数，以及明确标注的已知 Trace 小计。任一匹配 Trace 的指标缺失时对应总计为 null，不填 0；空查询的 Trace 数可为真实 0，但用量／费用仍无采集证据。费用是观测来源值，不是财务结算或账单承诺。
- 仅 GET 请求；只支持 loopback 的既有 Langfuse v3，生产模式拒绝该本机配置。HTTP 代理环境不继承、不跟随重定向；沿用现有项目凭据，不写库、创建数据集或 Trace，不把秘密和 Trace 输入／输出返回或归档。
- 单页 100，最多 20 页；校验分页条数／总页数／总数及重复 ID。超过预算、分页变化、非法结构、来源故障均返回统一 503，不发布不完整的部分聚合。每响应最多 2 MiB、详情并发 4、单请求超时 5 秒、整体 30 秒。发生故障时收束已启动的读取任务，不无限重试。
- 分页完整不等于原子快照，响应明确 `snapshot_guaranteed=false`；来源异步入库及查询期间并发变化仍可能影响观察结果。Run 成功率、延迟和状态分母未在此定义，`run_metrics_available=false` 保留。

代码：`services/console-api/src/console_api/trace_metrics.py`。Console 数据库仍为 0006，不新增表或身份权限体系。原 `/metrics/operations` 保持控制面计数，不用 Trace 指标冒充其 Runtime 执行统计。

### 版本兼容说明

现有 compose 使用 Langfuse v3，本轮只适配实际本机 v3 响应，不升级镜像／SDK。[官方 API 说明](https://langfuse.com/docs/api-and-data-platform/features/public-api)和[旧接口迁移文档](https://langfuse.com/faq/all/deprecated-api-migration)用于核对版本边界；v4／Cloud 的迁移不在本次范围，不能把本机兼容性推广到新版本。

## 已实现：发布页面闭环

- 改造现有 `apps/console-web/src/views/Agents.vue`，将“仅保存草稿”与“发布”拆开；不再固定发送 `eval_run_ref=manual` 或自动声称 `eval_passed=true`。
- 保存／复制草稿保留完整 config JSON，不因页面只展示少数字段而丢弃已有工具、Skill、红线及扩展配置；已发布快照只复制为新版本，必须输入新版本号。进入编辑／完成保存时清除旧发布选择，避免保存新草稿后误发布旧选中版本。
- 选中版本后读取真实 `/agents/{id}/eval-gate`，显示 mode、最小条数、通过率和配置数据集。Langfuse 模式输入真实运行引用；后端仍核对数据集、Agent／版本／租户、评分与分页完整性，不靠前端放行。
- flag 模式只作为既有开发契约保留：须操作者显式勾选评测通过并明确提示不是真实评测验收；没有默认为真，也不改变生产必须 Langfuse 的基线。本轮浏览器实测使用 Langfuse 模式。
- 灰度支持 0–100 整数与主体白名单；0% 明确为白名单预发布，不能冒充通过评测；0→正比例放量使用版本已存评测引用并重新经过后端闸门。页面不能用未保存的新引用替代放量校验。
- 发布、灰度和回滚均有页面内确认及冻结的请求摘要；执行期间禁止重复提交、编辑身份或更换目标。回滚说明目标恢复全量和其他已发布版本退役；0% 版本不能直接回滚为全量。
- 展示真实 HTTP 失败，成功后重读状态；身份采用显式应用，切换清空原租户列表／表单／选中版本。开发身份头不等于生产 OIDC。没有自动重试未知发布结果或新增部署入口。

## 本机验证与证据

### 真实来源与真实服务

`make verify-s10-traces` 只读已归档 S9 的真实本机 Langfuse 数据；样本窗口为 **3 个 Trace、5 个 GENERATION、300 Token**，无定价证据所以费用总计 **null**，不是 0 元；跨租户查询拒绝。没有生成新观测数据。

`make verify-s10-publishing` 使用独立临时 Console／Runtime SQLite 和回环 HTTP，模型清单为明确本机桩、Harness 为 mock，不调用真实模型。验证草稿不写 Runtime、错误引用在同步前阻断、白名单预发布、真实 Langfuse 评测后放量、Runtime 真实持久化发布状态及不可覆盖已发布快照。不是 MockTransport 代替 Runtime 的验证，也不是生产部署。

1. 复用本机 v3、既有 Langfuse 凭据与已归档数据，不升级或生成新数据，避免扩张验证范围。
2. 采用 Agent 粒度、最多 7 天、2000 条扫描预算、4 并发、30 秒截止和失败关闭；这些是可调整的本机保护值，不是业务 SLA 或容量验收结论。

5. 恢复已安装 Docker Desktop 及当前项目原已存在的 Redis、MinIO、Langfuse PostgreSQL、ClickHouse、MySQL、Langfuse Web 六个容器用于验证；未 pull、创建新容器／卷、升级镜像或启动其他项目容器。相关环境收尾状态另行记录。

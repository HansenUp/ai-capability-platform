# S12 Owner单Agent只读摘要与Trace契约草案

状态更新（2026-10-25）：**用户已确认D1～D6推荐方案，仅授权临时库／签名测试身份／Langfuse替身的本机实现，不授权真实服务或生产。** 实现与验收见《2026-10-25-S12Owner单Agent只读最小闭环验收》。下文保留起草轮的候选契约与执行边界，“本轮起草”指原起草轮，不是后续实现轮。

本轮仅起草数据／权限／验收契约。未新增路由、修改业务源码、OpenAPI、角色或表结构；不启用自动跟进、不操作真实服务或数据库、不读取凭据、不写评分／Trace、不部署。北极星仍待定义。下文的“必须／禁止”均为候选方案获批后的实现要求，不表示当前系统已经具备。

## 1. 推荐范围与非目标

推荐第一阶段仅支持：**当前明确分配给操作者的一个Agent，读取控制面最小摘要及Trace聚合用量**。同一Agent允许多名显式被分配管理员，不引入唯一Owner、组织继承、代理操作或跨租户权限。

- Owner候选＝可信身份映射后的Console ADMIN及以上角色＋当前同租户UserAgent显式分配；两项缺一不可。
- 新Owner路径不继承`assert_assigned`对租户／平台管理员的自动归属豁免；未分配的管理员仍使用现有管理员入口，不由新入口扩大范围。
- 不含反馈、评分／correction、Run明细、原始Trace／Span、输入输出、Trace详情跳转、用户／分配人数／排名、租户总量、节点指令、审计正文、Run成功率／时延或北极星。
- 不修改现有`/metrics/operations`、`/metrics/traces`和反馈接口的最低权限、时间语义或响应结构，不调整现有Operations管理员页面的allowed条件。

当前事实依据：《2026-10-25-S12Owner运营视图数据与权限只读梳理》及Console auth／db／Trace源码。现有指标仍限管理员；本草案不是修复某个“应给Owner放行”的既有缺陷。

## 2. 可信身份映射

### 2.1 推荐链路

候选链路：**Console服务端验签用户JWT → 固定身份元组 → 受控显式绑定 → 当前角色与Agent分配查询**。

1. 验签校验固定允许算法、可信issuer、配置的Console audience、有效期等。Console audience的实际值／签发客户端需另行确认，不接受客户端自报或自动借用Runtime audience。
2. 只接受用户身份，不接受client credentials、服务账号、act代理／冒名身份；不能仅凭`human:`前缀判定用户可信。
3. 身份主键为`(issuer, tenant_id, subject)`，大小写与原值精确匹配。tenant来自受信验签声明，缺失、歧义或冲突拒绝；不能由query或X-Console-*覆盖。
4. 由受控绑定将该元组映射到现有`UserAgent.user`。不以显示名、邮件、created_by、Directory条目或删除`human:`前缀猜测用户名。角色也须来自显式批准的受信声明映射，不能信任UI选择的ADMIN字符串。
5. 同一身份只能绑定一个legacy user；第一阶段同租户legacy user不允许被多个不同身份元组共享。缺失绑定拒绝准入，歧义／配置不完整受控不可用，不创建新绑定或默认回退。
6. 新入口只接受Bearer；请求中出现试图指定user、owner、tenant、role的额外参数或X-Console-*身份头，推荐400拒绝，不静默采用它们。旧开发头接口行为不改。

JWT签名有效只证明该issuer签发了声明，不自动证明旧分配字符串与此人对应；必须同时有受控绑定。JWT中的角色也不替代Agent分配。

### 2.2 本机最小验证与正式身份门禁

推荐获批后的本机实现先用签名测试JWT、固定测试issuer／audience、测试夹具内不可由请求修改的一对一绑定；仅临时库，不新增真实账号、角色、密钥或持久服务。绑定是测试用受控数据，不升级Directory展示元数据为授权目录。

真实IdP、正式绑定存储／管理主体／变更审计／防复用规则、角色同步与撤销策略另行验收；若需要新增持久映射表或迁移，须先确认。本机版本默认关闭且不在生产启用，不能把测试绑定当作正式身份接入已完成。

本范围不调用Runtime身份／反馈管理员接口，不将用户Bearer转发给Runtime或Langfuse，不使用发布服务账号代读；Langfuse凭据只留服务端已有受控配置中。

## 3. 数据准入与最小响应

### 3.1 候选接口形态 未创建

| 候选GET路径 | 输入 | 范围 |
| --- | --- | --- |
| `/owner/agents/{agent_id}/summary` | 单Agent ID；不接受tenant／owner／版本选择 | 该Agent读取时的控制面版本计数 |
| `/owner/agents/{agent_id}/trace-metrics` | 单Agent ID、带时区since／until | 该Agent指定时间窗内的Trace聚合 |

这是独立、版本化响应scope的候选路径，不是OpenAPI承诺；两个请求各自独立鉴权，结果不是共同快照，不允许根据摘要成功跳过Trace准入。Agent ID保持既有长度约束，不接受通配、批量或“全部Agent”。不增加匿名Agent枚举入口，候选Agent列表继续使用已有受限管理列表，不能由客户端列表替代后端鉴权。

共同响应字段建议：`scope`、`schema_version=1`、`tenant_id`、`agent_id`、`read_started_at`、`read_finished_at`、`snapshot_guaranteed=false`、`authorization_policy`。`authorization_policy`只标记`current_assignment_rechecked_v1`，不暴露其他Owner名单、内部绑定ID或伪造一个授权修订号。

`scope`分别固定为`owner_agent_summary_v1`／`owner_agent_trace_metrics_v1`；Trace响应另带UTC规范化后的`since`／`until`和`interval=half_open`。时间字段均为带时区ISO 8601字符串；计数为非负整数且拒绝布尔值；费用为有限、非负十进制字符串，未知使用JSON null而非空串。返回模型采用字段白名单，不允许把源对象的额外字段透传浏览器。两个响应没有共同data version或授权epoch，不制造跨请求快照保证。

### 3.2 摘要白名单

- `versions.draft`、`versions.published`、`versions.retired`：当前同租户同Agent版本数；计数状态依据现有版本状态，不把灰度比例视为流量实测值。
- 不返回全租户Agent数、分配关系／人数、创建者、配置正文、评测正文、审计／节点数及指令状态。
- 从Console本地事实读取，单次数据读取范围完整才允许精确0；失败不伪造空对象或补0。摘要无时间窗，也不代表查询期间版本状态没有变化。

### 3.3 Trace白名单与未知语义

复用现有读取器的指标含义，不复用管理员HTTP处理函数绕过Owner准入：

| 输出 | 候选语义 |
| --- | --- |
| `trace_calls`、`generations` | 完成有界API扫描后选中的唯一Trace数／GENERATION数，不是Run或任务数 |
| `tokens.total` | 所有选中Trace用量均完整时才返回；无Trace或任一缺失为null |
| `tokens.known_trace_subtotal`、`traces_with_complete_usage` | 已知Trace级用量之和与完整样本数；明确不是总量 |
| `cost_usd.total` | 全部完整才给十进制字符串，否则null；不是财务结算或单次任务成本 |
| `cost_usd.known_trace_subtotal`、`traces_with_complete_cost` | 来源费用已知小计及完整样本数；不以未知补0 |
| `complete_scan=true` | 只表示有界源API分页及详情读取通过，不保证采集无遗漏、留存完整或历史快照 |
| `run_metrics_available=false` | 不提供Run成功率、时延、活跃用户或北极星 |
| `source_trust=metadata_consistency_only` | 租户／Agent字段一致不等于有签名来源证明；不宣称Trace权威归属已验收 |

无Trace时`trace_calls=0`、完整样本数0、已知小计0，但总Token／总费用仍为null；该0仅是本次扫描的观测结果，不证明历史没有调用。接口不提供他租户／他Agent的排除数、来源项目总量、未授权名称、原始错误正文或原始Trace ID。

准入先于外部读取；服务端自行限定Agent和时间，列表／详情继续核对tenant／agent、Trace ID、时间及重复／分页完整性。缺失、冲突、超上限或不兼容返回受控不可用，不返回部分结果或部分比率。来源中其他租户记录不出现在响应或诊断计数中。

本机替身可按已有元数据一致性profile验证；**真实Owner开放前还须确认采集身份、来源项目／租户边界和数据归属可信条件**。现有Langfuse结构兼容与同字段一致不足以证明跨租户保密，不将本草案升级为真实来源验收。

### 3.4 时间窗与历史可见性

推荐新Owner Trace scope使用UTC归一化的`[since, until)`，带时区、递增且跨度最多7天；最多7天是单次跨度，不是自动限制只能看最近7天。不自动扩大查询或默认扫描全部历史。

现有管理员Trace处理是含尾边界；新scope若获批必须在适配层明确过滤`timestamp == until`，保留完整分页校验，不能悄悄修改旧接口。Owner首次查询显式提供时间窗；推荐以本请求固定的`read_started_at`为上界，`until`在其之后或时间无法表达时422拒绝，不默默截短、不自行增加时钟容差、重试或拉长时限。

**推荐业务选择：当前被明确分配者，可读取其请求窗口内该Agent历史聚合，包括接手前的历史，但不读取个人／原始内容。此项须确认后才生效。** 新被分配者不继承旧Owner的缓存，重新验权并查询。

若选择“只看任职期间”，现有分配表没有有效起止和授权epoch，不能用当前行、创建者或不完备审计记录重建历史。届时先设计权威授权区间、撤销／重授语义和迁移方案，不直接实施。本草案不增加迁移。

## 4. 撤权、在途响应与缓存

### 4.1 推荐一致性等级

推荐采用**当前分配准入＋输出前再次核对，最终核对后已准入的有限JSON响应允许完成**。它不是即时撤权，也不是跨服务原子事务，须经用户接受才实施。

1. T1：验签、角色映射、同租户Agent存在和当前显式分配核对；失败不得调用Langfuse。
2. T1～T2：在既有有界读取预算内构造完整最小响应；不流式发送、提前输出计数或返回缓存结果。
3. T2：使用独立新读取事务核对当前角色绑定／Agent／分配，避免ORM缓存或旧数据库事务快照冒充重新验权。配置或签名有效期不再满足也拒绝；若角色权威只在JWT，则不能宣称可即时发现IdP侧角色撤销。
4. T2观察到撤销、Agent删除、身份／绑定改变、令牌到期或读取失败：丢弃已经收集的数据，不发送部分JSON；后端任务取消仅停止读，不执行业务补偿或重发。
5. T2通过后到响应送达之间发生撤销：允许该次已通过最终核对的响应完成；响应不授予后续查询权限。已经发送到浏览器的数据无法收回，不能承诺其他设备同步清除已显示结果。
6. 后续每次GET从T1重新准入；不缓存“此人有权”、跨请求聚合结果、角色或分配证明，不用旧JWT的角色声明覆盖已撤销Agent分配。

只读请求不持有会阻塞分配撤销的长事务／锁，不跨Console与Langfuse分布式加锁。不增加现有Trace读取的分页、响应体、并发和超时上限；整体请求应有界，不以持续请求延长准入。

### 4.2 必须披露的ABA与角色边界

- 在T1、T2之间撤销又重新分配同一人，而T2再次有权：第一阶段按T2当前授权允许结果，不证明未发生过撤销。当前表没有授权epoch，两个布尔检查无法检出该ABA。
- 角色只从有时效JWT取得时，IdP侧撤销角色可能要到令牌失效或受信同步后才可观察；本方案不新建撤销订阅、introspection或持续会话服务。
- 若要求“一旦撤销，所有在途响应都必须永不送达”，不能用检查次数、客户端abort或短TTL声称满足；需另行定义授权epoch／最终发送仲裁、撤销时点与可交付保证，再评审架构和数据变更。已经交付的数据仍不能靠服务端撤销消除。

### 4.3 浏览器与缓存

建议响应`Cache-Control: no-store`、`Vary: Authorization`；不得按Agent ID单独做共享缓存。身份、角色、租户、绑定上下文、Agent或时间窗改变时立即清空旧摘要与指标、abort旧读，并用代次隔离忽略仍到达的旧响应。组件卸载释放读取，不后台自动续查。

两个接口分开显示各自读取时间与结果状态。一个失败时不以另一个成功证明该数据可用；每一区域清空自身旧数据。收到授权失败时清空该Owner视图全部数据，并要求重新认证／重新选择，不自动切换管理员身份，也不把未授权当作0样本。

## 5. 错误与不可枚举建议

| 状态 | 候选含义 |
| --- | --- |
| 400／422 | 禁止的身份覆盖字段／非法单Agent或时间输入；不回显敏感原值 |
| 401 | 缺失、失效或不合法Bearer；不接受旧开发头降级 |
| 403 | 没有允许的用户角色／无有效身份绑定；不透露Agent状态 |
| 404 | Agent不存在、他租户Agent、未分配Agent、T2观察到分配撤销或Agent消失，统一对外不可用 |
| 503 | 身份绑定歧义／授权事实不可读／来源不完整或不可达；不返回已有部分数据、其他主体数量或下游原始错误 |

同一类404的正文一致；不宣称掩盖了所有时间侧信道。服务端日志仅保留受控请求关联信息、决策类别和必需的最小主体标识，不记录Bearer、密钥、原始Trace正文或他租户清单。

只读不等于零持久副作用：未来若通用中间件写审计，须在临时库确认其行为；正式启动／审计留存仍单独授权。本轮没有运行应用或产生此类服务写入。

| 兼容与隔离 | 临时库、签名测试身份、Langfuse替身；不写真实评分／Trace，不连接真实IdP或新增角色／密钥；相关回归后按授权决定是否扩大回归 |

## 7. 需确认清单与推荐选择

| ID | 需确认事项 | 推荐选择 | 其他选择的影响 |
| --- | --- | --- | --- |
| D1 | Owner含义和范围 | ADMIN及以上＋当前显式UserAgent分配，多Owner；仅单Agent版本摘要和Trace聚合 | 唯一Owner、组织继承、全租户或反馈均须另定义，不能隐式增加 |
| D2 | 身份来源及绑定 | Console专用受众的验签用户身份＋受控一对一legacy user绑定；第一阶段仅测试身份／绑定，默认关闭 | Runtime受众复用、网关注入、正式映射存储／同步均需单独可信边界设计；不得用开发头或展示目录代替 |
| D3 | 历史可见性 | 当前分配者可看指定窗口的接手前聚合，不看个人和原始内容 | 限任职区间需要新增权威区间／epoch及迁移评估，不能从现表推断 |
| D4 | 撤权／在途／ABA | T1＋T2复核；T2观察到撤销拒绝，T2之后已准入响应可完成；重授按T2当前授权，明确JWT角色撤销并非即时 | 更强撤销语义需重新评审最终发送仲裁／授权版本等架构，不能先实现再补批 |

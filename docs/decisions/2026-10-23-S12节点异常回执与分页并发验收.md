## 红测及最小修复

并发红测在两个独立 Session 都读到 pending 后设置屏障，再允许提交两份不同终态，实际返回不同状态／result／acked_at；`receipt-red.log` 为 1 failed／5 passed，证明旧读后写不能维持首次回执契约。

修复为一条 `UPDATE ... WHERE node_id AND command_id AND status='pending'`，原子写 status／result／acked_at，提交后读取持久结果。后到者条件不匹配，只读取同一结果；无重试、超时或新锁表／迁移。确定性测试对旧 SELECT 在读取后屏障，对新 UPDATE 在执行前屏障，避免用时间 sleep 猜测竞争窗口。不规定哪一个请求获胜，两方与最终 GET 必须完全一致。

新增历史页／回执 helper 校验及 DOM 红测，拒收非法页时清空整页、不返回部分历史、不发生 POST；保留历史旧类型的读取兼容。历史页限定本次请求的 50 条上限，校验请求状态／类型筛选、页内及已加载 ID 重复、非空合法 ID／类型／状态，空页不得继续返回游标；不凭 UUID 猜测数据库排序，不新增 schema。既有严格递减游标检查保持。

`browser-red.log` 在修复接入前实际展示非法状态及重复指令，等待受控错误的原 5000ms 断言失败；不是用缺少新 helper 的导入错误充当产品红测。同轮 AgentConfig／component 文件另有原 30000ms 超时，完整保留；该轮与 Python 并发，不据此直接断言其根因。随后通过原组件接入校验，单独串行运行最终浏览器，不提高阈值或跳过用例。

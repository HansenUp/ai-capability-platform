## 源码发现的授权耦合

现有 `feedback-evidence` GET 先校验真实用户，再调用 `feedback_writes.enabled()`；后者要求 dev 且 FEEDBACK_LOCAL_PROTOCOL=1，**同一开关也控制评分 prepare／execute 等写协议**。因此不能为了本轮只读对照，直接开启该开关来扩大写接口暴露面。

`AUTH_REQUIRED=false` 的开发主体也不能满足 `user_scope()` 的验签用户要求。不能通过伪造 human／platform-admin 开发头、调用内部函数、直接查库或复用 Langfuse 项目密钥绕过 Runtime 的租户／角色核验。启动 Runtime 还可能涉及既有数据库迁移和 Worker 生命周期，本轮未获准进行这些环境变更，不创建替代账本。

3. 若现有实例未运行且未配置验签，需明确授权恢复已有 Runtime 的启动／验签配置边界；不得自动迁移、创建空库、运行业务 Worker 或启用真实反馈交付。
4. 针对当前开关耦合，推荐另行批准**拆分只读证据准入与反馈写协议开关的本机代码闭环**：仍要求验签平台管理员和单租户限制，读侧开启不得使写接口可用；先临时库／替身回归，再决定已有非生产实例的只读启用。当前未修改开关或代码。若已有经授权、已启用且验签的实例，可保持其既有配置，仅 GET，但不能默认存在。

# S10.3 节点控制安全契约（本机开发）

本契约覆盖 Console 持久指令、Runtime 模型版本选择及受管节点排空重启。D47 继续延期，禁止以此记录替代生产部署、外部渗透或 S9 完整出口验收。以下约束为本机实现边界，不扩大操作者权限。

## 信任与下发

- 指令由 Console 生成不可变 ID；节点只通过既有节点服务鉴权拉取和回执。`tenant_id` 与 `authorization_role` 由 Console 持久写入，不从客户端 `args` 推断。
- 租户管理员只能切换自己租户的 Agent 模型版本；共享节点重启须 PLATFORM_ADMIN，Runtime 再检查下发时的角色。历史未记录角色的重启指令失败关闭，须重新授权下发。
- 回执失败保持顺序，不执行后续指令。重启必须核对已持久化的 ok 回执及原始结果内容，不能仅凭 HTTP 200 或发送成功退出。响应丢失后通过节点鉴权的 receipt 接口对账；404／终态冲突取消排空，不触发重启。

## 模型切换

`switch_model.args`：`agent_id`、`base_version`、`expected_version`、`target_version`、`model_alias`，全部必填，拒绝额外字段。

仅 api／all 接单节点接受模型路由切换；纯 Worker 不选择新 Run 版本，明确拒绝此指令，不能回执成功却无实际作用。

1. 不修改已发布 AgentVersion，不直接替换网关 URL、供应商、密钥或任意 alias。只能选择同租户、同 Agent 中已发布且全量放行的目标版本；目标 alias 必须与快照一致，并通过模型网关别名解析。
2. 基线与目标的 system_prompt、harness／版本、config、skills_lock、skills_digest 必须一致，仅模型与版本选择不同；模型数据分级、工具闸门和失败关闭逻辑照常运行，不放宽回退或数据矩阵。
3. 路由按稳定 NODE_ID＋租户＋Agent 持久化；仅当原默认／灰度选择命中 base_version 时作用于后续未固定版本的新 Run。显式固定版本、已创建或在途 Run、审批恢复及跨 Worker 续跑不改模型／版本。
4. expected_version 使用数据库 CAS，过期操作拒绝；指令指纹与成功回执和路由同事务持久化。同 ID 同参数重投只读原回执，不覆盖后续切换；同 ID 不同参数拒绝。首次并发建行冲突回滚，不自动覆盖。正常发布带来新基线后，允许以 expected_version=新 base_version 明确重设基线，并对旧持久行执行 CAS；旧指令回执重放不得撤销新基线。
5. 目标之后退役或不再全量放行时拒绝该节点路由，不偷偷回退至其他模型。基线选择已因正常发布变化时，旧节点覆盖不干预新的灰度／版本选择。再次切换或回切须使用新指令 ID 和正确 expected_version。

## 优雅重启

`graceful_restart.args` 仅允许 `timeout_s`（0.1～300 秒，默认 30 秒）。不接受 PID、信号、命令行、可执行文件、shell 或强制杀进程参数。

1. 仅本机受管启动器 `python -m runtime.node --role api|worker|all` 支持实际自动重启；要求显式稳定 NODE_ID、持久 Runtime 数据库与 Redis 队列，内存数据库拒绝重启。启动器只绑定回环地址，拒绝 RUNTIME_ENV=prod；标准 uvicorn／非受管进程没有退出回调，不伪装成功。
2. 先关闭 HTTP/SSE 接单、暂停 Worker 消费／接管，并报告 ready=false；Console 路由及按标签推送排除排空节点，健康探针返回 503。已注册节点与分组不删除。
3. 等待已进入的 HTTP/SSE 请求以及 Worker 在途任务自然结束；不取消 Run、不强杀脚本、不提前释放有效租约、不重做未知写操作。队列中已领取但未开始的 Redis 投递不 ACK，由现有至少一次投递机制恢复。
4. 超时、配置不合法或未完成排空则返回错误，恢复接单与消费并恢复心跳；原任务继续运行。回执网络失败则保持排空并重试／对账，不绕过确认强行退出。
5. 排空成功后回执阶段为 drained_restart_requested，并包含旧 boot_id 和 completion_requires_new_process=true；仅在持久回执确认后请求本进程正常退出。
6. 本机父启动器仅在子进程返回约定码 75 后重新启动固定 Python 模块；退出前回收已无在途会话的自有 Harness 进程池，清理失败不返回重启成功码。其他故障退出不伪装受控重启、不无限重试。SIGINT／SIGTERM 转发后结束启动器，不自动复活被人工停止的节点。
7. 重启完成证据须同时具备新子 PID、新 boot_id 注册和 ready=true；ok 回执本身只证明排空及退出请求被确认，不能作为实际启动成功的唯一证据。模型路由及 Run 状态使用原持久库，重启后保留。

## 其他指令与验证边界

reload_skills 继续签名／哈希校验与原子物化；reload_config 仍只调整当前 NodeAgent 的轮询与超时，不跨进程持久化，也不热改 Runtime 全局安全配置。

迁移：Runtime `0006` 新建节点模型路由与幂等回执表；Console `0005` 新增 ready、boot_id 与指令授权角色。本轮只在隔离 SQLite／MySQL 测试库应用，不操作生产数据。

`scripts/verify_s10_node_control.py` 使用随机本机端口、独立临时 SQLite、独立 Redis 容器、mock Harness 和本机模型清单桩；不调用真实模型，不使用生产凭据。脚本 subprocess 的输入仅为固定模块、已解析 Docker 路径与测试生成值，不启用 shell；Ruff S603 仅在该测试脚本按文件豁免，其他安全规则保持不变。

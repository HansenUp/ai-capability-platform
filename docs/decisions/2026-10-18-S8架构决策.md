# S8 能力网关 V1 架构决策纪要（2026-10-18）

> 范围：执行实施计划 S8.1～S8.6 期间做出的决策，并收口排到 S8 的遗留项（S4 遗留 #1、#4，S6 遗留 #5，S7 遗留 #4，S4 二次评审建议）。决策人：平台架构师。编号接续 `2026-10-18-S7架构决策.md`（D105～D121）。用户 2026-10-18 确认：rustup 升级并从官方 crates.io 下载、CI 安装 Rust 从源码编译 Cedar sidecar；下载 fastembed + bge-small-zh-v1.5 用于本机语义检索（CI 用 hash 向量）；Keycloak 保持 26.3 不升级。

## 1. 先修的现存缺陷

核查发现 S8 之前的授权链路存在失败开放：网关 `_authz` 把主体租户取成能力租户、Runtime 闸口请求缺 principal 与资源租户且不传审批状态（跨租户 forbid 与污点外发 forbid 从未触发）；闸口在策略不可达时回退放行，本机 `POLICY_URL` 指向不可达地址；网关回退依赖未声明的包。S8 一并修复，策略链路全程失败关闭。

## 3. 评审发现

独立评审必须修 3 项均已修复：① 写规范"不合规不可发布"可经登记路径绕过（登记直接激活、active 版本可原地修改、无 manifest 时只看自报字段）；② 服务态下第一级发现与能力详情缺用户令牌时不按租户过滤；③ 网关第二道防线对审批、污点、Agent 跨租户实际失效（Runtime 未传参数、网关放行 require_approval）。建议修一并处理：评测闸门防复用 Trace、检索结果带租户与发现事件 HMAC、连接器查询与策略判定接口鉴权、jti 共享防重放与 JWKS 旧钥沿用上限、baseline 生产判定识别统一环境变量。另修复对账 retry 组装时未带用户令牌的问题。

联调：Keycloak realm 已重新导入（新增 `ai-runtime-svc` 与 mcp-knowledge / crm / mail 受众）；本机 Docker 中 ES 磁盘超过高水位导致新索引无法分配，开发环境已关闭磁盘水位阈值（Docker 约 14 GB 镜像可回收，未清理）。用户全局 cargo 配置把 crates.io 替换为清华镜像，Cedar 构建在仓库外以独立 `CARGO_HOME` 进行以使用官方源。

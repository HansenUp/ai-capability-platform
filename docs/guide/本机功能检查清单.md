# 本机功能检查清单（S1～S3）

> 适用于本机 compose 联调环境。文中所有账号口令都是本机开发用的公开值，只在本机有效，不得用于其他环境。

## 1. 启动

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | `make compose-up` | 基础设施：MySQL、Redis、Keycloak、Vault、LiteLLM、Langfuse、OTel Collector 等（带 observe profile） |
| 2 | `.venv/bin/python scripts/dev_stack.py start` | 应用进程：Runtime、Console API、观测适配器、门户、Console 前端；日志在 `.dev/logs/` |
| 3 | `.venv/bin/python scripts/dev_seed.py` | 演示数据（可重复执行）：portal-demo、gray-demo v1/v2（v2 灰度 10%，bob 在白名单）、t2-demo（租户 t2） |
| 停止 | `.venv/bin/python scripts/dev_stack.py stop` | 只停应用进程；基础设施用 `make compose-down` |

查看状态：`.venv/bin/python scripts/dev_stack.py status`。

### 应用凭证（Client Credentials）

| 客户端 | 密钥 | 身份 | 用途 |
|---|---|---|---|
| agent-demo | agent-demo-dev-secret | app:agent-demo，无管理员角色 | 模拟业务应用调用 /v1 |
| console-api | console-api-dev-secret | app:console-api，带 platform-admin | Console 同步 Runtime、调用 /admin |

### Console 操作者角色（开发态，在 Console 前端页面上方切换）

| 角色 | 能做什么 |
|---|---|
| USER | 不能访问管理接口（403） |
| ADMIN | 只能管理自己创建或被分配的 Agent，操作别人的 Agent 返回 403 |
| TENANT_ADMIN | 管理本租户全部 Agent（默认身份：用户 ops、租户 default） |

租户输入框改成 `t2` 即切换到 t2 租户的视图。

## 3. 检查清单

### A. 登录与对话（S2、S3.4）

| # | 步骤 | 预期 |
|---|---|---|
| A1 | 打开 http://localhost:5173 | 自动跳到 Keycloak 登录页（地址栏含 `code_challenge_method=S256`） |
| A2 | 用 alice 登录 | 回到门户，页头显示"alice · default"；列表有 gray-demo（v1）、portal-demo（v1），没有 t2-demo |
| A3 | 进入 portal-demo，发"你好，介绍一下你自己" | 流式返回回答（DeepSeek 真实模型） |
| A4 | 发"请调用 echo 工具回显'葡萄'" | 回答中包含"葡萄"（模型调用了 echo 工具） |
| A5 | 未带令牌访问 Runtime：`curl -i http://localhost:8080/v1/agents` | 401，响应头带 `WWW-Authenticate: Bearer` |

### B. 反馈与观测（S1.5、S2.3、S2.6、S3.5）

| # | 步骤 | 预期 |
|---|---|---|
| B1 | 在 A3 的回答下点"👎"或"修正"（填写正确答案后提交） | 显示"已反馈，谢谢" |
| B2 | 登录 Langfuse → Traces，打开最新一条 `run portal-demo` | Session 为 run_id；含 `chat …` 模型轮次（输入 / 输出 / 缓存命中 token）与 `execute_tool echo`；Scores 中有 `user_feedback = -1` |
| B3 | Langfuse → Sessions，打开同一个 run_id | 同会话里还有 `audit POST /v1/messages` 等审计镜像 |
| B4 | 查审计表：`docker compose -f deploy/compose-dev/docker-compose.yml exec mysql mysql -uroot -proot ai_platform -e "select ts,actor,act,auth_method,tenant_id,action,object,result from t_audit order by id desc limit 10"` | 能看到 alice 的对话、反馈请求，以及 `tool.decision`（工具判定）行 |
| B5 | Vault → secret/ai-platform/runtime | 有 MODEL_GATEWAY_API_KEY；Runtime 进程环境里不设该变量，网关 Key 从这里读取 |

### C. 灰度与回滚（S3.2、S3.3）

| # | 步骤 | 预期 |
|---|---|---|
| C1 | alice 进入 gray-demo 对话 | 回答以【v1】开头 |
| C2 | 退出，换 bob 登录 | 列表中 gray-demo 显示 v2；对话回答以【v2】开头（白名单） |
| C3 | Console 前端（http://localhost:5174），gray-demo v2 行点"放量"，填 100 | 提示 `PUT … → 200`；alice 刷新门户列表后 gray-demo 变为 v2，对话以【v2】开头 |
| C4 | gray-demo v1 行点"回滚到此版本" | v2 状态变为 retired；alice、bob 再对话都回到【v1】 |
| C5 | 想再演示一次：在 Console 前端用 agent_id=gray-demo、version=3、灰度 10 发布新版本 | 约 10% 的用户进入 v3（白名单为空时 alice、bob 大概率仍走 v1；完整统计见 `make verify-s3`） |

### D. 角色、权限与租户（S2.1、S2.2、S3.3）

| # | 步骤 | 预期 |
|---|---|---|
| D1 | Console 前端角色切到 USER | 列表加载失败，提示 403 |
| D2 | 角色切到 ADMIN、用户改为 bob2，对 gray-demo 点"放量" | 403（Agent 未分配给该操作者） |
| D3 | 角色切回 TENANT_ADMIN，租户改为 t2 | 只看到 t2-demo |
| D4 | 门户用 dave 登录 | 只看到 t2-demo；直接访问 http://localhost:5173/chat/portal-demo 对话会失败（其他租户的 Agent 视同不存在） |
| D5 | 应用令牌调管理接口（见下方命令） | agent-demo 的令牌调 `/admin/agents` 返回 403；console-api 的令牌返回 200 |

D5 的命令：

```bash
TOKEN=$(curl -s -d grant_type=client_credentials -d client_id=agent-demo -d client_secret=agent-demo-dev-secret http://localhost:8180/realms/ai-platform/protocol/openid-connect/token | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $TOKEN" http://localhost:8080/admin/agents
```

把 `agent-demo` 换成 `console-api`（密钥 `console-api-dev-secret`）再执行一次，应返回 200。

| 命令 | 内容 |

## 4. 当前已知限制

- 审批卡片：门户里发起人自己点"通过"会被拒绝（403，不能审批自己的 Run，S2 的安全修复）；其他人员审批的界面在 S4 审批流中实现。
- Console 的身份目前是开发态请求头，未接登录；Console 前端的"聊天侧"页面只在 Runtime 开发态（AUTH_REQUIRED=false）下可用，鉴权模式下请用门户对话。
- 门户的 Agent 列表尚未按 Console 的可见范围过滤（S4）。
- Helm 部署方式暂不启用（D47），只维护 compose。

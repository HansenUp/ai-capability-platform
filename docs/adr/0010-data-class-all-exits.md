# ADR-0010 数据分级传播覆盖全部出口

- 状态：已采纳
- 日期：2026-09-12
- 关联需求：SC-03、SC-05、OB-05
- 依据：外部设计评审第 04 条

## 背景

原污点机制只约束邮件、即时消息与外部地址等显式外发工具。数据进入对话后还会流向六条隐式通道：模型推理、向量化、重排、观测上报、自动回退到另一厂商的模型、跨会话记忆。这些通道大多不被开发者意识到，而观测平台存储的是完整提示词与响应，自动回退可能把机密数据送到未经审查的厂商。

此外，应用层的出网控制只覆盖平台自身发起的请求。Harness 子进程与 Skill 脚本使用各自的网络栈，不受该控制约束。

## 决策

建立数据等级、允许处理方、允许输出目的地三维矩阵，作为平台的强制规则：

| 数据等级 | 允许的模型 | 检索与重排 | 观测记录 | 跨会话记忆 |
|---|---|---|---|---|
| 公开 | 不限 | 不限 | 全量 | 允许 |
| 内部 | 私有化部署与已过合规审查的云端模型 | 企业内服务 | 脱敏后记录 | 允许 |
| 机密 | 仅私有化部署 | 仅企业内服务 | 只记元数据不记内容 | 禁止 |

标签随附件、检索结果、摘要与跨会话记忆传播，不因换一个 Run 而丢失。自动回退限定在同一数据处理等级且已评测的候选集合内。出网控制下沉到容器网络策略，不再依赖应用层拦截；隔离能力不可用时拒绝执行，不降级放行。

具体等级划分与云端模型准入清单由企业安全合规负责人签署，平台只负责执行。该清单可能触发私有化模型部署的立项，需提前确认。

## 备选方案

维持仅约束显式外发工具。实施成本最低，但隐式通道是实际泄露事件中占比最高的一类，不采纳。

## 后果

闸口增加模型与服务准入校验，机密污点下调用未授权模型直接拒绝。模型响应事件在机密污点下不落正文内容。模型网关的回退配置需按数据等级拆分候选集，当前默认回退到另一厂商的配置在机密场景下违规，必须改。安全合规签署是外部依赖，应在首期场景投产前完成。

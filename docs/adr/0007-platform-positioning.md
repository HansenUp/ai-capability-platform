# ADR-0007 平台定位：治理与供给优先，执行能力集成不自研

- 状态：已采纳
- 日期：2026-09-12
- 关联需求：全局（影响所有工作包的投入分配）
- 依据：《平台定位路线调研报告 V1.0》

## 背景

设计与实施过程中反复出现同一处含糊：平台到底是治理与供给平台，还是 Agent 能力平台。前者管身份、授权、审计、复用，Agent 执行能力靠标准与成熟开源；后者要自己把执行能力做到最强。这处含糊导致多项技术讨论滑向自研执行能力，与建设方案的原始意图不符。

判断口径不是"做治理还是做能力"，而是"哪一层会被别人免费做掉，哪一层只有自己能做"。执行层是模型消费入口，厂商有动机免费提供，同类能力已有多个免费实现并高频迭代，自研投入半衰期短且难以沉淀。治理与供给层绑定企业自身的身份体系、组织结构、数据分级、业务系统接口与合规要求，外部无法替代，投入可沉淀为资产。

## 决策

平台定位为治理与供给平台。自研范围严格限定在：能力目录与复用、身份与授权、审计与回滚、发布与评测、业务系统集成。执行能力一律通过 Harness 适配器集成，仅在适配器确实覆盖不了时临时补齐，且补齐后应主动寻找让渡时机。

投入分配基线：能力供给与复用三成，身份授权审计与数据分级三成，触点与自助两成半，执行层适配与评测一成半，自研执行能力为零。

判断某项投入归属的准则：该投入若明年被某个开源项目免费提供，它是沉没还是仍然有效。仍然有效的自建，会沉没的跟随。

## 备选方案

自建 Agent 能力平台。仅在四条同时成立时才应考虑：核心业务即售卖 AI 产品；存在通用方案无法覆盖的刚性约束；具备可长期投入的专职团队；接受该投入不产生可复用积累。本项目四条均不成立。

## 后果

Workflow 编排画布、自建追踪存储、代码执行模式、自研规划与子代理能力均排除在自研范围外。纯治理会退化为收费站被业务绕过，因此供给与自助必须与治理同步交付，不得把 Console 与能力复用后置。执行能力的上限受所选适配器约束，需通过季度复评与真实场景评测控制风险，见 ADR-0008。

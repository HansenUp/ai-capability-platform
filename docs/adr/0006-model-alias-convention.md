# ADR-0006 模型别名规范：`<family>-<yyyy-mm>`，Agent 快照锁定别名

- 状态：已采纳
- 日期：2026-10-16
- 关联需求：CG-12、CG-20、RT-03、RT-29
- 依据：`services/model-gateway/config.yaml`；实施计划 S1.2、S3.1；ADR-0010、ADR-0011

## 背景

模型厂商会持续发布新版本，也会下线旧版本。如果 Agent 直接引用厂商的模型名，厂商一次升级就会悄悄改变线上 Agent 的行为，评测结论随之失效；反过来如果一律用"最新"，回滚和灰度也无从谈起。

发布评测闸门评估的是"某个 Agent 版本加某个模型"的组合。要让评测结论对生产环境成立，Agent 发布快照里引用的模型必须是版本固定且可追溯的名称。ADR-0011 也要求发布快照锁定实际命中的模型标识。

## 决策

### 1. 命名规则

- 版本锁定别名使用 `<family>-<yyyy-mm>`：
  - `<family>` 为模型系列名，含系列内的代际标识，小写字母、数字与连字符，例如 `claude-sonnet`、`deepseek-v4-pro`；
  - `<yyyy-mm>` 为该别名所指向的上游模型版本在平台完成评测并上架的年月，不是厂商发布日期。
- 现有别名：`claude-sonnet-2026-06`、`deepseek-v4-pro-2026-08`。
- 版本锁定别名一经创建，其指向的上游模型与参数不得修改。需要换模型时，新增别名，而不是改旧别名。

### 2. 稳定别名（不带日期）

`default-chat`、`embed-default`、`rerank-default` 是功能性稳定别名，指向会随平台升级调整：
- 稳定别名只用于 Agent 未指定模型时的默认值、开发调试和非锁定场景；
- Agent 发布快照禁止引用稳定别名，发布闸门必须检查并拒绝；
- 稳定别名的指向变化必须走和新增别名相同的评测与灰度流程，只是不要求每个 Agent 改快照。

### 3. 默认别名与回退链

- 默认别名为 `default-chat`，当前指向与 `claude-sonnet-2026-06` 相同的上游模型。
- 回退链在模型网关的 `router_settings.fallbacks` 中配置：`default-chat` 失败时回退到 `deepseek-v4-pro-2026-08`；连续失败 3 次后冷却 60 秒。
- 版本锁定别名默认不配置回退，失败直接报错，避免快照锁定的模型被悄悄换成另一个模型。需要回退的锁定别名，必须在配置中显式声明候选，并通过评测。
- 回退候选必须与原模型处于同一数据处理等级且已评测（ADR-0010）。当前 `default-chat` 回退到另一厂商的配置，在机密数据场景下不合规，需要按数据等级拆分候选集后才能用于机密场景。

### 4. 模型升级流程

模型升级 = 新增别名 + 灰度切换 + 弃用旧别名：
1. 在 `config.yaml` 新增别名（例如 `claude-sonnet-2026-12`），旧别名保持不变；
2. 用新别名发布 Agent 新版本，跑评测数据集，通过发布评测闸门；
3. 按 Console 的哈希灰度逐步放量，异常时一键回滚到旧版本（旧快照仍引用旧别名，立即可用）；
4. 全量后，旧别名标记为"弃用中"。

### 5. 弃用策略

- 别名状态依次为：可用、弃用中、已下线。
- 弃用中的别名继续可用，但不允许新的 Agent 版本引用，Console 列出仍引用它的 Agent 版本。
- 下线条件需同时满足：弃用满 90 天（初始值，可经评审调整）；没有任何已发布快照和运行中任务引用。
- 例外：上游厂商强制提前下线时，按厂商时间表执行，并提前通知相关 Agent 负责人完成迁移。
- 别名下线后从 `config.yaml` 删除，历史 Run 事件日志中的别名记录保留，不改写。

### 6. 与配置的一致性

本 ADR 与 `services/model-gateway/config.yaml` 保持一致：该文件头部注释与 `README.md` 引用本 ADR 作为别名规范来源。新增或下线别名的变更，必须同时更新 `config.yaml` 与本 ADR 的现有别名清单（或其后续的别名台账）。

## 备选方案

直接使用厂商模型名：厂商升级会改变线上行为，评测结论失效，不采纳。

全部使用 `latest` 类浮动别名：无法保证评测对应的就是线上模型，且无法精确回滚，不采纳。

用语义化版本号（如 `claude-sonnet-v5.1`）：厂商的版本号体系各不相同，无法统一，且无法反映"平台何时验证过"，不采纳。

## 后果

- 发布闸门需要增加校验：快照中的 `model_alias` 必须是已登记的版本锁定别名。
- 文档与示例中的别名需要与 `config.yaml` 保持一致：根目录 `README.md` 第 5.1 节示例使用的 `chat-2026-06` 不在 `config.yaml` 中，应改为 `claude-sonnet-2026-06`，该修订不在本次变更范围内，另行处理。
- 评测快照文件中可能出现 `default-chat`（如 `evals/snapshots/ticket-summary-basic.jsonl`），用于回放，不受快照禁用稳定别名规则约束，该规则只约束 Agent 发布快照。
- 配置里同一别名对应多个部署时由路由策略分流；别名数量随模型迭代增长，需要在 Console 提供别名台账与引用关系查询。

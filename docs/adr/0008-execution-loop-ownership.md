# ADR-0008 执行循环归属与适配器能力分级

- 状态：已采纳
- 日期：2026-09-12
- 关联需求：RT-15、RT-16、RT-27
- 依据：ADR-0007；《平台定位路线调研报告 V1.0》第 9 章

## 背景

执行循环指"组装上下文、调模型、执行工具、回灌结果、再调模型"这一反复过程。谁持有这个循环，谁就掌握执行权。外部 Harness 持有循环时，平台只能通过其提供的钩子在工具执行前介入；若某个 Harness 没有可靠的执行前拦截，平台只能事后看到它做了什么，审批与闸口形同虚设。

此前的适配器能力描述以传输方式分级，即进程内还是子进程。该分级与可治理性无关。同时把某官方开发套件标为进程内也与事实不符，它实际以子进程运行命令行。

## 决策

管控点与循环位置解耦。管控点固定在工具代理与能力网关，不落在循环内部。工具执行收敛到唯一入口，所有能力以 MCP 形式由能力网关提供，禁用 Harness 自带的有副作用内置工具。满足这一前提后，循环由谁持有不影响授权、幂等与审计。

适配器按可治理性分三级，由契约字段声明并经探针实测校验：

| 等级 | 条件 | 允许承载 |
|---|---|---|
| L0 | 仅能事后观测 | 只读、无副作用的文本生成 |
| L1 | 执行前拦截可靠且不可绕过 | 低风险写 |
| L2 | 在 L1 基础上可中断、可由平台事件日志恢复 | 高风险写、审批挂起、长任务 |

分级的一条关键推论：当循环归属为平台时，工具由平台的工具代理执行，闸口必然生效，恢复也由平台的事件日志重放完成。此时拦截强度与原生恢复能力由平台自身保证，与适配器自带的钩子无关，因此平台持有循环的适配器直接归入 L2。反之，循环归属字段未显式声明时按 harness 持有处理，落入 L0，这是失败关闭的默认值。

首期由平台持有循环，理由是三条：首期即投产受控写操作，平台持有循环时每次工具调用必然穿过闸口，不依赖第三方钩子可靠性；外部适配器的拦截能否被绕过需探针实测，首期无验证窗口；上下文由平台组装时可重建不变量最易成立，而该不变量是审批挂起与故障恢复正确性的基础。

平台持有循环是工程过渡态，不构成自研执行能力的许可。让渡条件：适配器通过拦截与恢复探针，且真实业务场景评测达标，即可将循环让渡给该适配器。复评每季度一次。

## 备选方案

始终由平台持有循环。放弃成熟 Harness 的规划、子代理、上下文压缩等能力，与 ADR-0007 的定位冲突，不采纳。

直接交给外部 Harness。在拦截可靠性未经验证前承载写操作，风险不可接受，不采纳。

## 后果

契约的能力描述增加循环归属、执行前拦截强度、可由事件日志恢复三个字段，并提供能力等级判定函数。发布闸门增加校验：Agent 声明高风险写能力而所选适配器低于 L2 时拒绝发布。探针套件按模式拆分，第二套增测拦截不可绕过与恢复后不重复执行。文档中不得再以"进程内"或"是否官方 SDK"作为分级依据。

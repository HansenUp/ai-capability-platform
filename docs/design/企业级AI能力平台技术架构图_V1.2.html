企业级 AI 能力平台 · 建设路线
V1.2 · 先补底线 → 再做结构 → 后补体验与生态 → 编排与评测后置；顺序由依赖决定，不是愿望清单
PHASE 1 · 约 2 个月
补齐企业底线
  • 最薄垂直切片：1 个低风险场景端到端上线
  • 统一 Identity · Token 交换选型 · 策略引擎选型
  • 统一审计 · Trace（OTel）· 用户反馈采集
  • Run 状态机（A2A 命名）与事件日志模型 · 上下文预算
  • 版本 / 灰度 / 回滚 · Agent 版本锁定模型版本
  • Model Gateway 最小版 · 密钥管理
依据：底线能力 + 一个业务可见成果；Run / 评测数据模型早定避免返工
里程碑：首个场景投产；任一请求可回答"谁、何时、以何身份、调了什么、结果如何"
PHASE 2 · 约 3 个月
结构性对齐
  • Contract 六要素 · 进程内 + stdio 双 Harness 适配 · Run 重放恢复
  • 能力网关数据面 POC → V1：目录 + 两级发现 + 策略授权
  • MCP 写规范 · Skill 商店（Agent Skills 规范 + 供应链硬规则）
  • 出站白名单 · Taint · Fail-closed 沙箱 L1 · 节点只出不进
  • 节点管理 · Console 后端 · 观测平台 V1
  • Langfuse / Opik 接入为事实源 · 发布前回放闸门
依据：趁单 Harness 抽象成本最低；节点管理支撑三种部署拓扑
里程碑：五条核心链路 + 审批挂起 / 恢复链路端到端跑通
PHASE 3 · 约 3 个月
体验与接入
  • Agent Console 前端（双工作台）
  • 统一 AI 门户（注册上架 · 会话 · 可见范围）
  • Web SDK 嵌入组件（业务系统 + AI）
  • 零代码搭 Agent（表单配置人设 / 能力）
  • Data Hub（受限 SQL 视图优先）· 运营看板（北极星指标）
  • 首批业务场景上线（销售 / 售后 / 工单）
依据：后端能力已就绪，补齐体验层与接入层
里程碑：业务人员可自助组合 Skill / MCP / 知识发布 Agent
PHASE 4 · 约 3 个月
规模化与生态
  • 桌面端客户端 Runtime（混合式拓扑）
  • 第三方 Agent 开放接入 · A2A Agent Card 与任务端点
  • 渠道接入（企业 IM 平台）
  • 更细粒度数据权限（字段 / 行级策略）
  • Text2SQL（权限 / 脱敏 / 审计前置）
  • Agent 即 MCP Server · 评测自动化扩展
依据：本地拓扑成型后做桌面端；Trace 数据积累后再做评测
里程碑：三种部署拓扑全部投产
后续演进
规划后置能力
  • Workflow 编排（编译校验 + 证据回放）
  • 多 Agent 协同
  • 完整 AI Eval 评测平台
  • 更完整的 MaaS（训练 / 部署 / 推理）
  • 个人构建空间（用户自建 · 经验沉淀）
  • 本体 / 知识图谱（保持关注）
依据：依赖前序阶段的数据与规模积累，待方法论明确后推进
节奏原则：先补底线并交付一个场景 → 再做结构（Contract / Run / 能力网关 / 评测闭环）→ 后补体验（门户 / Console 前端 / SDK）→ 再扩生态（桌面端 / 第三方 / 渠道）→ 编排与重型评测后置。周期为建议值，按团队投入调整。

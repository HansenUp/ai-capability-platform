> 依据：《建设方案 V1.2》《开源调研报告 V1.1》《技术实现方案 V1.0》第 10 章、《平台定位路线调研报告 V1.0》、ADR-0007 至 0011；结合 `ai-capability-platform/` 当前代码骨架状态编制。
> 用途：后续开发**严格按本计划执行**。每个工作包的任务、交付物、出口标准都可逐条勾选验证；未达出口标准不得进入下一工作包。
> 版本：V1.1 · 2026-09-12 · 维护人：平台架构师。计划变更只允许在阶段边界经评审后修订并升版本号。

## 0. 使用规则

| 规则 | 内容 |
|---|---|
| Sprint 周期 | 2 周。每个 Sprint 首日开 Kickoff 确认本文件对应章节的任务，末日做演示与出口标准逐条核验 |
| 状态标记 | 每个任务行的状态列取值：`未开始` / `进行中` / `已完成` / `阻塞`；勾选框 `[x]` 只在出口标准核验通过后打上 |
| 完成定义（DoD） | 代码合并到主干；单元与契约测试通过；`ruff check` 与 `mypy` 通过；中文注释齐全；相关 README / ADR / OpenAPI 已更新；出口标准全部可演示 |
| 分支与提交 | 主干 `main` 受保护；功能分支 `feat/<需求编号>-<简述>`；提交遵循 Conventional Commits；PR 标题带需求编号（如 `RT-24`）；至少一名非作者评审 |
| 接口变更 | `packages/contract`、Messages / Run API、Discovery / authz / token exchange 接口在 P0-2 冻结后，变更必须：提 ADR 或接口变更单 → 契约测试更新 → 向后兼容检查 → 只在阶段边界合并破坏性变更 |
| 质量门禁 | 详见第 10 章；门禁在 CI 中强制，不允许手工绕过 |
| 阻塞升级 | 任务阻塞超过 2 个工作日，由组长在日会升级到架构师；外部依赖阻塞记录在第 12 章风险表并指定跟进人 |
| 本文件的更新 | 只更新状态列与勾选框、追加"实际完成日期"和"备注"；不改任务定义。任务定义的修改走计划变更流程 |

## 2A. 评审与定位优化项并入（计划 V1.1 修订）

依据外部设计评审、平台定位路线调研报告与 ADR-0007 至 0011，对本计划做一次修订。修订只增加约束与前移时机，不改变阶段划分与里程碑时间。

判据：优化项必须直接服务三根支柱之一，即统一供给、安全可控、业务自助。只提升执行能力上限的项目一律不纳入自研范围，见 ADR-0007。

**必做六项，全部属于补齐闭合，无一项扩展能力：**

| 编号 | 优化项 | 并入位置 | ADR |
|---|---|---|---|
| OPT-1 | 工具执行收敛到唯一入口，全部经能力网关走 MCP，禁用 Harness 内置副作用工具 | P0-5、S4、S8 | 0008 |
| OPT-2 | 授权改为多条件合取，跨租户由独立 forbid 兜底，审批不可替代基础权限 | P0-5（已完成）、S8 | 0009 |
| OPT-3 | 审批改为范围授权，绑定参数哈希、目标资源、预演结果与有效期 | P0-5、S4 | 0009 |
| OPT-4 | 数据分级传播覆盖模型、向量化、重排、观测、自动回退、跨会话记忆六条隐式通道 | S4（最小闭环）、S9（完整） | 0010 |
| OPT-5 | 执行者身份由平台签发，不接受客户端自称 | P0-5（已完成）、S8 | 0011 |
| OPT-6 | 写前记录消除结果未知窗口，幂等责任按风险分级，发布快照补全 | P0-5、S4、S7 | 0011 |

**方向正确但时机未到的四项，只做契约预留，不实现：**

| 编号 | 事项 | 处置 |
|---|---|---|
| DEF-1 | Run 即任务，令牌与时间双预算替代轮数主控 | 契约预留扩展点，实现放到 S7 |
| DEF-2 | 上下文裁剪事件化并真正生效 | 降为纪律，首期短任务不触发压缩，实现放到 S7 |
| DEF-3 | 能力包渐进式披露 | 后置到 S9，数量起来后再做 |
| DEF-4 | 在线抽样回放与漂移监控 | 后置到 S22，首期用发布闸门加反馈沉淀 |

**明确不做的四项（偏离定位，见 ADR-0007）：** 代码执行模式、引入成熟持久执行引擎、代理间协作协议适配层的实现、前端事件流对标通用协议。其中代理间协作只需修正文档中的过度表述，把"状态命名相同即兼容"改为"状态命名对齐，协议适配层待建"。

**两条零成本纪律，立即写入开发规范：**

- 任何对上下文的裁剪必须落成事件，不落事件就不允许裁剪。
- 任何新增的写能力必须先声明幂等与影响预演，声明不全不允许上架。

**一处排期调整：** OPT-2 至 OPT-6 的最小闭环从原定的 S8 与 S9 前移到首个业务场景投产前，即 S4 结束前必须完成。理由是垂直切片原则本身，首期场景一旦接触真实用户数据与真实写操作，这些就不再是可选项。
